# 项目目标与架构

## 目标与依据

以C++17 + raylib复刻《冒险迷宫村》一代，尽量保留玩法、数值、事件顺序、UI与操作流程。先稳定二维世界和交互，再替换为3D表现。

[research入口](../research/README.md)及其维护规则、prototype、素材是产品唯一规格来源，输入身份见 [EVIDENCE](../research/dungeon_village_1/EVIDENCE.md)。产品侧只读维护交付，不读取 `research/work`、不执行逆向，也不把夹具、研究原型保护或跨版本截图数值当作原版规则。

研究覆盖、产品接入和原版一致性分别验收。持续世界及任务闭环已有历史验收；此前e8接入已实现五项菜单中的建设/冒险、当前世界建设与设施交互、任务管理、完整授勋操作和晋级页面。系统仅开放稳定主场景两栏手动存读档；2b479f6接续开放村办类型0/1/2、奖励95、普通道具/设施强化及按flag16开放的南瓜商会，898b653继续开放类型3地图扩张。情报和其余未交付操作仍禁用。具体差异集中在 [原版对照](reference/REFERENCE_CHECKLIST.md)与 [研究需求](reference/RESEARCH_REQUESTS.md)。阶段历史保留在 [B1记录](stages/B1-playable-prototype.md)。

2026-10-07工程审阅确认当前Owner/线程/依赖主链可继续演进；维护存取目标分离、桌面协调器职责和字段分类防漏等为待实施建议，未改变下述现架构。具体发现/验收见[PRODUCT_REVIEW](PRODUCT_REVIEW.md)，研究历史与可接范围见[当前审计](reference/REFERENCE_CHECKLIST.md#research-history-current-audit)。

## 三层结构

按用户最新决定，试玩固定一倍速，已移除切换按钮、world-speed窗口入口及旧切片Tab切换。加载沿用当前会话速度；源规则与无窗口显式速度组合回归仍保留，历史速度字段不要求改格式。

依赖从表现层向下，规则层只使用标准C++，没有raylib、窗口或屏幕类型。

产品公共库通过独立`shared-libraries`预设统一以Release构建；四套消费者导入同一份CMake目标和DLL，不分别编译核心。规则、Owner、存档与会话保持原依赖方向；Debug调试消费者代码，库内部已优化且不保留符号。Windows全部EXE及DLL统一位于`build/bin/`，EXE带消费者配置后缀。Release玩家包复制游戏PE导入闭包和资源并恢复`ark_village.exe`名称。此政策不修改research目标或构建缓存。

`src/app/world_simulation_main.cpp` 是标准C++无窗口入口，直接调用世界运行时；桌面入口 `src/desktop/main.cpp` 根据启动参数选择运行模式。启动参数属于 `ark_launch`，逻辑时钟适配属于 `ark_timing`，SEB/TSV解析属于 `ark_asset_metadata`。这些平台无关工具不持有第二套业务世界。

规则已按真实职责拆文件，运行时按跨域消费者拆文件。公开接口放 `include/ark/`，实现放 `src/`，实际模块README说明边界，不预建空ECS、服务容器或事件总线。

## 唯一Owner与事务

默认世界唯一可变聚合是 `StartupWorldRuntimeState`。它持有当前地图/实例、共同现金账本、随机流、实时人物/怪物名单、共享定义进度、任务、场景/日历、脚本页栈及表现缓存。

静态定义与可变共享进度、设施实例、人物实例分开。初始化对象仅用于真实新局投影，完成接管后销毁。路由、脚本、收尾和月报所需状态是在调用时构造的临时投影，提交后丢弃；不额外持久保存地图、资金或随机副本。道路/撤除/移动仍提交该Owner：FIFO绑定观察到的编辑模式、定义、旧起点及移动实例；移动重建源实例并保留规定白名单，旧人物目标沿原到达/退出消费者失效，不由桌面迁移或清AI。住宅H资格与真实800G重建费用独立。

`prepare_startup_world_runtime` 在候选Owner内组合原资格和消费者，全部成功才替换当前世界。桌面每次获准更新还消费 `update_startup_world_render_cache`，保留原可见性及缓存时点；任一失败保留旧Owner并明确报告，不残留扣款、名册、随机游标或局部页栈提交。

`ark_world_save`显式编解码版本化耐久字段、验证稳定身份/引用/占地并纯重建缓存，独立于raylib。随机、页面栈、held与一次性输出不落盘；账本余额与月度累计分别保存，不重放审计费用。文件层采用同目录临时写入、flush和替换，失败保留旧档；WorldSession在FIFO边界捕获/提交，成功读取更换会话代次并拒绝旧命令。两栏手动档位于Windows用户本地目录，自动轮内恢复另待合同，退出不自动保存。字段覆盖见[存档模块](../src/app/world_save.md)。

维护存取接口为`startup_world_persistence.hpp`，normal保存完整稳定主场景Owner/随机/账本，replay另存有序审计及外部控制器。它不接管玩家系统菜单。读取返回私有Session候选；控制器验证完成后才联合安装，不能将日历轮内审计当作下一帧入口。SHA256用独立纯C++ `ark_world_hash`，文件只读校验、预算及同目录替换失败不改变现Owner/旧有效档；codec字段覆盖按产品Clang AST严格比较规范清单，不编码指针或对象padding。

实时名单、共同c/d前缀、FIFO控制、路线推进、设施使用/退出、非人物消费者、任务成功/收尾、事件续体和日期/月报沿维护运行时组合。不能把已存在的领域函数等同于玩家能通过菜单操作该功能。

地图格、连续x/height/z、原定义ID、维护实例ID、事件身份和现金统计均保留各自语义。到达收入与退出效果、金币/村子点数/人气、页面关闭与世界资格各自独立，UI不代替领域计算或补造事件顺序。

## 更新、页面与表现

默认不带参数、`--world` 和 `--check` 都选择完整世界；`--world` 是显式别名。窗口模式每个进程只启动一种世界，不运行旧Game来补建设，也不同步两个持久Owner。

逻辑更新与60FPS绘制分离。`ark_world_session` 的模拟线程独占世界提交，以47ms最小开始间隔、实际观测提交及卡顿不补算调度；倍速由源场景规则决定获准轮数。主线程读取不可变 `WorldFrame` 快照并以60FPS绘制，锁只保护命令队列和快照指针。输入按序在完整事务之间提交，相邻镜头请求可以合并，暂停/确认/倍速是不可跨越的顺序边界；有限命令批次后检查更新截止，持续拖动不会饿死世界。线程退出会唤醒并等待当前事务完成，失败发布明确错误并停止更新。原47ms门槛属于Android render/input路径，产品独立调度、桌面时钟和原框架生命周期尚未动态认证等价。

只对相邻快照中普通可见行走做位置插值，瞬移、进出设施及状态变化直接切换；逻辑位置、动作计数、伤害、金币和随机流不插值。命令提交后的快照不重复播放上一段位移。

桌面主菜单使用`WorldFrame.main_menu_open`元数据和FIFO开关命令，打开只冻结worker资格、不改源显式暂停或伪造raw3；关闭保留原暂停。选择“建设”或“冒险”在单个候选事务内打开真实目录并关闭桌面菜单，源拒绝保留菜单；无活动任务时冒险打开22目录，活动任务打开26队伍，空目录消息沿源事件29。旧建设Game不参与菜单状态。

页面栈与生命周期由运行时持有。玩家确认调用实际页面消费者，定时页raw16和摄像页raw56/57自行推进；模态、暂停、场景状态和脚本是否跳过一轮沿原资格消费。年度raw87按贡献榜索引请求授予，再按源绑定人物确认/拒绝；结束授勋使用另一组request/reject/confirm命令。普通确认不替玩家选择授予或终止。勋章由WorldState唯一持有，脚本opcode29通过临时投影读写同一字段。无窗口入口的 `--auto-confirm` / `--end-awards` 和 `world-active/world-month/world-rank/world-award` 的自动确认只属于明确的测试输入。

月报按最新用户决定恢复源自动消费者：左上报告不要求确认、不冻结世界，也不阻断菜单/人物/任务命令。phase1/2分别累计70次有资格更新，先关闭再一次性发放快照点数；phase0维护费不重复执行。原脚本模态与场景更新资格仍由运行时决定，显式玩家暂停会同时冻结世界和报告且不会自动恢复。`world_report_visible`只查询可见性；`acknowledge_world_report`仅保留显式诊断skip，不是正常输入路径，也不能绕过暂停或非世界场景资格。旧手动冻结决定已被ADR-0042取代。

任务入口是主场景“菜单→冒险”或T，菜单开关属于桌面适配，不绕经旧Game，也不视为完整原版菜单生命周期。`WorldSession`将打开目录、页面动作、取消和征集按住状态排入同一FIFO，由模拟线程在事务间验证当前栈顶/页面身份、提交结果并发布快照；桌面只保留选择行/滚动等表现状态。22–28/33读取当前任务、参与者、费用、预测与期限；26可追加队员、查看绑定raw60成员详情，X开启raw4任务管理，原默认“否”的绑定raw1将答案交回父页消费者；24按住加速绑定页面并在松开/切页/暂停/失焦时释放，不从绘制帧数追加世界更新。31成果确认、83仅取消、97自动、59满70计数后确认及99/100演出沿维护消费者执行，重复/过期输入拒绝，不伪造参与者、扣费或奖励。

`world_task_inspection`仅供显式`world-task-recruitment/team/result`诊断：从真实新局选择实际可负担任务，经接受、征集及出发消费者，自然到达同一任务的征集、队伍或成果页；有界失败明确报告。它不参与正常窗口自动操作，真实输入诊断也不替代OS鼠标或原APK动态对照。

`world_progression`区分raw48晋级申请/四项条件解释与raw49只读条件页。实际晋级、金额、事件和庆典参与名单由源消费者提交；raw50按phase/count开放确认。raw67/88/96读取源绑定人物、共享旧值/新值和计数作文字展示，不从绘制线程发奖励或推进演出，也不宣称已还原完整动画。

源可见性会影响世界分支和随机消费，所以桌面从第一轮起把实际逻辑视口和zoom写入Owner，不能先在240×320参考视口运行，再改成宽屏。相机拖动/缩放只修改表现坐标，不选择人物目标或替代人物移动。

`world_scene` 根据当前地表分片、道路补块、栅栏/外部入口与实时名册建立稳定深度队列。人物/怪物图片按职业/性别/体型绑定，动作帧读原action counter和动画资格；血条、累计伤害、X2/X3现金、cd24经验和cd14升级标签读取真实状态。旅馆休息叠层按占用名单前4项与flags32显示，两阶段共用源startup_world_visuals头像计划，按当前职业/性别裁剪walk01帧0；B<170计时，后段显示容量与displayed HP；隐藏人物身体不会隐藏设施面板。纯显示计划位于 `ark_world_visuals`，raylib执行器只绘制、不结算奖励。渲染FPS不会推进人物动作时钟。

命中与绘制共用逻辑布局，framebuffer使用原生像素（含Retina），素材最近邻采样，文字按物理密度生成。鼠标保持窗口点坐标，不重复乘DPI。表现层不直接扣款、改变占地、任务参与者或人物控制状态。

当前任务场景反馈由`world_dungeon_visuals`只读active_task、真实实例阶段/g/h及首占地格显示绑定，素材层提供实际PNG高度。攻略条和轮廓各自进入稳定深度队列；raw31由`world_crew_summary`保留原定义名单与击倒/倒地统计，不重复结算。raw30由`world_reports`读取页面/退休安全摘要、原序m和phase/counter，确认仍走原消费者；月报只读K/O/M和自动计数，无确认按钮。通知底栏由冻结源推进counter/移除，`world_notice_view`按原逆序前两条计划平移到底栏，读取富文本、77皮肤和成长ap前半。32特殊条仍为文字适配；没有60FPS通知时钟。日期年/月/周与周内进度只投影当前calendar，条值为`units/10800`，其精确皮肤、尺寸、方向尚无认证。

人物点击以当前演员ID及定义绑定进入raw60；`world_human`读取当前职业/等级、六属性、四战斗值、装备和可用魔法，等待源page_ready，不由绘制初始化。转职61/62/63、赠礼64/65/66/68、职业大师70和只读73发送源动作；目录顺序及选择属于Owner。63在55切职业、197确认重算，目标职业独立展示，头部始终配当前职业自己的等级；65只返回答案，父64恢复才付费/消耗库存与装备。raw67沿既有progression消费者。最大HP同步不回血，声音输出每次成功提交后只领取一次。完整演出和普通道具未纳入本批。

住宅税收`world_tax`显示raw90冻结名单原序、当前G金额、五行滚动与合计，无取消；确认只关闭90，raw98按当时资格自动入账、通知并清理，不显示第二个按钮。该年度税收页面与非模态月报分属不同消费者。

`ark_world_queries`从当前Owner生成设施详情值，经营属性调用原派生规则并使用当前职业/共享成长，邻接来源只在与有效缓存一致时显示；不另持世界、不刷新提示。实际建筑点击经FIFO打开源raw74，入住raw80、升级raw81和返回沿原资格操作，不再另造冻结式详情Owner。

## 数据与来源

运行资源副本位于 `assets/`，世界定义与脚本位于 `assets/simulation/`。产品构建从这些副本生成数据，不链接research target，不在运行时读取APK或研究工具。

`assets/simulation/SOURCES.json` 记录冻结研究源与产品迁入结果，素材来源另见 `assets/SOURCES.json`。接入只消费已提交、已交付的维护代码；在途研究改动独立登记，不能悄悄混入产品。研究提交同步、产品构建/测试、真实窗口和原版动态对照分别保留证据。

## 旧切片边界

`ark_game` 及 `src/world/`、`src/facilities/`、`src/people/`、`src/economy/` 的旧建设/首访生活切片保留为诊断，显式入口是 `--legacy-slice`。`--ai-preview`、`--check-ai`、`--verify-play` 和旧 `--inspect-page` 名称自动选择该切片。`--tick-rate` 可配 `--legacy-slice` 或允许覆盖时钟的命名旧诊断；默认世界拒绝覆盖，`--verify-play` 仍要求原节拍。

旧切片七种单格建设、单人局部交接、1456步月前保护及初局固定布局诊断的契约见B1，不适用于默认持续世界。新增玩家建设应直接向完整Owner提交，而不是持续扩展旧模型或复制它的耐久状态。
