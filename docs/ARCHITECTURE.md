# 项目目标与架构

## 目标与依据

以C++17 + raylib复刻《冒险迷宫村》一代，尽量保留玩法、数值、事件顺序、UI与操作流程。先稳定二维世界和交互，再替换为3D表现。

[research入口](../research/README.md)及其维护规则、prototype、素材是产品唯一规格来源，输入身份见 [EVIDENCE](../research/dungeon_village_1/EVIDENCE.md)。产品侧只读维护交付，不读取 `research/work`、不执行逆向，也不把夹具、研究原型保护或跨版本截图数值当作原版规则。

研究覆盖、产品接入和原版一致性分别验收。持续世界及任务闭环已有历史验收；此前e8接入已实现五项菜单中的建设/冒险、当前世界建设与设施交互、任务管理、完整授勋操作和晋级页面。系统仅开放稳定主场景两栏手动存读档；2b479f6接续开放村办类型0/1/2、奖励95、普通道具/设施强化及按flag16开放的南瓜商会，898b653继续开放类型3地图扩张。信息已开放冒险者、收支、物品和装备；776508c本批补城镇/设施目录与正式导航接线，其余未交付操作仍禁用。具体差异集中在 [原版对照](reference/REFERENCE_CHECKLIST.md)与 [研究需求](reference/RESEARCH_REQUESTS.md)。阶段历史保留在 [B1记录](stages/B1-playable-prototype.md)。

2026-10-07用户批准工程审阅建议后，维护存取已分离为独立目标，桌面自然预运行/存档验收/截图职责移至world_inspection，并加入玩家新增字段分类检查；Owner和正常输入提交政策不变。具体边界见[ADR-0055](MILESTONES.md#adr-0055)，问题来源见[PRODUCT_REVIEW](PRODUCT_REVIEW.md)，研究历史与可接范围见[当前审计](reference/REFERENCE_CHECKLIST.md#research-history-current-audit)。

## 三层结构

按用户最新决定，试玩固定一倍速，已移除切换按钮、world-speed窗口入口及旧切片Tab切换。加载沿用当前会话速度；源规则与无窗口显式速度组合回归仍保留，历史速度字段不要求改格式。

依赖从表现层向下，规则层只使用标准C++，没有raylib、窗口或屏幕类型。

产品公共库通过独立`shared-libraries`预设统一以Release构建；四套消费者导入同一份CMake目标和DLL，不分别编译核心。规则、Owner、存档与会话保持原依赖方向；Debug调试消费者代码，库内部已优化且不保留符号。Windows全部EXE及DLL统一位于`build/bin/`，EXE带消费者配置后缀。Release玩家包复制游戏PE导入闭包和资源并恢复`ark_village.exe`名称。此政策不修改research目标或构建缓存。公共源码/头/数据/工具链内容身份与成功DLL产物哈希由构建侧验证；EXE内嵌身份，在访问业务对象前检查实际加载的Ark依赖，不匹配退出78。运行不依赖Node/构建清单，不为玩家带入未使用维护库；装载器先发生的缺DLL/缺导出错误与守卫范围分开，见[构建检查](CONTRIBUTING.md#构建检查)。

## 唯一Owner与事务

默认世界唯一可变聚合是 `StartupWorldRuntimeState`。它持有当前地图/实例、共同现金账本、随机流、实时人物/怪物名单、共享定义进度、任务、场景/日历、脚本页栈及表现缓存。

静态定义与可变共享进度、设施实例、人物实例分开。初始化对象仅用于真实新局投影，完成接管后销毁。路由、脚本、收尾和月报所需状态是在调用时构造的临时投影，提交后丢弃；不额外持久保存地图、资金或随机副本。道路/撤除/移动仍提交该Owner：FIFO绑定观察到的编辑模式、定义、旧起点及移动实例；移动重建源实例并保留规定白名单，旧人物目标沿原到达/退出消费者失效，不由桌面迁移或清AI。住宅H资格与真实800G重建费用独立。

`prepare_startup_world_runtime` 在候选Owner内组合原资格和消费者，全部成功才替换当前世界。桌面每次获准更新还消费 `update_startup_world_render_cache`，保留原可见性及缓存时点；任一失败保留旧Owner并明确报告，不残留扣款、名册、随机游标或局部页栈提交。

`ark_world_save`显式编解码版本化耐久字段、验证稳定身份/引用/占地并纯重建缓存，独立于raylib。随机、页面栈、held与一次性输出不落盘；账本余额与月度累计分别保存，不重放审计费用。文件层采用同目录临时写入、flush和替换，失败保留旧档；WorldSession在FIFO边界捕获/提交，成功读取更换会话代次并拒绝旧命令。两栏手动档位于Windows用户本地目录，自动轮内恢复另待合同，退出不自动保存。字段覆盖见[存档模块](../src/app/save/world_save.md)。

维护存取接口为`startup_world_persistence.hpp`，由独立`ark_world_persistence`目标实现，依赖唯一`ark_world_runtime`及私有`ark_world_hash`。玩家运行时不依赖此维护目标；维护测试显式链接，normal保存完整稳定主场景Owner/随机/账本，replay另存有序审计及外部控制器。它不接管玩家系统菜单。读取返回私有Session候选；控制器验证完成后才联合安装，不能将日历轮内审计当作下一帧入口。SHA256用独立纯C++ `ark_world_hash`，文件只读校验、预算及同目录替换失败不改变现Owner/旧有效档；codec字段覆盖按产品Clang AST严格比较规范清单，不编码指针或对象padding。历史c19ab6a/b99c6db曾只变页面布局而保留玩家身份；当前776508c增加菜单/任务/NEW字段并采用世界5/应用8/系统2，旧维护完整Owner和应用快照均拒绝。玩家schema5独立保存任务NEW，页面与构造缓存不保存并在恢复清空；旧玩家schema4因本批已确认初值语义更新而拒绝。

产品系统2以app/session/world_system提供的独立语义身份存取最高纪录/继承，维护系统仍默认使用维护dataset；同一codec和原子文件桥保留全部校验，不自动回退身份。说明正文和UI布局不触发产品系统纪录失效，实际字段/语义变更才评审身份；玩家schema5及随机政策独立保持。

完整应用维护目标另持标题表现Owner及有序应用动作，AVRAPP01应用语义8保存标题20槽与相关外层状态，嵌套AVRSAVE1世界语义5、系统语义2；旧维护语义明确拒绝、不迁移，它们都不替换玩家schema5。标题基础人物皮肤为标准C++只读计划，桌面目前只将其用于定义0职业/主武器及草稿性别预览，不挂载完整标题宿主更新，也不按60FPS推进随机或动画。e73bb31三张Steam启动PNG仅用于静态背景/顶部/草边，现有Logo和两栏手动档流程保持。

`startup_information`纯查询读取Owner的收支、物品、装备及村庄统计；收支仍按12×5×2桶、原月/年、五类别和32位回卷格式输出，不推进日历、资金、随机或NEW标志。`startup_world_information`已迁入raw9/34–40的输入、模态、目录与退休消费者，35→60追踪保存来源资格及可选真实人物实例；NEW清理发生在源页面事务边界，不由纯查询执行。b99批信息入口/Steam目录/追踪FIFO已有历史验收；本批34/39及40维护消费者已正式迁入并接产品，最终验收单独记录，不消费research在途代码，也不以信息页替代自动月报。

## 更新、页面与表现

普通无界窗口先在`world_title`完成开始/选档；此时尚无模拟线程，初始Owner不更新。继续沿玩家codec准备候选、保留冷启动随机/暂停/速度后一次安装，再交给WorldSession；新游戏先在标题编辑城镇名称/主角姓名/性别，确认才在私有冷启动候选中安装资料/继承，不覆盖世界存档。独立system.arksys由标题启动边界及活动worker管理跨局纪录。有界世界诊断保持直达，标题三个具名诊断不推进模拟。此启动边界不创建第二个运行世界或接入原自动档，见ADR-0060。

默认不带参数、`--world` 和 `--check` 都选择完整世界；`--world` 是显式别名。窗口模式每个进程只启动一种世界，不运行旧Game来补建设，也不同步两个持久Owner。

逻辑更新与60FPS绘制分离。`ark_world_session` 的模拟线程独占世界提交，以47ms最小开始间隔、实际观测提交及卡顿不补算调度；倍速由源场景规则决定获准轮数。主线程读取不可变 `WorldFrame` 快照并以60FPS绘制，锁只保护命令队列和快照指针。输入按序在完整事务之间提交，相邻镜头请求可以合并，暂停/确认/倍速是不可跨越的顺序边界；有限命令批次后检查更新截止，持续拖动不会饿死世界。线程退出会唤醒并等待当前事务完成，失败发布明确错误并停止更新。原47ms门槛属于Android render/input路径，产品独立调度、桌面时钟和原框架生命周期尚未动态认证等价。

只对相邻快照中普通可见行走做位置插值，瞬移、进出设施及状态变化直接切换；逻辑位置、动作计数、伤害、金币和随机流不插值。命令提交后的快照不重复播放上一段位移。

`startup_world_presentation`另提供显式维护请求：Session核准真实页栈，在私有候选内共同提交绘制期随机、任务失绑清理和声音请求，再返回冻结计划。它不挂到桌面绘制循环，也不改旧逻辑回放；调用次数/夹入位置及包装准入由独立维护控制器记录，0/1/2请求和双恢复全输出另验。原框架自动准入/赠礼包装尚缺映射，不能用世界暂停、60FPS或一次逻辑更新代替。建设图块及闪烁使用独立只读查询，不需要这种有副作用请求。
