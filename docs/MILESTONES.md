# 计划与决策

所有状态从新产品重新开始。旧M阶段不是新产品的完成依据。

| 阶段 | 范围 | 状态/验收 |
| --- | --- | --- |
| B0 | 工程/文档/本地Git重置，raylib启动和打包资源 | Completed；四套构建/CTest、资源、两种尺寸窗口和研究边界检查通过 |
| B1 | 原版领域模型与定义/共享进度/实例/地图契约，首个建造/冒险者加入切片 | Waiting for research；[切片设计](stages/B1-playable-prototype.md)，等待真实新局与到访规则 |
| B2 | 建设目录→放置/移动/撤除/道路→详情及邻接经营 | Planned；规则/页面分别依研究，缺分支不猜 |
| B3 | 人物资格/候选/路径/到达收费/使用/退出/成长 | Planned；只接已证分支，来源统计和局部顺序对账 |
| B4 | 日历/经营/任务/人气/道具/城镇闭环及文件存取 | Planned；完整调度、奖励和恢复依各自交付 |

| B6 | 3D化重构 | Planned；在二维行为基线上替换表现，复用领域测试 |

阶段前先分析并确认设计；编码遇到非预期问题停止。结束四套配置/编译/CTest通过，实际窗口/输入及原版对照另记。
四套预设为headless-debug/headless-release/desktop-debug/desktop-release，不沿用旧预设或历史日志。

近期操作项以 [TODO](../TODO.md)为准；本页只记录阶段范围、状态和稳定决策。

## ADR-0001

main从新起始提交建立；research工作区与未完成成果保留，旧工程存放仓库外备份。远程改写另按明确指令执行。

## ADR-0002

Accepted：C++17 + raylib，核心仅标准库，表现独立。先2D复刻原版玩法/UI，再考虑3D替换。
原版研究事实优先，旧demo/schema/测试不兼容；允许必要APK素材用于本地学习，按研究来源登记副本。

## ADR-0003

Accepted：当前只建立可验证的启动底座，不生成虚构村庄。业务模型、地图和原版页面按研究交付逐批设计/确认/实施；缺证依赖等待研究。

## ADR-0004

Accepted，2026-10-03：用户选择等待research补齐后再做可玩场景，不采用临时地图/资金/人物。
首个切片的“招募”指新冒险者加入村庄，与住宅入住/任务征集分开；是否自动到访、手动命令或收费由研究证明，不预设招募按钮。
优先缺口与交付条件见[研究需求](reference/RESEARCH_REQUESTS.md#首个可玩切片的阻塞项)。已证独立底层规则可按阶段设计推进，不要求等整部游戏研究完成。
