# 主动经营验收与建设收益方案

<a id="full-unlock-campaign"></a>
## 完整经营长跑的验收范围（2026-10-10，用户明确要求）

最终目标是证明真实游戏进程能够健康推进：从新局开始，按真实前置逐步解锁并消费全部可达的玩家功能、建筑、道具、装备、魔法、活动、探索副本及BOSS，完成逐星、自然通关、继续经营和继承。首星、二星或日期抵达计分页仅是阶段结果，不能称完整长跑通过。保留冻结三个月及短规则测试，但它们不替代这条主动经营主线。

“全部”按当前固定来源的定义ID和功能合同核对，不只测每类一个代表。先保留完整目录分母，再区分玩家内容、地图/任务专用对象及尚无可达证据的内容；排除项必须附来源和理由，不能因策略不会使用或研究消费者缺失而默默删除。互斥或无法在同一局消费的内容用同身份合法业务前缀分支验证，保留一条连续主线；多种子用于补不同自然轨迹，不能靠注入资源、改日期或强制随机制造解锁。

| 内容 | 必须有的真实输入与结果证据 |
| --- | --- |
| 建筑、住宅、植物、地图编辑 | 解锁/商会点数购买→领取→合法占地/连通→付款建设→施工完成→实际营业或对应功能；设施道具强化、共享等级与邻接价格/品质/魅力分别验证，住宅检查入住/税收，装饰不能拿没有营业额判失败 |

每个覆盖项分别记录资格、输入/费用、效果、后继和恢复证据；最终认证要求全部适用项闭合，当前不具备该条件。收益策略先服务持续经营和晋级，再安排有预算的覆盖消费：预留维护/任务/活动/新建筑点数，不为了逐项打勾破坏现金流。三星收入35000G尚未达成；旧实验最高月收入11321G，接续Steam布局轨迹已达12286G，具体来源及中止边界见[本轮记录](#steam-layout-blueprint)。优先继续新店强化、密度/植物与真实需求对照，不盲目推进日期。无进展应输出阻塞条件、未满足的数值与前缀，限时结束并定向修复，不修改通过阈值。

实施顺序：①定义级覆盖目录与分段观测、失败诊断；②收入策略达到三星并建立可恢复业务前缀；③按解锁补齐四五星、全内容驱动及逐项效果断言；④自然通关/继续/继承和缺项复核。源码中的`CampaignCoverage`已为现有所有主动路线记录每进程`coverage-segment-*.tsv`，每月/保存/失败输出；`--coverage-inventory`输出完整静态分母。当前观测包括设施收入/共享改良/升级、库存变化、装配、活动开始、任务完成计数、配方状态和晋级。它**不是完整证书**：活动完成效果、物品使用因果、魔法实际命中/治疗、BOSS链及跨段证据合并仍待逐项接入；加载前缀不倒填历史消费。最终全功能收口不能仅根据这些观测标签判断成功。

## 三星定向复现与收益修正（2026-10-10，已批准实施）

用户要求从已保存前缀补失败诊断，同时改进收入策略；进一步明确优先设施道具强化，合理安排建筑密度/植物邻接，必须用村子点数购买新解锁建筑并实际使用。两条轨迹分开：`diagnose-third`保持旧决策，从月49玩家档冷载；`income-baseline/improved`在独立副本做有界经营对照。研究规则仍冻结1f19c88，不混入在途交付，不通过修改资金、点数、库存、日期或随机凑升星。

诊断仅增加失败stage、对象ID、领域error的透传；候选仍完整回滚。失败时保存更新前完整Owner及随机、schema/数据/生成库身份，`replay-failure`只执行一次更新并核对同一拒绝及输入不变。玩家前缀冷载本身沿新随机政策，且系统文件含原失败期间合法峰值，不把前缀续跑误称精确维护回放；精确回放从新捕获的失败前Owner起算。证据集中在`build/validation/third-star-diagnostics/`，原失败现场只读保留。

收益策略通过真实WorldCommand执行商会85支付点数→93领取→建设/完工/营业，以及74→75消耗道具→76共享强化→77结果。保留两个月当前维护/职业费用预算；每次使用前调用已交付纯规则预测，排除封顶无增益，按上一个完整月的营业额估计收益、四个月简单回本门槛选道具，现金购买预算10000G、最多24件。预测仅用于选操作，实际支付、库存、改良及收费另核；不把预期收益当实际收入。新商店先检查解锁星级、现金及连通可放置空间，保留学校占地，优先当星级新内容，不再机械补早期同类店。实验控制器不序列化为已认证业务档，明确拒绝保存，待收益与三星条件通过后再设计正式后继前缀。

### 本批实际结果

原策略从保存前缀续行13085轮后重现投射71拒绝，完整Owner单轮精确回放通过。根因是法术接触只生成延迟投射，本轮damage_target为空，表现却误用该字段；产品按已证实际碰撞目标修正转发，补瞄准目标与碰撞目标不同/不提前扣HP/随机/回滚检查，同一失败Owner修复后单次提交成功。详情及研究维护交接见[最小复现](../reference/RESEARCH_REQUESTS.md#spell-contact-visual-target)。

旧收入策略两完整月（原始月50/51）分别9331/5318G，共14649G，现金净增4644G。只用2件库存道具的先行观察分别9456/8959G，共18415G。首次加入两座新店但仍只按历史营业额分配24件道具时，两店观察期均零收入，实际营业断言失败，现场保留，不计通过。

随后为新购店增加独立小额引流预算：先等待完工，再以共享魅力20为玩家目标优先使用有魅力增量的库存道具，单件购买最多500G；不为无历史的新店编造月收入。24件总上限/10000G现金预算和旧店回本约束保持。大众酒吧花90村点、800G建造，弓箭练习场花50村点、800G建造；均实际完工、连通、强化到共享魅力21，分别营业810G与2196G。月50/51实际观察收入10072/12645G，共22717G，现金净增10187G；24件均来自真实库存，本轮道具现金购买为0，不能宣称已验证此策略的买道具分支。

最终证据：`build/validation/third-star-diagnostics/runtime-introduction/build/validation/business/`及相邻business.log；完整观察Owner已保存，能用`inspect-observation`只读复核。原始slot/sidecar保留不变；它是实验终态，不是可接续三星认证的业务档。对照共用同一玩家前缀和冷启动种子；改良分支含本批投射表现补正，旧基线未触发该失败分支，版本分别保留。单前缀策略结果受实际行动/随机顺序影响，不是道具的纯因果估计或全局最优。

当前系统最高月收入记录为11321G，和观察账本的12645G不是同一统计口径；三星仍需按真实maximum_income≥35000与人气等条件验收，禁止用测试累计营业額替代升星字段。后继先优化密度/植物与新店布局，再扩大居民/需求及强化收益，不盲跑日期。两Debug标准及Release修复证据见[B1](B1-playable-prototype.md#third-star-diagnostics-income)。

## 2026-10-10三星隔离验收的实际阻断

1f19c88规则的隔离原EXE在源码重排之外运行。阶段A真实完成搬店/铺路360G、西餐厅120点兑换、建设及600G营业收入、20次胜利，在月49保存463135字节玩家档，并由新进程冷载。阶段B到月56后以`runtime=3/world=3`失败，含义为runtime_failed/共同调度consumer_failed；不是超时，且日志不足以识别具体消费者。失败时二星、人气1340、最高月收入10627、38次活动、23胜、任务24活动，不能认证三星或学校消费。

阶段A约1359秒，阶段B约1220秒；所有本轮进程已收齐，无自动重跑/放宽断言。现场位于`build/validation/product-cleanup/campaign-runtime-e1b164e7711948a48592e255351b3c1a/build/validation/third-star-road/third-star-player-e756f582-f16b-4cb6-8857-78f5172d1e6d/`，只读诊断为`build/validation/product-cleanup/third-star-runtime-failure.md`。已有前缀可用于后续定向排查，玩家冷载会换随机，不能称精确维护回放；系统纪录还包含失败前已合法提交的峰值。

下一步先补足拒绝发生的stage/实例ID/下层错误定位；同时收入策略仍停在11店，不能把继续推进日期当成35000收入目标的经营方案。这两个问题分别处理，不改研究规则凑晋级。

2026-10-09。用户已批准本方案，并要求并行构建短测试与长测试；用于检验游戏推进的产品长测必须含真实世界操作。本文件保留设计依据并记录实际验收，不是已获得全局最优收益或五星通关的报告。

初版建设分析、五组短对照及首星结果按产品冻结89f157c的391项维护闭包；二星接续使用3780a3b的402项闭包，后续e73bb31修正新局任务目录和共享人气，均保留各自历史数值身份。当前已冻结1f19c88的430项闭包并修正邻接实际收费，旧经营档不能续作修后自然路线前缀。不修改或构建research；后续短对照与主动长测分别登记，不读写正常玩家档。

## 修后建设建议与验证分工（2026-10-10）

研究侧负责短时功能/逻辑及必要边界、顺序、回滚测试；本产品侧负责真实经营、升星、新内容消费与跨进程存读档长链。既有有效断言和三个月基线保留，具体见[验证分工](../CONTRIBUTING.md#研究与产品的验证分工)。

1f19c88已完成同种子/初局/三个月的P0–P4复验，实际报价与到达收费缓存一致。含首星必需面包房的候选中，P3（面包房35位于格12,6，向日葵66位于格9,6）本轮现金净增最高：总建造800G，最低现金4200G，期末11100G；比只建面包房的P1多160G。P0虽期末现金更高，却没有满足首星建设条件；P4提前加花店有额外建造/维护和客流分流成本。完整数值、源身份和局限见[B1本批记录](B1-playable-prototype.md#research-1f19c88-integration)。这些格坐标属于既定初局，不能外推不同布局、种子和长期全局最优。

本批经营长链沿已批准的P1稳定基线，避免在同一次跨进程认证中切换策略。修后全新首星已通过建设营业、培养、7次任务胜利、原始绝对月22真实晋级与绘画展、完整后续月营业和独立冷载复核；随后从本批档案推进二星与三星。旧e73bb31前缀仅保历史，不换版本头或改世界数值复用。下方旧批次“收费缓存未修”等结论保留其历史时点，不再代表当前状态。

修后二星已实际升星、付100点举办活动30并营业至原始月41，三进程验证通过。三星试跑定位出两处自动玩家遗漏：西餐厅40须先在商会支付120点并领取资格；二星10店4屋已经围满原道路，直接等待建设候选无法推进。现保留120点预算，并为本次已核地图真实搬迁实例23/定义45花店（300G），铺六格道路（60G），保留学校四格和连通；未知布局明确拒绝，不强套坐标。独立临时Owner的真实输入检查已验证搬迁后销售/月桶/序号保留、只扣360G、道路候选恢复，原档不变。它是既有布局的有限改进，不宣称全局最优；后续初局方案应比较提前预留分支是否省去搬迁费。

三星仍须实际西餐厅营业、任务胜利和业务保存/冷载，再满足1500人气/35000最高月收入/15活动/西餐厅四条件，建设学校并消费活动7、继续整月营业。取消的失败试跑未生成stageA，未复用其未保存进度；新路线从已通过二星档重新开始，结果按[B1](B1-playable-prototype.md#research-1f19c88-integration)记，不将短道路检查代替三星通过。

## 收益目标和策划约束

“最大化收益”必须有期限与约束。建议比较3个月开局回本、12个月累计净现金，并以相同经营里程碑比较效率；长期再检验24个月现金安全和星级推进。这些是测试策略参数，不是原作数值。

主指标为同起点、同期限下的净现金增量，完整扣除建设、维护、人物费用、招募/续期、培养/交易支出，分别记录设施净经营收益、任务奖励、税收、卖出与其他收入。不能用出售库存、少做升级目标或停止出征把账面收益“优化”上去。记录最低现金、亏损月份、回本时点、首星/后续星达成时点、任务胜率、已开放内容的实际使用情况。

硬约束：实际目录可建、真实资金支付、完整占地合法、通路保留、真实建设完成、维护可支付、有效业务目标持续推进。不能靠负债维持、关闭必要装备服务、取消全部任务/培养或永不升星来取得高余额。所有试算候选只读状态、经真实命令改变世界，禁止写入金钱、点数、人气、人物、等级或任务结果。

只能报告“在本次候选、期限和种子内最好”，不能凭固定表或单一种子保证全局最优。随机、客流竞争、共享升级、任务出征离店和解锁都会改变最优组合；最大化收益是需逐步测量的优化目标。

### 已核实的关键规则

- [经营规则](../../research/dungeon_village_1/rules/FACILITIES.md)：维护费向零取十整；等级/道具改良属于定义，多个同类店共享，维护费按实例支付。升级提示不等于已升级，真实raw81消费者才提高等级。
- [活动选择](../../research/dungeon_village_1/rules/ACTIVITY.md)：普通加权目标使用定义魅力，不能把实例邻接魅力直接当作客流权重。多格候选、路程、访问历史与特殊分支仍影响真实选择。多建店会分流客流，不会凭空生成顾客。
- [到达/退出](../../research/dungeon_village_1/rules/FACILITY_USE.md)：收费与退出效果分离；武器/防具/饰品店使用装备价格替代普通设施价格，表中价格0不等于零收入。普通到达路径不能凭假设加“人物钱包不足拒付”。旅店活动0/1的等待是200次解释，不能按表中60直接估算其周转率。
- 邻接：单格外环含对角，每来源/目标实例去重，不按定义去重；向日葵提供价格+20、品质+5，零维护费。价格/品质封顶后只算实际差值；给装备店增加普通价格槽，不等于装备实际成交价增加。道路的实例魅力+2同样不能直接算作新增顾客。
- 升星收入纪录读取[月报snapshot2](../../src/simulation/village/rules/world_month_report.cpp)，为类别0/1/2的收入合计峰值，不是净利润、不是当前所持资金，也不是只看单家店营业额。经营优化另算净现金，不能混用指标。

### 滚动扩建与现金安全

建议自动玩家采用滚动决策，而非把全地图一次铺满。每个完整经营月汇总实例收费次数、成交额、维护费、使用时长、价格/品质/定义魅力、等级和完工状态。把单店净贡献与全村增量分开；两家同类店共享升级但各付维护费，故评价单位是整个组合。

建议现金保留线为“未来两月当前设施/人物费用＋下一项已选任务招募费及一次实际续期费”。这是可调玩家预算政策；费用从当前消费者查询，不注入固定演示数值。若需入住或培养，再为即将确认的真实报价留款。非必需扩建后低于保留线则延后；欠缺的升星必需设施也需先经营筹款，不能透支安装。

扩建顺序：必需解锁建筑→弥补装备/恢复服务→经对照证明有正增量的商业/装饰→合格住民住宅→为下一星补数量。接近收入门槛时仍核现金安全；达到2/4星的10/25家商店数量要求需真实扩店，但不能把“数量刚满足”当成“每家都赚钱”。连续低效店先查客流、道路、等待及共享升级，再评估移动或拆除成本。
