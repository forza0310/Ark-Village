本轮目标为真实新局→建造设施→新冒险者到访/加入→在场景与名单中可查询。
这是验收操作路线，不表示建造触发到访；首访由更新计数自动触发，不创建手动招募按钮或收费。
不要求本切片先完成住宅入住、任务征集、战斗、完整成长或所有设施。

用户未采用此前独立演示场景建议：不使用临时地图、资金、固定申请者/入住费或自定时钟补齐可玩场景。
研究验证仍可使用明确隔离的测试夹具；夹具不是玩家新局数据，也不能作为场景验收。

## 恢复可玩实现的最小交付

完整交接清单与接收条件统一维护在[研究需求](../reference/RESEARCH_REQUESTS.md#首个可玩切片的阻塞项)。本切片主要依赖：

- RQ02：可读取的新局底图、边界/入口、初始设施/人物、资金/日期/解锁、初始化顺序及初始镜头。
- RQ07/RQ10：至少一名新冒险者的定义、到访资格/触发与身份初始化；明确与人气、日期、城镇状态或事件的实际关系。
- RQ07/RQ01：人物加入、到访展示、关闭展示、场景生成和名单刷新的完整顺序；失败/重复与到访后初始行动。
- RQ03/RQ10：新局可建目录及至少一种真实可建设施，完整审批/扣款/绑定/取消/拒绝；不假定已恢复三类都初期开放。
- RQ06：上述施工、到访及人物行动的最小更新资格/顺序、菜单影响和速度换算；不要求先恢复全部月报。
- RQ01/RQ04：本切片页面/输入/字体、地图及首名人物资源绑定和连续前后状态，支持独立行为与视觉验收。

研究可分批交付。已证定义、几何、共享进度、地图访问等独立规则可继续进入底层设计，具体编码仍先确认设计。
新局/到访依赖缺口未补齐时暂停对应可玩实现，不要求研究先完成整部游戏，不修改研究侧的完成状态。

## 本轮实际范围与差异

参照research/prototype的startup、数据编译器、SourceSprites和中文字体适配；迁入tools的维护解析子集。
不链接research target、不使用生成Java或旧fixture；产品副本与来源固定在assets/SOURCES.json。

- 设施不可变定义、定义共享等级、实例和人物分模块；Game唯一持有可变状态，建设以候选状态一次提交。
- 源格不是完整加载后地图，种子ID是产品身份；设施下面临时显示草地27，原入口重建/道路邻接刷新未复刻。
- 道路/入住募集仅禁用目录预览；移动/撤除/住宅/经营收入、完整人物AI/成长/存档未实现。
- 人物保留出生格及已证属性，未知首段AI不套用旧原型。出生点使用本地随机选择，不复现APK随机消费。
- 界面240×330、60FPS、相机收敛和物理热区为适配策略；源镜头/资金/工期不替换成演示参数。
- 1456模拟步后保守结束本轮，可重新开始；这是产品研究边界，不是原版结束条件，不跳过未闭合月报费用。
- SEB结构保留完整记录，PNG边界只校验实际请求帧；草地frame3/海面未用frame1/2不当成正在绘制的非法图块。
- inspect-page为有界渲染检查，不能记为正常新局或真实鼠标输入；四页原版人物名单尚未接入。

## 模块与依赖

只建立本切片会使用的模块，不预建战斗、任务、存档、ECS或事件总线。

| 模块 | 接口 / 实现位置 | 职责 |
| --- | --- | --- |
| world | include/ark/world、src/world | 格坐标、尺寸、完整占地、实例ID与占地查询；不接触屏幕坐标 |
| facilities | include/ark/facilities、src/facilities | 不可变定义、定义共享进度、设施实例、两朝向几何和建设报价 |
| people | include/ark/people、src/people | 人物定义/实例、到访资格/加入状态、名单与行动；未知职业/属性不补造 |
| app | include/ark/app、src/app | 唯一可变聚合所有者、建造命令、到访事件与新局/逻辑更新协调；保留启动参数 |
| desktop | src/desktop | raylib资源生命周期、等距投影/反投影、场景渲染、菜单/预览与输入适配 |
| assets | include/ark/assets、src/assets | 独立标准C++的维护SEB/TSV解析子集，供desktop校验和绘制 |

world为底层；facilities/people依赖基础身份与格坐标；app协调这些模块；desktop调用app并读取只读状态。
标准库业务代码组成ark_game目标，启动参数保留ark_launch；ark_village链接二者与raylib。避免一模块一小库。
每个实际模块在对应src目录放一份README.md，简述职责、公开入口、依赖和研究依据；不在include重复放文档。

## 状态与命令契约

- 定义目录不可变；共享定义状态、设施实例、人物、资金只有一个权威存储。占地索引由实例推导，校验完整绑定，不能只检查锚点。
- UI只保留页面、选择、预览位置、朝向和提示；不直接扣款、修改实例或决定人物资格。
- 建造预览读取同一校验函数；确认重新校验定义、边界、完整占地和资金。可达性不作为额外建设前置。
- 命令返回明确错误和结果ID。跨资金/设施/人物的操作在候选状态上完成校验，一次提交；拒绝不得消耗ID、资金或人物机会。
- 人物定义ID、实例ID、到访事件身份分开。创建与展示时点以研究为准，不把关闭弹窗等同于创建人物；重复触发的实际结果需要来源及验收。
- 地图格坐标与业务身份不包含raylib类型。2D投影参考X=30×(x+y)、Y=15×(y-x)+15，再应用相机；未来3D替换这部分与拾取，命令不变。
- 不自行添加周期到访、招募费用、经营收入或人口奖励来凑闭环；已证副作用依原顺序实现，其他系统分别按研究进入后续切片。

## 自底向上的实施顺序

1. 基础身份、格坐标与占地几何；验证双格两朝向、越界、重叠、多实例同定义。
2. 定义与共享状态、资金和设施实例；建设候选事务以及拒绝后完整状态不变。
3. 真实新局初始化、人物定义/到访资格/加入、最小调度；验证人物唯一性、事件顺序和实际资源变化。
4. raylib素材封装、投影与拾取、建造目录/预览/详情、到访展示和人物名单/场景。
5. 实际窗口操作、四套构建和CTest、差异登记、文档更新与本地checkpoint。

重要文件开头注明职责/边界；公共命令、几何、候选提交、投影/拾取、逻辑调度注明前置、效果或易错点。
注释解释为什么及研究边界，不逐行复述代码。已证规则给出维护报告链接或原表字段；原型策略明确标注。

## 验收与暂停条件

- 领域验收覆盖完整占地、多格旋转、不要求接路、相同定义不同实例、余额不足/重叠/越界后的事务不变。
- 可玩验收覆盖真实新局、建设成功、达到原版到访条件、按已证顺序创建/展示/加入、提示关闭后的场景/名单一致；取消任何UI预览不得改变领域状态。加入是否收费以研究为准。
- desktop资源解码、源/副本哈希、程序旁资源加载；投影/拾取同源，缩放/留边后输入坐标正确。
- 四套headless/desktop、Debug/Release配置、编译和CTest；Release不得通过关闭assert跳过检查。
- 真实窗口验证建造、取消、旋转、选择设施、余额不足及冒险者到访/名单；自动领域测试不代替鼠标输入。
- 原版视觉、研究规则、产品功能分别登记；跨版本截图数值和测试夹具不能记为原版新局验收通过。

研究发现与所选方案冲突、跨域契约存在歧义或出现非预期编译/测试问题时，停止对应编码并保留现场、说明原因及恢复方案。
