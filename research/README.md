## 消费与保留约定

- 原版事实、局部推断、维护安全策略、夹具和异版本动态分开；同名／同图不自动认证消费者相同。
- 产品只消费已交付规则、独立实现、数据和有来源清单的素材；运行不读取APK或research/work，研究不代改产品。
- 生成Java、IL2CPP映射、原游戏／存档、账号身份、候选及分析缓存保持只读来源或本地work，不进入发布源。
- `work/`只作忽略的本地工作目录，不强制加入Git。正式规则、必要来源证据与参考图可归档，长期解析／提取工具归`tools/`；研究交付的audit／check／verify核对脚本及其临时产物禁止Git跟踪，也不得改名规避。验收结论合入现有文档，不为每个小步骤新建过程记录。
- 日常研究构建只留项目内单Release动态树，Debug／插桩按需；测试按功能批次集中，仅选受影响的功能／逻辑及必要短组合。
- 2026-10-10用户明确分工：**产品侧负责世界长跑验证，研究侧只需简单的功能／逻辑测试。** 研究围绕已证规则、关键边界、拒绝及必要事务组合选择最小测试，不以自然经营到某星级／完整通关为交付前置，不继续新增经营长跑Driver或常规全世界长测。条件夹具、原版事实和产品自然路线结果分别登记；既有长测／快照证据保留为历史参考，不自动重跑。详见[研究测试分工](WORKFLOW.md#研究与产品的测试分工)。
- 原窗口观察、研究C++检查、OS输入与产品验收分别报告；纯文档整理不运行游戏回归，也不把旧检查记成本轮通过。
- 冻结实验与失败证据不删改；有效引用历史不当作泄漏，账本／任务／检查点不宣称永久有界。
- 阶段结束收齐本轮进程，只提交已验research文件、保留其他维护者改动，不自动推送。
