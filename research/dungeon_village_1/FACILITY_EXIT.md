# 设施退出、共享使用数与满足度请求

日期：2026-10-03；阶段 [R3-A](stages/R3-facility-exit-helpers.md)。固定输入与常规/fallback 行号
见 [证据清单](EVIDENCE.md)。本报告延续 [到达记账](FACILITY_ARRIVAL.md)，不将到达和退出合并。

## 退出局部顺序

常规 `c/b.java:3832-3948` 的 opcode 24 与已有低层 `Character.java:11810-12125` 交叉核对。
关键低层标签 `Lc7c`（11944）先调用定义 `e()`，再清人物标志 33、从实例移除人物、清控制列表，
设置状态并排入活动 0；随后依活动类别分支追加命令。这是带异常捕获的巨型方法局部，不是原作事务。
当前实例不存在时走诊断/清理，不调用共享使用 helper。

| 类别 | 局部退出行为 | 限制 |
| --- | --- | --- |
| 2 | 追加 `e(9,0)` | 不进入普通商店满足度 helper |
| 1，细分类 1/4/5 | 装备/道具展示和后续操作码 28/30 | 本阶段不执行装备选择/数值 |
| 1，其余细分类 | 调 `a.e.a(definition,character,tenant)`，随后可能抽定义 z/A 参数追加 opcode 19 | 满足度小函数见下；opcode 19 的经验/延迟另行研究 |
| 9 | 调恢复方法，然后清六项人物 I | 不把所有完成访问都清零 I |
| 其他 | 没有以上分支的同等效果 | 不由“没有此分支”推断完整行为无效 |

多格设施退出前还检查当前位置是否邻接状态 3/4；无邻格时按绑定格与方向顺序寻找可退出位置并
直接修改位置。该行为不同于原型“统一回到接近点”，本阶段仅记录，不实现瞬移/运动 UI。

## 定义共享使用数与升级提示不是升级

`a/o.java:833-839` 的小函数每次先 `K++`；`v[1] > 0`、`G < 5`、新 K 达到 `d()` 才置 L=true。
`d()`（825–827）按等级 1–5 从第 23/24 列插值。字段 K/G/L 属于定义并随定义读写
（785–816），不同实例使用同一定义累计；K 不是 Tenant 月销售或 Character.K。

不满足门槛时直接返回，不会把已有 L 清 false；满级也继续 K++。因此派生的 upgrade_ready 只能描述
当前门槛，不能替代持久保存的提示位。现有 [经营函数](example/include/dungeon_village_reference/facility_economy.hpp)
提供阈值/当前门槛，新候选另外保留提示的锁存语义。

主场景点击设施看到 L 时打开 UI 81（`b/c.java:1605-1612`）。UI 初始化调用
`a.o.a(definition,tenant)`（`b/g.java:3840-3841`）；该较小函数 `a/o.java:272-290` 先记录属性，
K 减**旧等级**阈值，再至多 G+1，重算并准备显示差值。关闭展示才清 L（`b/g.java:5713`）。
升级不是每次完成自动升一级，也不是把使用累计归零；本阶段不实现 UI 提交或关闭协议。

## 普通商店满足度小函数

`a/e.java:270-276`：读取角色记录 C、当前职业 `h.m[0..1]`、实例品质 `definition.a(1,tenant)`，
计算 `threshold = m[0] + C*(m[1]-m[0])/100`，再加 `随机helper(10)-5`。
只有调整后门槛**严格大于**品质时结果 0，否则 1；等号成功。随机偏移为 -5..4，不是 -5..5。

`c/d.java:118-131` 是整数插值，向零截断；随机 helper 75–76 使用绝对值/取模，有偏差。
`a/e.java:485-487` 将 C 加结果后限制到 0–100；角色页面 `b/g.java:4288-4298` 把 C 标作“满足”。
职业端点读取来自 `a/h.java:66-68` 的第 13/14 列，但本批没有发布职业表，不猜默认端点。

最后无论结果为 0/1 都调用 `UserData.a(result,false,0)`：满足度已封顶时成功仍请求人气 +1；
失败也有零增量请求。false 是提示标志，不表示禁止增加人气。原因 0 的逻辑计数为 10，
[既有人气核对](FACILITY_EVENTS.md#人气队列低层核对)显示耗尽才应用；不换算秒数或假装已入账。
实际应用即使增量零仍继续检查阈值事件，所以零请求不能擅自等同于“可以省略整个原作调用”。

## 独立 C++ 交付与未知

维护 [接口](example/include/dungeon_village_reference/facility_exit.hpp)、
[实现](example/src/facility_exit.cpp)与 [测试](example/tests/facility_exit_test.cpp)。
两个纯函数分别准备定义累计和满足度投影，返回原身份；调用方必须先验证目标、分类分支并避免
重复退出。它们不自动释放实例占用、排队活动、提交跨所有者事务或执行完整效果。

端点/品质采用 signed int32，宽整数计算避免 Java 回绕，不猜负品质应裁零；原件中的数值并未因此改动。
满足度输入范围 0–100、等级范围和计数保护是维护安全契约，非法值返回无候选。
票号由外部提供，不恢复 RNG 状态、完全相同随机序列或跨功能随机消费顺序。

后续 [生命值协议](CHARACTER_HP.md)核对旅店使用中恢复与住所退出直接赋值的小型消费者；
不把该协议当完整旅店/住所状态机。仍需研究：完整恢复调度、装备/经验 opcode、职业原表与所有品质来源、升级 UI/提示关闭
重入及存取、实际人气应用全部副作用、退出位置选择和完整时钟调度。本阶段不改 R2 原型完成策略。

当前独立切片通过 124,230 项检查，示例三套 17/17、原型三套无窗口回归 23/23；
格式/链接与当前工具链证据见 [验证记录](VERIFICATION.md)。
