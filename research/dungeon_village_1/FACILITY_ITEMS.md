## 适配与共享状态

设施第 34 列 `F` 在 `a/o.java:233` 以 `item.f34e` 索引，不是以道具 ID 索引。
85 条原始设施定义的列表全部为 12 项，值只出现 0/1/2。原表旅店全部为 0；
咖啡厅类别 5 为 2、类别 8/9/10 为 1，其他为 0。0 不表示禁止使用或零效果。

`a/o.java:231-270` 小型设施改良函数直接执行：

1. 保存当前实例三个实际属性，查询适配值。
2. 适配 2 对道具 `k[0..2]` 加倍；适配 1 减半，经 float 再 int 向零截断；其他保持原值。
3. 临时推导增加后的共享改良，得到当前实例前后差值；差值全零把显示响应置为 -1。
4. **仍然**将三项增量写回定义共享 `J` 并重算定义，不因显示响应 -1 撤回道具或改良。

维护费槽 3 没有道具增量；等级/改良/普通消费累计属于定义，不属于当前选中的单一实例。
邻接修正属于实例，前后差值必须经过已有 [经营顺序](FACILITIES.md#独立经营数值规则)，
不能直接用道具三项值当作最终显示增量。价格倍率和封顶可能使显示差值不同。

## UI 调用与消费次序

状态 75 初始化（`b/g.java:3760-3772`）只列 `z > 0` 的道具；确认分支 5574–5591 调用
`UserData.c(item,vector)`，后者（`c/n.java:1718-1725`）调用 `item.d()`，库存减一但不低于零，
耗尽从临时列表移除。`a/g.java:181-189` 的获得方法封顶 999，消费方法下限 0。

确认分支随后将状态 76 加入 UI 栈、递增当前实例事件计数并测试门槛；状态 76 初始化
（`b/g.java:3773-3774`）才调用设施改良函数。UI 栈 `kairo/android/a/a.java:25-31`、
`kairo/android/a/b.java:105-132,246-272` 把新状态标为待初始化，再在调度循环调用初始化。
因此不能声称原作在一个小函数里原子完成库存/共享改良/事件，也不能认定“属性变化成功才计数”。
巨型 UI 初始化和确认方法带 JADX 警告，精确中断/重复初始化仍待 DEX/运行核验。

## 独立 C++ 交付边界

只从同一输入计算完整候选：剩余库存、共享改良数组、当前实例计数/脚本触发意图、实际前后属性、
三项显示差值与显示响应。失败无候选，不碰调用方状态；整体提交是 Ark 自有安全契约。
调用方管理稳定实例身份、查找定义和防止重复命令；纯函数不是幂等库存命令，不引入隐藏全局状态。

接口见 [候选事务](example/include/dungeon_village_reference/facility_items.hpp)、
[实现](example/src/facility_items.cpp) 和 [测试](example/tests/facility_items_test.cpp)。输出只交付定义
改良数组，不把含实例邻接修正的整个经营输入写回共享状态。before/after 只针对当前实例，其他同类
实例需用新的共享改良和各自邻接重新推导。测试库存/年龄为隔离夹具，不声称是原作初始库存。

固定原始道具数值较小，整数半倍/双倍与原作 float 路径一致；自有巨大或负参数用于安全边界测试，
不冒充原作道具。示例不重现 float 大整数精度损失、Java 回绕、原作短整数存档布局或 UI 动画。
没有恢复全部道具获取/购买/角色使用、`A` 库存、完整事件解释器和正常产品存档。
