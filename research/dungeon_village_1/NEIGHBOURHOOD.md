# 周边格、邻接属性与来源身份

更新：2026-10-02；切片设计见 [R2-E](stages/R2-neighbourhood.md)，证据根见 [证据清单](EVIDENCE.md)。
本报告区分可读的小型消费者、派生推导与 Ark 安全契约，不新增原作未证实的道路建设门槛。

## 直接证据

- `a/o.java:60` 的 `aj` 外环含 8/10/12 格，分别围住单格/双格/四格设施；包含对角格，
  不与四邻接寻路方向表混用。静态顺序与形状/朝向有关。
- `a/o.java:399-416` 先保存旧三属性到 `G`，清零每个实例的 `s` 与来源列表 `w`，再完整重算。
  重复调用不会天然把邻接增益翻倍；旧值仅供后面的变化提示比较。
- `a/o.java:419-448` 来源只为种类 3 或 2，目标必须是种类 3。对每个来源重置临时 `H`，
  目标首次命中后设 `H`，后续同来源不重复作用，即使多个外环格都属于同一个大设施。
- 设施第 26/27 列对应 `x/y` 平行列表；槽位 0/1/2 分别加到实例 `s[0/1/2]`，即价格/品质/魅力。
  来源列表记录定义 ID 与同定义实例序号 `f207c`，不是只记设施名称。
- `a/o.java:451-460` 只对商店遍历外环，每个显示状态为 3 的道路格令 `s[2] += 2`，没有目标去重需求，
  因为计数对象是道路格。对角道路也在这个外环内。
- `a/o.java:463-488` 比较新旧修正并发增减提示；这是表现事件，不是再次发放属性。
- `a/o.java:757-758` 在读取槽 0–2 时加实例修正再封顶，维护费槽 3 不加这些值；与
  [经营推导](FACILITIES.md#独立经营数值规则) 接续，不在邻接计算阶段封顶。

## 固定原始数据的例子

数值来自 [原始设施表](data/original/tenantData.txt)，不是自行调参：

| 定义 | 种类 | 修正槽位 / 值 | 该邻接消费者中的作用 |
| --- | --- | --- | --- |
| 28 旅店、29 双格旅店 | 3 | `2` / `10` | 每个相邻商店魅力 +10，一目标仅一次 |
| 36 咖啡厅 | 3 | `2` / `10` | 每个相邻商店魅力 +10 |
| 66 向日葵 | 2 | `0&1` / `20&5` | 每个相邻商店价格 +20、品质 +5 |
| 74 木灵大树 | 2 | `0&1` / `70&20` | 每个相邻商店价格 +70、品质 +20 |
| 25–27 住宅 | 12 | `2` / `10` | 这条消费者不把它作为来源，也不把它作为商店目标 |

字段有值不意味着所有种类都会执行。来源可同定义多实例叠加；对单个来源按目标实例去重，不能改为
按定义去重，也不能按目标占用格重复增加。同一来源没有效果项时，生成实现仍追加来源记录。

## 外环与朝向

外环是占地外一格的矩形边界，包含八邻域角落，不包含设施占用格。裁剪到地图内不报“设施越界”；
只有占用格越界才拒绝布局。周边顺序用静态表核对：

- 单格两朝向：从 `(0,1)` 开始，经右下角向上、左侧、左下角闭合。
- 双格朝向 0：从 `(0,2)` 开始；朝向 1：从 `(1,0)` 开始，先走右上角再走顶部/左侧/底部。
- 四格两朝向：从 `(1,0)` 开始，外环相同；占用格的绑定次序/分片仍不同。

外环只用于邻接修正/来源显示，人物终点仍是 [实际占用格](MAP_ACCESS.md#占用格就是设施活动候选格)。
这项修正会因建设、移动、旋转或撤除改变，但不修改金币、村子点数、任务计数或定义共享升级次数。

## 独立实现边界

本批仅维护计算后的三属性数组、来源身份和道路计数；用稳定实例 ID 替代原作“定义 ID + 同类序号”的
显示记录，不复刻其分配/复用细节。定义与实例相互校验、道路唯一、宽整数溢出拒绝属于 Ark 安全契约。
输入道路明确作为当前地图状态 3 格的快照，不据此恢复道路铺设工具或城镇边界。
完整邻接变化 UI、未知效果列表和城镇职业改良的全部来源仍不在本切片范围。

## 维护交付与消费

[几何接口](example/include/dungeon_village_reference/geometry.hpp) 中的 `facility_surroundings` 已实现
按表次序输出与裁边；[邻接接口](example/include/dungeon_village_reference/neighbourhood.hpp)、
[实现](example/src/neighbourhood.cpp)、[测试](example/tests/neighbourhood_test.cpp) 独立维护。
输出按实例输入次序排列，来源身份按来源实例输入次序登记；同一来源的修正列表可重复槽位，各项仍累加。
无效果来源记录是来源身份，不自动代表净属性增加。

消费者应先根据稳定 ID 找到目标实例，再使用 `neighbourhood_economy_input` 将完整新修正替换经营输入
槽 0–2；它不与旧修正重复相加，保留等级/定义改良/职业计数及槽 3。既有经营接口的实例修正为 32 位，
转换先检查范围，超限返回空输入，禁止强制窄化。然后由经营纯函数应用属性上限；邻接重算自身不封顶。

当前 6,280 项检查含完整六种外环序列、全部边界锚点、同类/多格去重、旋转/移除、正负/溢出和
200 组随机布局与独立 Chebyshev 集合差分。工具对固定原表验证 51 条非空邻接列表与并行长度/槽位，
没有改写原始数据或改变结构读取器对其他未知列的保留契约。
