## 索引怎么读

- `records`以`归档组/条目`作稳定键；保留来源hash、文件大小、PNG／SEB／INF类型、原索引槽和修饰参数。`code_candidates`记录代码位置与候选类型；同名字面量跨多个归档时保留歧义数量。
- `loader_bindings`将全局图片库字段追到原归档号及加载位置。九组包含common、common2、human、image、event、weapon、monster、effect与title；load另外按启动类局部字段定位。
- `seb_structures`逐层逐记录保存帧、图片槽、源矩形、偏移和两个原参数。负图片槽是绘图命令，不套PNG规则。默认图片边另反向进入PNG的`default_seb_users`，不把默认槽覆盖为最终运行时图片。
- `dynamic_slot_sites`和`unresolved_default_image_slots`保留未闭合项。没有数组越界异常兜底，也没有为凑“全覆盖”造消费者。普通Java加载与引用保持对应证据等级，精确DEX／机器码／窗口应另附验证。

本轮词法扫描剔除注释和字符串对代码模式的干扰；资源字符串只匹配精确文件名。固定槽匹配已登记的全局库，d/a自身字段，以及标题／启动类局部库。它不是完整Java数据流分析，不跟踪所有局部别名、泛型绘制helper或运行时文件名拼接。

无默认图片槽的资源中，cursor_arrow／fence／heart／rank_grade等也未列入当前seb.inf；develWeapon01却在common槽45。两类必须分别追查，不能一概当作“未使用”。人物／怪物／装备图通常通过共享SEB和调用者替换图像，后续应沿具体调用一路核到定义表、动作和帧号。

## 产品消费前逐项闭合

每个实际使用的图像、图集区域及SEB动作至少补齐：

1. **来源与身份**：版本、容器、条目或Unity对象、原hash、尺寸、语言、字节相同别名；运行时生成的画面另列。
2. **绑定**：PNG／Texture、Sprite／SEB／INF、定义ID、图片替换、翻转／调色／缩放；静态默认值与运行时选择分别登记。
3. **代码**：入口、状态／页面、条件分支、绘制顺序、裁剪／深度、帧与计数、位置／锚点、随机／声音／业务副作用。
4. **操作**：点击、按下／松开、拖动、滚动、键盘／控制器、取消、焦点、遮挡、锁定与页面退休；EXE专有行为单独证明。
5. **验收**：静态合同、必要的独立规则／像素检查、实际窗口与自然路线分别列结果；产品导入路径和消费状态由产品批次另登记。

发现文件、解析结构、定位代码、还原消费者、动态认证和产品接入是不同状态。当前已核专题继续复用[装备／设施提示](../ui/EQUIPMENT_FACILITY_RENDER.md)、[建设／绘制请求](../ui/INPUT_RENDER_REQUESTS.md)、[战斗](../ui/COMBAT_RENDER.md)和[探索](../ui/DUNGEON_RENDER.md)，不重复建立互相矛盾的规则正文。

Steam主菜单[完整逐行合同](../ui/PAGES.md#steam主菜单缓存输入与局部皮肤)进一步闭合menu SEB0/frame0–1、wnd_menuIcon SEB7按实际tag的图集格、NEW／GET、手形及common2/image0期间图的条件和原序；期间数字为SEB15／Steam image105，斜线为SEB76/frame5。底图／图标缩短源裁片，未将图集列数推成全部可选条目。原字体、完整raw3宿主与一次性光标仍另核；本增量不重生成早期APK候选索引或增加交付核对产物。

## 复算

在仓库根目录执行：

```powershell
node research/dungeon_village_1/tools/scripts/resource_code_index.mjs
node research/dungeon_village_1/tools/scripts/resource_code_index.mjs --check
```

[脚本](../tools/scripts/resource_code_index.mjs)只读固定APK、原素材／清单和本地生成Java；唯一写入是上述派生JSON。`--check`仅重算比较，不写文件。缺少输入、hash变化、清单／实际目录差异、INF目标缺失、坏SEB端点明确失败。索引不保存反编译代码片段或原程序，不操作游戏、存档、网络或产品文件。
