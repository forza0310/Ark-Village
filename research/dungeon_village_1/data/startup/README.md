# 新局数据交付

本包支撑 [新局、到访与建设报告](../../rules/STARTUP.md)，只交付固定汉化重签 APK 1.0.8 的
原始数据和有前置的静态推导，不是产品存档格式，也不是原版运行截图或动态世界捕获。

| 文件 | 内容与使用边界 |
| --- | --- |
| [MAP.json](MAP.json) | 24×24 原始格、两组区域、出生点、源哈希与未消费尾部；不是初始化后底图 |
| [TABLES.json](TABLES.json) | 六张完整源表，以及教程对话的三个指定记录；保留全部未知列与原始空列 |
| [STATE.json](STATE.json) | 无继承、未推进的新局资源/日期、源设施种子、初期目录、首位到访人物与镜头静态推导；未完成项单列 |
| [LOADED_MAP.tsv](LOADED_MAP.tsv) | 576格加载后逻辑/显示字段的静态重建，包含道路掩码、边界与原始/研究实例身份 |
| [LOADED_INSTANCES.tsv](LOADED_INSTANCES.tsv) | 加载后8实例的向量顺序、原始ID、研究非零ID、定义与位置；不是全部Tenant字段 |

## 原始字节与坐标

`TABLES.json.entries[].source_utf8` 是解码条目的完整 UTF-8 文本，而不是重新拼接后的 TSV。
源条目无末尾换行；按 UTF-8 编码该字符串应得到对应 `bytes` 与 `sha256`，不得自动补换行。
六表依次是地图显示、人物、职业、武器、事件、人气奖励；表中 ID 不一定等于顺序行号。
`talk.selected[].id` 是 `talk.txt` 经 `|` 分割后的下标，不是页面 ID；只发布选定记录，
完整条目哈希用于从本地 APK 复核，不能由选定记录重建完整对话文件。
设施定义复用 [原始设施表](../original/tenantData.txt)及其 [来源清单](../SOURCE.tsv)，不复制第二份。

`MAP.json.cells[y][x]` 每格为 `[h,i]`：显示记录 ID 与源变体值，不是设施 ID 与朝向。
源文件是大端有符号 16 位，宽、高、格子按 `y=23…0`、`x=0…23`排列。
随后读取区域组 `l`、区域组 `m` 和点列表；每组先读数量，区域读四值、点读两值。
列表 `raw` 是文件次序，`logical` 将两个端点或点的 y 分别变为 `23-y`；不改变端点顺序。
`logical=[6,10,17,2]` 因而不是 `[min_x,min_y,max_x,max_y]`。
已解释字段共2354字节，原条目2356字节；`unread_tail_hex="0000"`原样保留，不给这两个字节命名。
按源顺序重编码字段并附尾部应还原完整条目哈希。越界、截断、数量和总长度必须严格核对。

## 静态快照边界

`STATE.json.map_seed_instances` 按源扫描顺序列出8个实例种子，包含入口。
它仍是源种子，不当作最终对象表；加载后的入口删除/重建、地表重算和实例ID见单独TSV。
初期目录报价与施工阈值基于3个已解锁定义，其中农家2名、木匠1名；不是运行中3个人物。
实际人物向量在新局重置后为空，首位到访才增加为1。
武器、属性和初期解锁来源是本包源表；旧研究原型的夜骑士、7×7地图、资金和毫秒tick均不适用。
`first_arrival.legacy_D=[0,0,0,0]`与`legacy_m=0`来自无继承重置链，
不是运行中住宅/离村字段的通用默认；之后的入住与月度修改必须读取当前共享定义。
`boundary.character_spawn_minimum_y`及`world_overlap_boundary_y`都为2：
`h.l[0][1][1]`读取Y翻转后的较小边界，与另一个端点10分开。

数据交付没有扩展 [C++工具契约](../../tools/README.md)或新增维护地图解析器。
数据是既有归档库只读解码后的证据交付；可重复校验记录见 [当前验证](../../VERIFICATION.md)。
后续[原型数据编译](../../prototype/scripts/README.md)在构建期读取本包，用标准JSON解析生成只读C++。
源格、源种子与加载后静态推导分别接入，运行不读取本目录，不把独立重建认证为原版动态快照。

## 加载后快照

前置：固定APK、边界等级0、无继承、未推进、无玩家布局改动。证据顺序和数字身份详见
[新局报告](../../rules/STARTUP.md#加载后逻辑显示快照)。两个文件由
[独立C++导出器](../../prototype/src/dump_startup_map.cpp)生成，不手工填写576格，不复制反编译代码。

`LOADED_MAP.tsv`按y0…23、x0…23行主序，首行为14列名；后三种身份/方向标记须区分：
无原始实例用-1；原始ID0为有效实例；研究ID0表示无实例，重置快照有实例时为原始ID+1。
`boundary_fragment=-1`表示无边界覆盖，`external_direction=-1`表示无外部入口覆盖。
道路拼块优化标志为0/1；逻辑状态、路径类别、显示ID、变体均是独立字段。
实例表按原向量顺序，不按ID排序；后续新建不复用这张映射作为稳定生命周期契约。

派生文件SHA-256（不是原版归档条目哈希）：

| 文件 | SHA-256 |
| --- | --- |
| LOADED_MAP.tsv | `1a3955e1a139931c2731c5598806f920d836b353fa5ba98914b89f2269eefea1` |
| LOADED_INSTANCES.tsv | `835062acdce1f3c8befd641b65fc71e69f0aa7f08cf395a3ca1ee612445a3c8d` |

构建原型后可用 `dungeon_village_dump_startup_map cells [输出TSV]`或`instances [输出TSV]`重算；
不指定路径则输出到标准输出。CTest逐字节对账两份发布文件并校验行/列、整数、坐标及身份映射。
这保证维护实现和发布快照一致，不替代APK运行观测或独立原版差分。
实例销售、使用者、共享定义进度、场景缓存与继承局不在该快照范围。重置后快照不是实时可变地图；
玩家后续建设/撤除需另按实例与地表变化派生，不可继续使用它判断动态路径或绑定。
