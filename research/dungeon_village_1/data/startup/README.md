# 新局数据交付

本包支撑 [新局、到访与建设报告](../../rules/STARTUP.md)，只交付固定汉化重签 APK 1.0.8 的
原始数据和有前置的静态推导，不是产品存档格式，也不是原版运行截图或最终世界快照。

| 文件 | 内容与使用边界 |
| --- | --- |
| [MAP.json](MAP.json) | 24×24 原始格、两组区域、出生点、源哈希与未消费尾部；不是初始化后底图 |
| [TABLES.json](TABLES.json) | 六张完整源表，以及教程对话的三个指定记录；保留全部未知列与原始空列 |
| [STATE.json](STATE.json) | 无继承、未推进的新局资源/日期、源设施种子、初期目录、首位到访人物与镜头静态推导；未完成项单列 |

## 原始字节与坐标

`TABLES.json.entries[].source_utf8` 是解码条目的完整 UTF-8 文本，而不是重新拼接后的 TSV。
源条目无末尾换行；按 UTF-8 编码该字符串应得到对应 `bytes` 与 `sha256`，不得自动补换行。
六表依次是地图显示、人物、职业、武器、事件、人气奖励；表中 ID 不一定等于顺序行号。
`talk.selected[].id` 是 `talk.txt` 经 `|` 分割后的下标，不是页面 ID；只发布选定记录，
完整条目哈希用于从本地 APK 复核，不能由选定记录重建完整对话文件。
设施定义复用 [原始设施表](../original/tenantData.txt)及其 [来源清单](../SOURCE.tsv)，不复制第二份。

`MAP.json.cells[y][x]` 每格为 `[h,i]`：显示记录 ID 与源变体值，不是设施 ID 与朝向。
源文件是大端有符号 16 位，宽、高、格子按 `y=23…0`、`x=0…23`排列。
随后读取区域组 `l`、区域组 `m` 和点列表；每组先读数量，区域读四值、点读两值。
列表 `raw` 是文件次序，`logical` 将两个端点或点的 y 分别变为 `23-y`；不改变端点顺序。
`logical=[6,10,17,2]` 因而不是 `[min_x,min_y,max_x,max_y]`。
已解释字段共2354字节，原条目2356字节；`unread_tail_hex="0000"`原样保留，不给这两个字节命名。
按源顺序重编码字段并附尾部应还原完整条目哈希。越界、截断、数量和总长度必须严格核对。

## 静态快照边界

`STATE.json.map_seed_instances` 按源扫描顺序列出8个实例种子，包含入口。
加载后的入口删除/重建、地表重算及实例ID尚未形成完整快照；不能把这8条直接当最终对象表。
初期目录报价与施工阈值基于3个已解锁定义，其中农家2名、木匠1名；不是运行中3个人物。
实际人物向量在新局重置后为空，首位到访才增加为1。
武器、属性和初期解锁来源是本包源表；旧研究原型的夜骑士、7×7地图、资金和毫秒tick均不适用。

数据交付没有扩展 [C++工具契约](../../tools/README.md)或新增维护地图解析器。
数据是既有归档库只读解码后的证据交付；可重复校验记录见 [当前验证](../../VERIFICATION.md)。
后续[原型数据编译](../../prototype/scripts/README.md)在构建期读取本包，用标准JSON解析生成只读C++。
源格、源种子与静态推导分别接入，运行不读取本目录，也不将它认证为初始化后快照。
