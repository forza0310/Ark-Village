# 新局数据编译

[compile_startup.mjs](compile_startup.mjs)只在构建期使用 Node 内置 JSON 解析与 SHA-256，
从[发布包](../../data/startup/README.md)生成构建目录中的 C++ 常量，不手工维护第二套576格数据。
校验地图尺寸、未解释尾部、显示绑定、八个种子、单格目录、首访与职业派生契约；错误阻止构建。
定义投影同时保留种类、活动类别、定义方向、flags、形状、默认定义魅力；使用原表第9列显示绑定，
不从显示表第一条同定义记录猜最终显示。加载后地图由标准C++独立派生，不由脚本填预期格值。
使用组合另保留原表细分类、第25列等待、四属性/升级端点，以及首名人物职业第13/14列满足度门槛；
这些是只读规则输入，不代表已经运行默认AI或完成实例邻接重算，建设有效报价与原始经营端点分开。
退出属性保留原表第28/29列的原顺序，严格验证等长与六属性下标；不把属性0猜为经验值。
首名装配时武器重选计数6来自[较小源码消费者](../../rules/FACILITY_USE.md#weapon-choice)，
不是原表库存或生成器默认演示值；仅这一已证赋值由生成器投影，其余装备/使用状态不补造。
编译输入回归另交叉校验自动脚本集合/四月资格、事件89程序、初期武器解锁/rank/价格与道路显示深度flags。
运行时仅标准 C++17，不需要 Node、APK 或反编译目录。生成文件不能手改。

## 完整共同世界目录

当前投影完整保留普通设施分类`tenantData[8]`与晋级提醒字段`[32]`；
人物入住费用`character[8]`、住宅完成程序`[9]`、入住请求程序`[10]`分别存储，不能互相覆盖。
这些字段由固定原表与构造器交叉认证，新增消费者不修改原表/来源哈希。

[compile_startup_world.mjs](compile_startup_world.mjs)将[完整原表目录](../../data/world/README.md)
和[固定事件目录](../../data/scripts/README.md)生成另一个只读C++目标，不扩充旧首访切片的运行事实。
包括25人物、23职业、113装备、36怪物、36物品、81任务、85设施及全部活动定义。
脚本在构建期验证原始文件SHA-256、ID/字段/程序/命名空间，错误阻止生成；不根据测试缺口修改原表。
设施原A长于z的未消费尾部保留在独立字段，不把尾部冒充属性或删除。
任务第10列保留原序怪物列表，第12列用于基础遭遇配额、第14列用于待完成累计值，不能互换。
[输入回归](../tests/startup_world_data_test.mjs)覆盖全目录及错误输入，
[export_world_tables.cpp](export_world_tables.cpp)是发布表提取工具，不参与原型运行。

显示记录同时保留原第5列深度偏移和第7列flags；深度偏移不是SEB图片偏移，
不能以道路或建筑图片尺寸推导。两套生成数据都由CMake显式依赖对应源文件。
