## 当前共同世界合同：住宅税收与页面90／98

### 准备税额，不立即收钱

`b/c.java:272-298`与低层[MainScene](../work/construction-render-fallback/MainScene.java:777)的
`L2da→L355`交叉核对：跨月后的**原月份字段为3且原年份字段大于0**才运行住宅税收准备。
这里保留0起始原字段，不把3误写成第三个月，也不从显示“第几年”推断条件。

遍历完整人物定义`bv`源序，资格为`p != 0 && D[2] == 1`，而不是当前场上人物列表`bl`：

- 将符合资格人物的`G`重算为`F * rate / 100`；当前职业`a.h.i == 7`取60，否则30。
- 除法沿Java有符号向零截断，再执行`G -= G % 10`；不是浮点四舍五入，也不另加最低税额。
- `F`来自击倒奖励累计（`c/b.java:1300`），不是设施消费、职业薪资、年度贡献`am`或所持资金。
  共同Owner唯一事实位是`battle.humans[].battle_reward_stat`；日历辅助`legacy_F`只是旧投影镜像。
- 有至少一名合格居民就排出**事件122→raw90→事件123**，包括各人税额均为0的情况。
  没居民不创建这条税收页面链。不在这一阶段入金币，也不清`F`。

原[事件表](../data/scripts/original/events.txt:123)中122是`2,99`；123是`2,100&37,0`。
因此完整链还有**raw98自动结算页**，不是确认90就完成收税。事件123替换文本采用准备时合计；
该文本不是98的现金提交参数。

`c/n.java:103-104` 给出五个类别标签：设施、怪物、冒险者、商店、其它；月报汇总类别集合仅 `{0,1,2}`。
因此“月报合计”不是全部金币变化。建设支出同样走类别 0（`b/c.java:1723-1737`），不能把设施类别
的所有支出都解释成维护费。金币增加/扣除函数可接受有符号 Java 整数，本示例改为显式方向与非负金额。

点数名称还由 `b/g.java:131` 的资源类型标签与 `8621-8623` 的“获得街道点数”显示佐证；
同一资源类型 1 的确认动作调用 `UserData.b(int)`，金币类型 0 则调用 `d.a.f(int,int)`
（`b/g.java:6094-6097`）；月报奖励也只调用前者。使用汉化包的“村子/街道”两种显示名称
不意味着存在两种点数。巨型 `b/g` / `c/b` 方法有警告，这里只作语义佐证，不凭它们恢复精确分支。

## 时钟和报表的关系

`b/c.java:150-193` 的独立日历函数每次调用将 `UserData.t` 加一，再把日历累计量归一化：
每个子周期 10800 单位，四个子周期一个月，十二个月一年。它不是每次简单“增加一天”。
初始 `Q=80`、`R=43200/(Q*20)=27`，见 `d/a.java:133-134`；报表准备条件为
`t == Q*20 - 140 - 3`，见 `c/n.java:3808-3810`。在这些初始参数下是月内 tick 1457，早于 1600 tick
对应的月界。此处的 tick 是控制器调用计数，不宣称是固定墙钟毫秒。

`b/c.java:1554-1572` 所在主循环有重建警告：可看出 `UserData.e()` 与日历推进的调用关系，
但不据此保证每种菜单/暂停状态的完整顺序。日历函数跨月后的明确操作包括重置 `t` 与讨伐月计数、
推进居民/设施计数、季度检查、最后清除 `N` 展示列表（`b/c.java:195-317`、`c/n.java:2412-2415`）。

### 月报局部路径（仍为带警告控制流推断）

`UserData.e()` 带大量重复块/移除指令警告。以下是可由独立资金、统计和状态切换函数佐证的局部流程，
不是完成字节码逐分支认证的全状态机：

1. `r==0` 且准备 tick 命中：进入状态 1，清快照。汇总怪物定义 `u` 次数；`K[1] = Σ(l*u)`。
2. 遍历当前活动人物列表 `bl`，累计职业费用并按类别 2 扣款；随后遍历设施实例列表 `g`，
   每个读取定义属性槽 3，写实例费用统计，再按类别 0 扣合计。此处生成代码没有显示设施可用性过滤，
   不将“所有设施必收费”提升为跨版本事实。
3. 从当前月统计的类别 0、1、2 构造 `K[2]` 收入、`K[3]` 支出、`K[4]` 差额；更新最高记录。
4. `1 → 2 → 0`；切换函数同时重置动画计数（`c/n.java:2220-2222`）。状态 1、2 各 70 计数，
   跳过输入可能提前结束（`3871-3889`）。离开状态 2 时把正 `K[1]` 加到村子点数。
5. 另有状态 3 关闭也发 `K[1]`（`3891-3900`），其全部入口尚未恢复，不能删除这个未知分支。

展示函数只读取快照并绘制“收入/经费/合计”，见 `c/n.java:3502-3530`；没有把报表净额再入账。
怪物的即时金币奖励与 `l*u` 点数累计不是同一笔交易，不能从二者之一推断另一者数值。
上述报表准备以后，更新方法还会继续调用人物/设施更新；未恢复月界附近全部活动的快照归属，
不能断言报表包含整月所有最后时刻交易。

## 独立 C++ 示例设计与契约

自主授权见 [R2-C 阶段记录](../stages/history/R2-world-facilities.md#data)。方案 A：独立周期账本与报表快照，
保留双资源和事件幂等性；方案 B：月末再加报表净额会重复即时金币，不采用；方案 C：照搬动画状态
作为业务提交点不能脱离 UI 测试，也超出精确证据，不采用。

本批实现范围：

- 带稳定事件 ID 的即时金币流水，五个分类、显式收入/支出；同 ID 同载荷重试成功，不同载荷冲突。
- 准备报表时一次性写入设施/人物费用批次、生成前三分类快照和累计讨伐点数；任何非法输入、ID 冲突
  或整数溢出整批回滚，允许负金币余额，不添加原作没有证实的“无钱拒收维护费”。
- 领取报表只修改村子点数、上限 999；重复领取不修改余额或点数，报表不重复支付金币。
- 周期已封账后拒绝新流水；完全相同的旧流水重试仍成功。报表费用/讨伐输入的顺序是载荷一部分，
  换顺序的重试视为冲突。这是 Ark 的冻结契约，不是原作在动画期间停止交易的证据。
- 内存账本不连接现有 R1 状态，不接入原型，不实现序列化/恢复；周期号由调用者提供且必须大于零，
  不假装已经恢复原作日历或月界的完整规则。

验收包含即时交易与报表差额不等于余额变化、双币种、五类汇总范围、费用去重/冲突/失败回滚、
报表重复准备/领取、封账边界、点数封顶、负余额和有符号整数上下界；Debug/Release 与 sanitizer 回归。

### 当前实现与使用

[接口](../example/include/dungeon_village_reference/accounting.hpp)、[实现](../example/src/accounting.cpp)、
[测试](../example/tests/accounting_test.cpp) 已独立维护。除初始点数超过 999 的构造拒绝抛出异常外，
业务拒绝均返回 `AccountingError`，可读状态通过只读访问器查看。事件 ID 与示例定义 ID 必须非零；
不直接把原始表下标当作这里的稳定 ID。报告不存在时领取返回明确错误；不补造报告。

以下金额、时间号、点数都是接口夹具，不是原作平衡表：

```cpp
using namespace dungeon_village_reference;
PeriodAccounting ledger(1000, 10);
ledger.post_cash({1, 1, CashCategory::facilities, CashDirection::income, 300});
ledger.prepare_report({1,
                       {{2, 1, CashCategory::facilities, CashDirection::expense, 240}},
                       {{1, 2, 5}}});
// 此时金币 1060，点数 10；报表差额 60 不再入账。
ledger.claim_report(1);
// 此时金币仍为 1060，点数 20；重复领取不会再加。
```

接入层必须检查每个返回结果；示意代码省略错误处理，完整拒绝与回滚用例见测试。当前 8,898 项检查包含
100 组固定种子分类账差分，每组 40 个事件及重试。没有修改 R1 全局状态、资金夹具或原型消费接口。
