# 人物自主行动与加权寻路

更新：2026-10-03。输入身份、反编译参数与行号规则见 [证据清单](../EVIDENCE.md)。
本报告描述固定一代 APK；不将反编译器重建的可疑分支视为完整原作规范。

## 玩家与人物的控制边界

已定位的日常移动链由全局更新和人物状态驱动，不需要玩家点击某个设施发出移动命令。
因此学习原型的正常玩法应是玩家管理建设、人物自行选择活动。现有原型的 `Visit` 工具只是
预约/到达/完成的测试入口，不是恢复出的原作操作。此结论不排除任务派遣、装备或其他管理操作
对人物行为的间接影响；本轮没有穷举原作所有菜单。

### 普通设施分支的前置

`o(0)`先建立可达候选，再处理任务、救援和物体等优先级，最后才进入类别helper。
低层 `Character.java:9379`，`La1→L11b→L190→L1c0→L2c5`确认：

- 定义flags2参与任务特例。首名flags9不含2，但不能把这一结论推广到所有人物。
- 救援helper检查bl中状态2人物；仅有健康首名人物时不会产生救援候选。
- 物体helper从bp选状态3。新局重置时bp为空，不证明到第420次更新仍为空。
- 活动6另有野外事件优先级；活动0不会因此自动使用同一分支。

**条件推导**：更高优先级不抢占，且初始三个商店都可达/可用时，首名六项访问计数均0、实例标志8192，
第一级只考虑类别1权重40、类别2权重30，不加入类别3回退或类别4。
武器店30与包子铺33是类别1，定义魅力分别5和4；旅店28是类别2、魅力5；向日葵66类别0。
类别1内部按出现项魅力抽样，多格/重复项不得擅自去重。
上述40:30及5:4是票号区间，不是已认证的首次实际访问概率；APK随机helper有偏差，
全局随机消费顺序及首段地图候选尚未闭合。

### 路径、朝向和失败的独立交付

[设施出发接口](../example/include/dungeon_village_reference/facility_departure.hpp)、
[实现](../example/src/facility_departure.cpp)、[组合测试](../example/tests/facility_departure_test.cpp)
复用已有类别/快照/地图规则，不实现巨型解释器。调用方必须先证明已进入普通设施分支；
接口不接受“忽略更高优先级”的开关，也不自动替未知优先级作决定。

类别计数由同一快照产生；两级票号注入，无RNG副作用。保留重复权重及抽中项/最终首格的区别，
再回溯路径并校验目标绑定及已存在的有限成本。成功才返回完整候选，不移动、不预约、不收费、不进入使用态。
方向按格坐标：y增加0、x增加1、y减少2、x减少3；不依赖raylib/屏幕投影。
沿用维护寻路器的同成本稳定排序，不认证原作路径平局。起终点相同返回空路径并保留原方向，
不能以此认为原版已到达/消费。事件项无成本不等于必然不可达，仍需实查该距离场。
类别3/4及-1由各自策略处理，当前明确返回不支持；不可达不静默重抽目标。

失败时原解释器移除旧活动，再清同行/任务引用、高度与当前设施使用关系，清控制队列；
清标志97、置514。类型0设状态19，若带1024再排等待120，然后排活动5。
`v()`可在清理后继续解释新队列，不保证一定拖到下一tick重试。
512/1024/32768的退出分支、活动5区域回退和真实位置运动尚未作为一整套生命周期接入。
维护出发函数只报告失败，不自动执行这段清理，也不把技术输入错误当作原作无目标。

## 寻路图与成本

较小的生成寻路器 `work/decompiled/sources/c/l.java` 没有大型重复代码块警告。
其 `a(int)` 使用最小累计成本扫描和松弛，属于 Dijkstra 形态，而非等权 BFS。

| 项目 | 直接证据 | 已确认规则 |
| --- | --- | --- |
| 邻接 | `c/d.java:16` | 方向顺序 `(0,1),(1,0),(0,-1),(-1,0)` |
| 下一个节点 | `c/l.java:38-59` | 选择未访问且累计成本最小的格，超过搜索上限停止 |
| 出边准入 | `c/i.java:6`、`c/l.java:67` | 有向路径类别矩阵；不是“所有空格都能走” |
| 特例 | `c/l.java:34,67,76` | 仅第一次展开允许到状态 3/4 格，不能当作全程穿墙权限 |
| 成本 | `c/l.java:68-71` | 取决于离开的格；类别 2 水平 50、垂直 70，其他类别水平 5、垂直 7 |
| 初始化 | `c/l.java:103-117` | 清空访问、成本和前驱；无设施的类别 0/3 格不加入展开集合 |
| 候选与排序 | `c/l.java:120-191` | 活动参数改变终点过滤；一般候选按累计成本升序排列，额外事件候选另行添加 |
| 路径回溯 | `c/l.java:84-100` | 沿前驱反向收集坐标，到达起点才成功 |
| 道路/空地映射 | `c/i.java:56-67,104-110,121-133` | 道路定义种类 6 对应类别 1；清空/普通地表对应类别 2 |

准入矩阵中的类别 1/2/4 可进入 0/1/2/4，不可进入 3；类别 0/3 没有普通出边。
类别 0 可以作为设施终点，且有设施的格仍可能加入展开集合，不能简单概括成“0 永远不可进入”。
首步特例也意味着设施内起点与普通阻塞格不是同一种处理。

道路路径成本约为空地的十分之一，但这些整数是目标评估成本，不是人物移动速度或金币。
占地、朝向、`Tenant.z` 与准入已在后续 [地图访问报告](MAP_ACCESS.md)补齐独立切片；原始地图、
完整活动资格和建设菜单限制仍未知。旧单点示例没有因此自动成为多格实现或产品几何规范。

## 到达、收费与效果不是一个事件

`P()` 在抵达后调用 `a(Tenant,definition)`（`c/b.java:596-605`）。较小的到达方法
`c/b.java:1024-1062` 会增加分类访问计数，计算 `definition.a(0,tenant)`，按条件更新资金显示、
角色统计及设施统计。使用退出操作码 24 则另行处理占用清理、恢复、装备/效果序列和新活动。

因此不能把原作所有资金/效果都描述为“完成使用后统一结算”。R1 示例的完成时一次效果与独占预约
是 Ark 的明确契约，并非逐事件还原；原作是否出发前预约、容量是否始终为一仍未知。

后续 [普通到达切片](FACILITY_USE.md#arrival)核对分类分支优先级与收费守卫：免费/受标志阻止收费仍更新
访问，角色 B[2] 是统计而不是钱包；只交付无同行/附加道具/装备抽选的纯候选，不改变旧模拟契约。

## 本轮结论与后续

本轮确认自主调度和加权路径结构，不声称还原完整决策树。C++ 切片设计见
[R2-B 自主行动设计](../stages/history/R2-characters.md#autonomy)。该切片保持“证实的路径成本”和
“明确标记的演示决策策略”分开，正常模式取消玩家手动指挥，自动演示入口保留为测试工具。

已维护的 [路径接口](../example/include/dungeon_village_reference/navigation.hpp)、
[实现](../example/src/navigation.cpp) 和 [测试](../example/tests/navigation_test.cpp) 是独立 C++17 示例。
采用最小堆，不复制原作向量扫描实现；同成本按格索引稳定排序，这是示例约定，不是原作平局结论。
最多一百万格属于示例内存保护；搜索成本/展开预算可传入，预算不足与确定不可达分开报告。
`cost_limit` 表示有出边被预算裁掉，不能进一步推断目标在无限预算下必然可达。
终点步包含在返回路径中、起点不包含；起终点相同成功且路径为空，调用方不能只以空路径判断失败。
仅保留道路/空地类的首步退出，未复制未知设施格状态或地图事件的全部特殊处理。

## 早期自主 C++ 交付与差异（旧接口保留）

[模拟接口](../example/include/dungeon_village_reference/simulation.hpp)、[实现](../example/src/simulation.cpp)
和 [测试](../example/tests/simulation_test.cpp) 按固定整数毫秒和 tick 推进，同一输入的分段不会改变结果。
人物按稳定实例 ID 轮换选择可达、未预约设施；原作两级带权随机策略尚未替代该夹具。

模拟器对世界/路径做候选状态事务，整批时间输入失败时保留两者原状。目标移动、旋转、删除、
路径被新建筑阻断或身份/预约失效时取消并延迟重选，不在每帧重复搜索。完成效果继续遵守 R1 一次
活动 ID 契约；到达阶段不自行加入未恢复的原作收费。独占预约是 Ark 契约，人物之间暂不做碰撞避让。

R2-B 当时移除了可视原型的手动 `Visit`，新增暂停图标；渲染从模拟位置和路径进度插值，不能写人物规则。
每格最多一百万格、单次最多 60 秒、配置计数最多一百万 tick 是资源保护，不是原作时长。
大 delta 越过多个动作仍有确定性，但可视演示使用有界固定步长以观察每个阶段。

早期核心测试通过但图形会话阻塞。该历史证据不替代下面收敛版的当前验收。
