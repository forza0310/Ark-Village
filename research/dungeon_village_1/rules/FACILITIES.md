<a id="definitions-独立经营数值规则"></a>

#### 独立经营数值规则

[经营接口](../example/include/dungeon_village_reference/facility_economy.hpp)、
[实现](../example/src/facility_economy.cpp) 和 [测试](../example/tests/facility_economy_test.cpp)
已将这些计算拆成标准 C++17 纯函数，不使用 Java 全局单例，也不改原型夹具。

推导顺序为：按等级插值端点 → 加定义改良 → 槽 0 按两组标志分别乘职业倍率/整数截断 →
槽 3 向零取十整 → 各槽按两倍第 5 级端点封顶 → 槽 0–2 加实例修正并再次封顶。
负改良不会被擅自裁成零；负维护费向零取十整也与简单向下取整不同。

第一组价格倍率只命中一个分支，优先级为 `4096→8192→512→2048→65536`，分别使用职业计数
`2/3/4/6/5`，每名增加 20%；第二组优先 `131072` 的计数 0，次为 `262144` 的计数 1，
每名增加 10%。两组依次相乘，各自执行整数截断，不能合成一次百分比。
例：基值 304 经 120% 再 110% 得 400，而一次按 132% 得 401。
职业计数来自 `a/h.java:80-96` 对 `eVar.p != 0` 的角色记录按职业分类聚合，十个分类的名称仍未完全恢复。
输入因此保留 `legacy_job_counts`，不命名为城镇等级或通用 buff 数量。

计数 8 的建设折扣仅作用于装饰，按 0–3 从基价插值到基价整除 4，再取十整；非装饰不受影响。
计数 9 的建造阈值按 0–3 从原阈值插值到原阈值整除 10；超过 3 不再继续缩短。
使用升级阈值从第 23/24 列按 1–5 级插值，第 5 级不升级，末端阈值不大于零也不触发升级。
等级、改良和升级累计次数属于设施定义；同类实例共享定义进度，不将它们误放进每个实例。

后续 [退出辅助规则](FACILITY_USE.md#exit)补齐累计的修改时点和升级提示：退出先加定义 K，满足门槛
只置 L=true；不自动升等级，不清除已有提示。实际升级由 UI 81 初始化调用另一小函数执行，
该函数 K 减旧等级阈值后至多升一级；不能以 upgrade_ready 的派生布尔值代替保存的提示位。

示例有意以宽整数和显式溢出拒绝保护计算，不重现 Java 32 位回绕。参数无效/中间乘积溢出时
没有部分结果；这是 Ark 的安全契约，不是原作错误处理。未知标志不擅自扩展语义。

锚点格 `(0,0)` 不是双格/四格矩形的左上角；朝向 1 的四格占地集合不变，但绑定次序和精灵分片索引不同。
绑定分片索引分别为单格 `{0}/{1}`、双格 `{0,2}/{1,3}`、四格 `{0,2,4,6}/{1,3,5,7}`。
周边辅助表 `aj` 与占地 `ai` 不同；已定位其邻接属性/道路魅力职责，见 [地图访问报告](MAP_ACCESS.md#周边表的正确职责)，不是道路入口表。

菜单选定义时设朝向 0（`b/g.java:11611-11612`），主场景旋转操作执行 `ab = 1 - ab`
（`b/c.java:1905-1906`）。配合仅两项查表，固定输入证据支持 0/1 两种朝向，不是四个任意角度。
主场景方法有 JADX 警告，因此控制入口/条件仍保留推断等级；两项静态表和实例绑定为直接事实。

渲染/使用锚点另由 `Tenant.f()` 从 `z[0]` 与形状/朝向计算（`c/m.java:865-893`）。
不能把规范化 PNG 锚点当占地锚点，不能让产品四向入口跟一帧图片直接对应。

## 周边格、邻接属性与来源身份

更新：2026-10-02；切片设计见 [R2-E](../stages/history/R2-world-facilities.md#neighbourhood)，证据根见 [证据清单](../EVIDENCE.md)。

<a id="neighbourhood-直接证据"></a>

### 直接证据

- `a/o.java:60` 的 `aj` 外环含 8/10/12 格，分别围住单格/双格/四格设施；包含对角格，
  不与四邻接寻路方向表混用。静态顺序与形状/朝向有关。
- `a/o.java:399-416` 先保存旧三属性到 `G`，清零每个实例的 `s` 与来源列表 `w`，再完整重算。
  重复调用不会天然把邻接增益翻倍；旧值仅供后面的变化提示比较。
- `a/o.java:419-448` 来源只为种类 3 或 2，目标必须是种类 3。对每个来源重置临时 `H`，
  目标首次命中后设 `H`，后续同来源不重复作用，即使多个外环格都属于同一个大设施。
- 设施第 26/27 列对应 `x/y` 平行列表；槽位 0/1/2 分别加到实例 `s[0/1/2]`，即价格/品质/魅力。
  来源列表记录定义 ID 与同定义实例序号 `f207c`，不是只记设施名称。
- `a/o.java:451-460` 只对商店遍历外环，每个显示状态为 3 的道路格令 `s[2] += 2`，没有目标去重需求，
  因为计数对象是道路格。对角道路也在这个外环内。
- `a/o.java:463-488` 比较新旧修正并发增减提示；这是表现事件，不是再次发放属性。
- `a/o.java:757-758` 在读取槽 0–2 时加实例修正再封顶，维护费槽 3 不加这些值；与

<a id="neighbourhood-外环与朝向"></a>

### 外环与朝向

外环是占地外一格的矩形边界，包含八邻域角落，不包含设施占用格。裁剪到地图内不报“设施越界”；
只有占用格越界才拒绝布局。周边顺序用静态表核对：

- 单格两朝向：从 `(0,1)` 开始，经右下角向上、左侧、左下角闭合。
- 双格朝向 0：从 `(0,2)` 开始；朝向 1：从 `(1,0)` 开始，先走右上角再走顶部/左侧/底部。
- 四格两朝向：从 `(1,0)` 开始，外环相同；占用格的绑定次序/分片仍不同。

外环只用于邻接修正/来源显示，人物终点仍是 [实际占用格](MAP_ACCESS.md#占用格就是设施活动候选格)。
这项修正会因建设、移动、旋转或撤除改变，但不修改金币、村子点数、任务计数或定义共享升级次数。

<a id="neighbourhood-独立实现边界"></a>

### 独立实现边界

本批仅维护计算后的三属性数组、来源身份和道路计数；用稳定实例 ID 替代原作“定义 ID + 同类序号”的
显示记录，不复刻其分配/复用细节。定义与实例相互校验、道路唯一、宽整数溢出拒绝属于 Ark 安全契约。
输入道路明确作为当前地图状态 3 格的快照，不据此恢复道路铺设工具或城镇边界。
完整邻接变化 UI、未知效果列表和城镇职业改良的全部来源仍不在本切片范围。

<a id="neighbourhood-维护交付与消费"></a>

### 维护交付与消费

[几何接口](../example/include/dungeon_village_reference/geometry.hpp) 中的 `facility_surroundings` 已实现
按表次序输出与裁边；[邻接接口](../example/include/dungeon_village_reference/neighbourhood.hpp)、
[实现](../example/src/neighbourhood.cpp)、[测试](../example/tests/neighbourhood_test.cpp) 独立维护。
输出按实例输入次序排列，来源身份按来源实例输入次序登记；同一来源的修正列表可重复槽位，各项仍累加。
无效果来源记录是来源身份，不自动代表净属性增加。

消费者应先根据稳定 ID 找到目标实例，再使用 `neighbourhood_economy_input` 将完整新修正替换经营输入
槽 0–2；它不与旧修正重复相加，保留等级/定义改良/职业计数及槽 3。既有经营接口的实例修正为 32 位，
转换先检查范围，超限返回空输入，禁止强制窄化。然后由经营纯函数应用属性上限；邻接重算自身不封顶。

当前 6,280 项检查含完整六种外环序列、全部边界锚点、同类/多格去重、旋转/移除、正负/溢出和
200 组随机布局与独立 Chebyshev 集合差分。工具对固定原表验证 51 条非空邻接列表与并行长度/槽位，
没有改写原始数据或改变结构读取器对其他未知列的保留契约。
