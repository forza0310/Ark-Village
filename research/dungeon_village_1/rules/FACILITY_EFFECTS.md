## 设施事件表达式与实例触发

更新：2026-10-02；阶段 [R2-F](../stages/history/R2-world-facilities.md#events)。固定输入见 [证据清单](../EVIDENCE.md)，

<a id="events-第-33-列的结构"></a>

### 第 33 列的结构

`a/o.java:138-143` 将第 33 列交给 `a/f.java:29-44`，保存为定义 `E`。解析器以 `&` 分指令，
`,` 分整数；helper `kairo/android/i/m.java:49-80` 对字段 trim 并保留空字段，再 Integer.parseInt。
空字符串得到空二维数组。它不是布尔公式，也不等于人物每次使用时的属性奖励。

固定 85 条定义中，只有 33–58 的 26 条非空，全部为 `6,100&40,<本定义ID>`。33–44 图标字段
为 2，45–58 为 3；图标不等于设施种类或人物职业。读取器保留原文和通用整数矩阵，不把未知 opcode
删去；结构验证与运行语义验证是不同验收。

<a id="events-门槛与所有权"></a>

### 门槛与所有权

| 事实 | 生成证据 | 等级 |
| --- | --- | --- |
| `Tenant.y` 是每实例两项数组，初始为零 | `c/m.java:49` | 直接字段事实 |
| 两项随实例读写存档 | `c/m.java:274-276,330-332` | 直接读写事实 |
| 移动快照/恢复复制两项 | `a/o.java:590-592,626-628` | 直接调用事实 |
| 月份分支每实例 `y[1] += 1` | `b/c.java:270-273` | 巨型方法局部推断 |
| 道具菜单确认消耗物品、进入改良 UI 后 `y[0] += 1` | `b/g.java:5574-5591` | 巨型方法局部推断 |
| 图标 2/3、`y[0] >= 5` 且 `y[1] >= 36` 才调用定义脚本并返回 true | `c/n.java:1671-1677` | 小函数直接事实 |
| true 后调用方清零两项 | `b/g.java:5586-5591` | 巨型方法局部推断 |

因此 `y[0]` 不能叫人物使用次数，`y[1]` 不能叫年数或永久建筑年龄：两项在触发后一起重置。
跨月入口没有调用这个门槛函数；已达道具次数但月份尚不足，月份到 36 后仍需再次走道具确认路径，
不能在月界自动展示或发人气。消费道具后是否真正提高属性不是此小函数的门槛条件。
这些实例计数不同于定义共享的改良 `J`、等级 `G` 和普通设施使用累计 `K`。

<a id="events-延迟与展示"></a>

### 延迟与展示

事件解释器 `d/a.java:633` 带 switch fallback 警告，本节只组合局部证据，不恢复整个 switch：

1. opcode 6（647–652）建立 `c.c` 延迟记录，保存脚本身份、下一指令下标和参数 100，加入 `aN`，
   停止当前解释；不会立刻执行下一条展示指令。
2. 设施脚本身份由 `d/a.java:440-456` 按定义表下标加 2000 定位，恢复由 4156–4167 取回 `E`。
   `c/c.java` 保留续执行下标、倒计数、上下文文本/参数，并有读写方法。
3. 主场景 `b/c.java:1540-1553` 局部递减延迟，耗尽后取回脚本并从保存下标续执行；方法带警告。
   100 的真实秒数、暂停和场景调度完整关系未恢复，不将其直接当 100 渲染帧。
4. opcode 40（`d/a.java:945-960`）读取参数指向的设施定义，仅图标 2/3 创建 UI 状态 82，
   展示模式分别 0/1。没有建设解锁或共享属性改良调用，不能命名为“解锁设施”。
5. 状态 82 初始化（`b/g.java:3842-3880`）按模式选已有角色中职业类别 1/0，至多三个，
   无候选回退到第一条角色记录。完整 UI 方法带警告，不据此建立完整职业选择策略。
6. 绘制小函数 `c/n.java:1548-1619` 直接显示“传说中的商店”“话题传了开来”与人气 +20。
   展示结束分支（`b/g.java:5719-5750`）调用 `UserData.a(20,true,6)` 后关闭。
   这是人气变化请求，不是金币、村子点数，也不是开始延迟时立即奖励。

`c/n.java:2469-2475` 的人气请求进入 `I` 队列；小型实际应用函数 738 开始改变 `f214d`、
下限 -50 并更新峰值 `f216f`。常规输出 3922 和其重复代码 4139 曾有倒计数条件疑点，
后续低层核对如下；这两处不再作为“倒计数未耗尽就应用”的依据。

<a id="events-人气队列低层核对"></a>

### 人气队列低层核对

同版 JADX 1.5.6 独立单类 fallback 输出为忽略目录 `work/user-data-fallback/UserData.java`：

```sh
jadx --config none --decompilation-mode fallback --no-res --threads-count 2 \
  --single-class c.n \
  --single-class-output research/dungeon_village_1/work/user-data-fallback/UserData.java \
  --output-dir research/dungeon_village_1/work/user-data-fallback \
  research/dungeon_village_1/maoxianmigongcun.apk
```

复现时改用新的工作目录，不覆盖原证据。下述行号仅对应此低层输出。

| 局部 | 低层锚点 | 核对结论 |
| --- | --- | --- |
| 请求入队 | `UserData.java:8645` 的 `a(int,boolean,int)` | 在 `I` 索引 0 插入 `[aG[reason], 增量, 提示标记]`；提示标记不控制是否更改人气 |
| 倒计数 | `UserData.java:13335` 的 `L513→L51c` | 从列表末尾向前，槽 0 每次减 1 |
| 条件与移除 | `UserData.java:13340` 的 `L51c→L53e` | `if (剩余 > 0) goto L53e` 跳过应用；耗尽 `<= 0` 才调用实际应用函数并移除 |
| 局部更新顺序 | `UserData.java:13364` 的 `L548` 之后 | 处理完现有队列再更新设施标志 `S`，随后分别遍历人物 `c()`、`d()` |
| 实际应用 | `UserData.java:2796` 的 `a(int,boolean)` | 写当前人气、下限 -50、更新峰值；另有提示合并和阈值事件，不只是一个数值赋值 |

常规 `c/n.java:105` 的 `aG` 为 `{10,25,10,85,10,10,10,10,10,20}`，展示结束请求 reason 6
对应逻辑计数 10。入队插在头部、倒序遍历，使同一次到期的已有请求按较早插入者先应用；不同计数的
请求可以后入先到期。这只是该遍历局部的结论，不承诺完整事件回调/重入顺序。

较小应用函数还按事件是否已触发检查人气 1000/3000/5000/10000/20000 门槛，说明不能用纯粹
`popularity += 20` 代表完整后果。当前未维护人气全局模块，不把它并入金币或村子点数账本。
仍未穷举 `e()` 的调用频率、外部暂停/菜单守卫和跨场景调度；10/100 都不换算成秒或渲染帧，
也不从该局部顺序推出所有设施事件一定早于所有人物效果。

<a id="events-独立-c-边界"></a>

### 独立 C++ 边界

本阶段拆分通用结构读取、实例计数纯函数与受限计划识别。计数候选和脚本触发意图不自动调用 UI、
扣库存、加人气或执行未知脚本。受限计划保留逻辑延迟和定义身份，示例不实现原作事件队列。
空脚本门槛仍可满足并重置，但计划结果为 no_script；不能凭“有触发”就发 +20。

维护接口为 [事件计数/计划](../example/include/dungeon_village_reference/facility_events.hpp)，
[实现](../example/src/facility_events.cpp) 和 [测试](../example/tests/facility_events_test.cpp)；
结构解析在 [工具读取器](../tools/include/dungeon_village_tools/table.hpp)。示例库不依赖工具库，外部读取后
由调用方转换整数矩阵，计划识别会再次验证完整结构和定义身份。计数仍非幂等命令：调用方必须避免
重复投递道具确认/跨月事实；本函数没有偷偷把相同参数视为重试。

不恢复完整解释器、全部参数替换、嵌套事件/UI 中断，也不新增产品存档。完整人物进入/退出效果仍由
[行为报告](STATE_CONSTRUCTION.md)与 [自主行动报告](CHARACTERS.md)分别维护。

## 道具表与设施共享改良

更新：2026-10-02；阶段 [R2-G](../stages/history/R2-world-facilities.md#items)。固定来源见 [证据清单](../EVIDENCE.md)。

<a id="items-来源与字段"></a>

### 来源与字段

启动器 `b/a.java:348-352` 从 `xls.dat` 读取 `item.txt`，每行构造 `a.g` 道具定义。
固定条目 3,327 字节、36 行、25 列，SHA-256 为
`95e29d253688e30ac623b925a9a5dacd1f6280f60ed0528b551707df1252d6b8`。
不把道具表和设施表、装备表混为同一种数据。

维护原件为 [item.txt](../data/items/original/item.txt)，来源为 [道具清单](../data/items/SOURCE.tsv)。
原设施数据与清单没有改写；道具单独发布和校验，不覆盖已有目录。

`a/g.java:48-94` 的读取顺序：第 0 列定义 ID，第 1 列名称，第 3 列 `f34e` 类别，
第 9–11 列 `k[0..2]` 为设施价格/品质/魅力改良，第 12–15 列 `l` 另有角色用途。
第 17/18 列 `s/t` 在新游戏初始化复制给当前库存 `z/A`（`a/g.java:144-151`）；
其中 `z` 由设施道具选择菜单使用，`A` 的完整路径未恢复，不统一命名成同一库存。
显示/图片/角色效果/购买字段未全部命名，保留完整原文。

<a id="items-适配与共享状态"></a>

### 适配与共享状态

设施第 34 列 `F` 在 `a/o.java:233` 以 `item.f34e` 索引，不是以道具 ID 索引。
85 条原始设施定义的列表全部为 12 项，值只出现 0/1/2。原表旅店全部为 0；
咖啡厅类别 5 为 2、类别 8/9/10 为 1，其他为 0。0 不表示禁止使用或零效果。

`a/o.java:231-270` 小型设施改良函数直接执行：

1. 保存当前实例三个实际属性，查询适配值。
2. 适配 2 对道具 `k[0..2]` 加倍；适配 1 减半，经 float 再 int 向零截断；其他保持原值。
3. 临时推导增加后的共享改良，得到当前实例前后差值；差值全零把显示响应置为 -1。
4. **仍然**将三项增量写回定义共享 `J` 并重算定义，不因显示响应 -1 撤回道具或改良。

维护费槽 3 没有道具增量；等级/改良/普通消费累计属于定义，不属于当前选中的单一实例。
邻接修正属于实例，前后差值必须经过已有 [经营顺序](FACILITIES.md#definitions-独立经营数值规则)，
不能直接用道具三项值当作最终显示增量。价格倍率和封顶可能使显示差值不同。

<a id="items-ui-调用与消费次序"></a>

### UI 调用与消费次序

状态 75 初始化（`b/g.java:3760-3772`）只列 `z > 0` 的道具；确认分支 5574–5591 调用
`UserData.c(item,vector)`，后者（`c/n.java:1718-1725`）调用 `item.d()`，库存减一但不低于零，
耗尽从临时列表移除。`a/g.java:181-189` 的获得方法封顶 999，消费方法下限 0。

确认分支随后将状态 76 加入 UI 栈、递增当前实例事件计数并测试门槛；状态 76 初始化
（`b/g.java:3773-3774`）才调用设施改良函数。UI 栈 `kairo/android/a/a.java:25-31`、
`kairo/android/a/b.java:105-132,246-272` 把新状态标为待初始化，再在调度循环调用初始化。
因此不能声称原作在一个小函数里原子完成库存/共享改良/事件，也不能认定“属性变化成功才计数”。
巨型 UI 初始化和确认方法带 JADX 警告，精确中断/重复初始化仍待 DEX/运行核验。

<a id="items-独立-c-交付边界"></a>

### 独立 C++ 交付边界

只从同一输入计算完整候选：剩余库存、共享改良数组、当前实例计数/脚本触发意图、实际前后属性、
三项显示差值与显示响应。失败无候选，不碰调用方状态；整体提交是 Ark 自有安全契约。
调用方管理稳定实例身份、查找定义和防止重复命令；纯函数不是幂等库存命令，不引入隐藏全局状态。

接口见 [候选事务](../example/include/dungeon_village_reference/facility_items.hpp)、
[实现](../example/src/facility_items.cpp) 和 [测试](../example/tests/facility_items_test.cpp)。输出只交付定义
改良数组，不把含实例邻接修正的整个经营输入写回共享状态。before/after 只针对当前实例，其他同类
实例需用新的共享改良和各自邻接重新推导。测试库存/年龄为隔离夹具，不声称是原作初始库存。

固定原始道具数值较小，整数半倍/双倍与原作 float 路径一致；自有巨大或负参数用于安全边界测试，
不冒充原作道具。示例不重现 float 大整数精度损失、Java 回绕、原作短整数存档布局或 UI 动画。
没有恢复全部道具获取/购买/角色使用、`A` 库存、完整事件解释器和正常产品存档。
