# 地图、占用格、设施访问与连通状态

更新：2026-10-03；设计与验收见 [R2-D](../stages/history/R2-world-facilities.md#map)。证据根和警告规则见
[证据清单](../EVIDENCE.md)。本报告不把旧单点原型入口当作原作事实。

## 占用格就是设施活动候选格

`a/o.java:200-220` 创建设施时，以 [已恢复占地](FACILITIES.md#definitions-占地与朝向直接证据) 的 `ai` 顺序
绑定地图格，格反向指向同一实例，`Tenant.z` 保存这些格。它没有把周边道路装进 `z`。
双格朝向 0 的首项在锚点下方，四格首项在锚点左下方；不能认为 `z[0]` 恒等于设施锚点。

`c/l.java:156-181` 的一般活动候选收集有限距离的设施格；`c/b.java:857-881` 从所选实例 `z` 中
选候选格。后续 [低层核对与选择切片](ACTIVITY.md#ranked)补齐循环：普通加权分支取选中
实例的最小候选列表下标；按成本排序时为该实例优先格。后续 [R2-J](ACTIVITY.md#candidates)补齐候选
交换排序平局；当前路径前驱仍保留 Ark 平局约定。目标是在设施自身格中
寻找，而不是以外侧道路为唯一终点。`c/b.java:3294-3305` 保存目标坐标、定义 ID 和实例 ID，
`2233-2245` 的较小方法在到达时重新比较三者。

## 路径类别与地图显示状态分离

地图格字段 `g` 是路径类别，`f185e` 是状态；两个数字不能互换。`c/i.java:70-110` 的绑定消费者如下：

| 定义种类 | 绑定状态 | 路径类别 | 当前解释 |
| --- | --- | --- | --- |
| 3、12、13 | 1 | 0 | 普通商店/住宅等，能作终点，不能普通穿行 |
| 1 | 8 | 0 | 特殊设施格，仍为终点类 |
| 8 | 9 | 0 | 未完整命名的分支 |
| 9 | 10 | 0 | 未完整命名的分支 |
| 4 | 6 | 4 | 入口类，可有普通出边 |
| 5 | 7 | 4 | 外侧入口，另保存方向参数 |
| 其余绑定种类 | 2 | 3 | 已知装饰落入此分支；不能扩展成任意种类都合法 |

普通地表清空为状态 4 / 类别 2；铺路为状态 3 / 类别 1（`c/i.java:56-67,104-133`）。
城市边界会把地表格改成状态 5 / 类别 3（`c/h.java:974-995`、`c/i.java:165-169`），
这与占用终点不同。范围内仍可走地表，费用十倍但不是禁走。

普通准入矩阵来自 `c/i.java:6`，行为由 `c/l.java:67` 使用：

| 离开类别 → 进入类别 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 0 | 否 | 否 | 否 | 否 | 否 |
| 1 | 是 | 是 | 是 | 否 | 是 |
| 2 | 是 | 是 | 是 | 否 | 是 |
| 3 | 否 | 否 | 否 | 否 | 否 |
| 4 | 是 | 是 | 是 | 否 | 是 |

首次展开额外允许进入邻格状态 3 或 4，与邻格路径类别无关；并不是每次从设施出来都无条件忽略准入。
`c/l.java:103-117` 把没有设施且路径类别 0/3 的格从展开集合排除。因此一个类别 0 的设施能被到达，
随后没有出边；人物以其为新起点再次搜索时又可首步走回道路/地表。无设施的孤立终点不能靠这个
特例启动搜索。权重按离开格：类别 2 为水平 50、垂直 70，其余类别为 5、7。

## 连通状态不是建设硬门槛

`c/l.java:193-230` 从地图入口表第一项 `f180f[0]` 搜索，把商店/住宅的实例标志 `n` 的位 1
设为可达；遍历有序占用格，如果每格都是无穷距离再清除此位，必要时发事件 115。
任一占用格有有限距离就不会清除可达位；不要求全部占用格可达。

`b/c.java:1359-1397` 的小型放置检查检查地域、已有状态；普通建设分支遍历占地并扣款，之后调用
连通状态更新（`1702-1737,1774`）。该主方法有 JADX 警告，因此不能穷举全部前置菜单限制；
至少不能把“连通检查存在”改写成“必须先接道路才能建设”。道路影响权重、邻接魅力与视觉，
不是本报告擅自增设的硬拒绝条件。

## 周边表的正确职责

`a/o.java:399-490` 使用 `aj` 的 8/10/12 个周边格，按来源定义的第 26/27 列对附近商店添加
价格/品质/魅力实例修正。同一个来源只作用某个目标一次，即使触及该目标多个占用格；
末尾另给商店按周边道路格每格魅力 +2。它不是四方向或单个正门，更不是人物必走的入口集合。
这部分消费较清晰，后续单独维护邻接修正及来源列表，不混进路径节点。

后续 [邻接属性切片](FACILITIES.md#neighbourhood)已经实现有序外环、实例去重、道路魅力与完整重算；
它与本模块的四向寻路、占用活动格保持独立，不因此产生唯一正门。

## 未知与独立示例边界

- 首局原地图与加载后576格/8实例身份已静态重建，见[新局报告](STARTUP.md#加载后逻辑显示快照)；
  本模块的一般地图仍由调用方提供，动态扩张/继承/原版运行捕获不在本批范围。
- 一般候选的过滤还涉及设施状态、上一目标、任务和事件；本批可达性不等于完整活动资格。
- 普通加权分支的多格最小候选下标、候选交换排序已核对；其他活动特例/上层角色资格仍未完整恢复。
- 默认原型使用真实新局，旧自主经营演示是显式夹具；新局地图/行走组合不修改容量、预约或现金。
- 预算、稳定 ID、严格输入拒绝和事务保护属于独立安全契约；不模拟 Java 溢出或异常吞掉后的部分状态。

## 独立 C++ 交付

[接口](../example/include/dungeon_village_reference/map_access.hpp)、[实现](../example/src/map_access.cpp)、
[测试](../example/tests/map_access_test.cpp) 独立维护，已有的单点 [路径模块](../example/include/dungeon_village_reference/navigation.hpp)
继续服务旧模拟，不能把两者当成同一数据契约。

- `bind_facility_map` 从没有设施绑定的基础地图和唯一设施列表派生占用格；支持已恢复的种类消费者，
  未知/仅地表种类拒绝。它不是建设审批：允许覆盖基础格的道路，但不判断城市边界、费用或 UI 解锁。
- `search_legacy_map` 成功才返回带地图快照的完整距离场。预算裁剪返回错误和空场，不把部分结果报告
  为设施必然不连通；同成本按较小格下标稳定，R2-J 核对原作反向扫描偏向较大下标，仍未复刻。
- `inspect_facility_access` 检查实例、定义、占地和分片绑定，一格可达即有非空列表；保持占地顺序，
  不自动选唯一入口，不判断任务/职业/设施营业状态。
- `trace_legacy_path` 校验场结构和每条前驱的步长/准入/距离，严格递增距离排除循环；起点不出现在
  路径中，终点在内，起终点相同为成功空路径。结构校验不是外部任意场的最优性证明，应用应使用搜索结果。
- `arrival_binding_matches` 比较目标坐标、定义和实例；只证明身份匹配，不自动收费/使用/发效果。

历史R2-D切片通过6,339项检查；当前原型地图组合已消费此接口，用加载后地图验证两个真实出生点。
最新回归见[验证入口](../VERIFICATION.md)，不以历史数量替代当前检查。
完整操作/画面、动态扩张、首访上层优先级及全部活动资格仍不属于本批完成范围。
