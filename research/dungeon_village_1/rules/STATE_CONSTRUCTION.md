## 1. 建筑选择、放置、移动与撤除

### 直接观察

- 进入建造模式会将提示设为 `要建在哪里呢`，清零模式计数器，并选择建造专用 UI 提示
  （`b/c.java:582-609`）。触摸输入更新网格光标，控制器绘制闪烁的占地或道路预览
  （`b/c.java:1198-1355`、820-934）。
- 放置校验首先检查地图边界。建筑放置会用明确提示拒绝已占用格和城镇外坐标
  （`b/c.java:1359-1397`）。确认时先验证每个占地格，再在状态变更前比较价格与当前资金
  （`b/c.java:1702-1729`）。
- 提交分支区分设施建造、道路起点/终点、设施撤除、道路撤除、移动选择和移动完成
  （`b/c.java:1732-1890`）。建筑和道路成功使用不同消息；撤除会清空选中的运行时引用并刷新寻路。
- 移动选择保存现有实例及其朝向。移动完成分支设置朝向，快照选定字段，清除旧放置并创建新的 `Tenant`，
  恢复数字 ID/部分统计，并扣款 300（`b/c.java:1826-1890`、`a/o.java:576-593,613-635`）。
  不是保持同一个 Java 对象；旧占地重叠分支带反编译疑点，完整准入暂不按重建条件断言。
- 取消/返回会退回先前模式并清理建造覆盖层（`b/c.java:1899-1947`）。该方法含可疑的反编译循环体，
  因此这里只采信模式转换。

### 控制流推断

UI 是模态命令状态机：选择操作、移动光标/预览、确认时校验、提交，然后令寻路和选择缓存失效。
视觉预览不是权威状态。移动重建对象但保留数字身份及部分耐久统计。由于主更新方法带 JADX 警告，
具体模式数值和全部拒绝消息仍有部分依赖推断。

### Ark 建议

将建造、移动和撤除表示为作用于全局状态候选副本的命令。提交前验证边界、占用、资金和引用。
选择及预览留在接入层。移动已有 `BuildingId`；撤除必须清理预约和角色目标。C++ 示例实现了这一边界。

### 未知项

- 是否所有撤除分支都会退款；已观察到的道路撤除退款乘以零。
- 固定输入的占地形状和两种朝向已在 [设施报告](FACILITIES.md#definitions) 恢复；完整邻接准入和接入仍未完成。
- 未展开的辅助方法是否会清理全部缓存引用。

## 2. 角色选择设施、寻路与使用

后续细化见 [人物自主行动与加权寻路](CHARACTERS.md)：普通行动由人物状态机自主调度，
不是玩家点击控制。原型 `Visit` 为调试夹具；原作道路/空地成本不等，不能用原型 BFS 当原作规则。
最新 [普通到达报告](FACILITY_USE.md#arrival)已拆出访问计数与即时金币候选；下文 R1 的“完成才生效”
仍为 Ark 安全夹具，不是原作全部收费/统计的时点。

### 直接观察

- `Character.o(int)` 向共享服务请求候选地图格，过滤不可用的 `Tenant` 实例，按活动类型分支选择目标，
  没有候选时返回 `false`（`c/b.java:2337-3257`）。该方法有大量重复代码块警告。
- 写入目标前，它会用当前位置和目标格调用 `RouteSearch`；寻路失败即返回 `false`
  （`c/b.java:3259-3268`）。成功后将目标坐标、设施定义 ID 和实例 ID 写入四元素目标数组
  （`c/b.java:3290-3299`）。
- 使用退出操作码 24 会从当前格解析设施。不匹配时记录错误并重置角色
  （`c/b.java:3832-3838`）。合法转换会从设施占用向量移除角色、清理移动/使用标记，并安排按设施类型
  区分的效果（`c/b.java:3839-3948`）。
- `Character.q()` 返回角色当前格的设施或空值；`Character.r()` 清理目标和控制器，并在存在设施占用时
  移除该角色（`c/b.java:5886-5917`）。
- `Tenant.a(Character)` 添加占用者，`Tenant.b(Character)` 移除占用者
  （`c/m.java:169-220`、523-525）。

### 控制流推断

总体生命周期为 `idle -> 选择候选 -> 寻路通过 -> travelling -> 设施使用转换 -> 应用类型效果 -> 重置`。
候选优先级依赖活动和角色状态，但带警告的方法不足以可靠复现精确权重。现有证据也不能证明原作的
占用向量一定是出发前建立的严格预约。

### Ark 建议

显式且唯一地记录预约所有者。开始寻路时预约；寻路失败或取消时立即释放；只有抵达后才进入
`in_use`；使用完成后才应用收益。该契约有意比恢复出的向量协议更严格，也更容易验证。

### 未知项

- 精确候选评分、随机平局规则和活动优先级。
- 原作每类设施是否都只允许一个占用者。
- 完整地图类别语义、入口几何与回退行为；已确认的道路/空地成本见后续报告。

## 3. `Tenant` 设施实例数据

### 直接观察

- 创建 `Tenant` 时传入设施定义索引和位置，寻找未使用的全局及同定义数字 ID，初始化活动状态，重置
  居民/任务向量，并将居民链接设为 `-1`（`c/m.java:111-168`）。
- 序列化保存全局实例 ID、同定义实例序号、定义索引、生命周期状态/计数器、多项累计计数、可变向量、
  位置、朝向、关联角色 ID、年度/月度数组和效果历史（`c/m.java:223-332`）。占用者保存为稳定角色 UID，
  不是对象地址（`c/m.java:299-303`）。
- 加载后，`deserialize2()` 使用全局角色向量解析保存的 UID，并记录无法解析的引用
  （`c/m.java:76-99`）。
- `Tenant.c()` 推进建造中、活动和特殊状态；完成分支修改状态并调用设施定义辅助方法，活动设施则更新
  待处理效果和占用者（`c/m.java:531-827`）。
- `Tenant.e()` 根据保存的定义索引取得不可变设施定义；`f()` 根据地图坐标和设施形状计算渲染/使用点
  （`c/m.java:856-894`）。

### 控制流推断

`Tenant` 是可变设施实例，不是目录定义。它拥有稳定身份、放置、生命周期、占用者、周期统计和效果队列，
同时将静态价格、类别和形状委托给定义表。

### Ark 建议

保持 `BuildingDefinition` 不可变，`BuildingInstance` 只保存其键。持久化单调递增实例 ID、位置、朝向、
进度和耐久引用。加载后通过已校验 ID 重建临时占用和寻路缓存。

### 未知项

- 每个序列化标量和数组槽位的语义名称。
- 哪些效果队列项必须跨 Ark 存档保存，哪些应恢复或取消。

## 4. `UserData` 全局聚合

### 直接观察

- `UserData` 包含居民/设施、当前任务、计数器、事件队列、周期统计数组、解锁状态和报表快照
  （`c/n.java:40-162`）。
- 读写器对称地序列化全局计数、当前任务 ID、参与者 ID、周期矩阵、事件队列、报表值、记录标记和
  选中的报表实体（`c/n.java:2492-2651`）。
- 运行时协调器保存 `UserData`，并分别序列化角色、怪物、效果、任务和紧凑设施放置分区
  （`d/a.java:3194-3268`）。
- `UserData.e()` 推进报表状态机，并更新事件队列、角色、怪物、设施、任务和临时效果
  （`c/n.java:3778-4201`）。它含重复/移除指令警告，因此完整总顺序不作为直接事实。

### 控制流推断

`UserData` 是大型全局领域聚合，`d.a` 是运行时/资源/存档协调器。状态被拆入多个二进制存档分区，
跨分区身份通过数字 ID 恢复。更新方法混合了周期结算、实体生命周期、事件调度和清理。

### Ark 建议

在 `Game` 边界保留唯一 `GlobalState` 聚合，但将规则拆为建造、预约/活动、任务和结算函数。在聚合中
保存稳定 ID，由接入层序列化并重建派生索引；不复刻全局单例或平行数组布局。

### 未知项

- 存档分区版本兼容性和协调器拥有的全部字段。
- 哪些全局数组是耐久事实，哪些只是报表/UI 缓存。

## 5. 月度收入、维护费、任务与设施效果

### 直接观察

- 时间累计将四个子周期合并为一个月、十二个月合并为一年；月份变更块在日历字段更新后运行
  （`b/c.java:150-195`）。
- 月份变化时，控制器重置月度计数、递减居民计时器、推进设施统计年龄、执行计划中的季度检查，随后
  调用 `UserData.G()`（`b/c.java:195-317`）。另一子周期分支推进任务持续时间，可在八个子周期时预警、
  十二个子周期时给出结果（`b/c.java:319-342`）。
- 临近周期边界时，`UserData.e()` 进入报表状态 1，计算角色周期费用和设施维护费，实际扣款并更新设施统计
  并记录总计（`c/n.java:3807-3869`）。报表从快照槽位显示 `收入`、`经费` 和 `合计`
  （`c/n.java:3517-3530`）。
- 报表状态按 `1 -> 2 -> 0` 推进；离开状态 2 时把累计讨伐奖励计入村子点数，不是金币
  （`c/n.java:3871-3900`、`3158-3159`）。另有状态 3 发点数分支，其入口仍未知。
- 角色在使用退出操作码中解析设施后，调用按定义/类型区分的效果函数
  （`c/b.java:3832-3948`）。
- 终止任务会请求确认并扣除人气；任务事件文本包含开始、继续、终止和一个月预警
  （`b/g.java:11182-11217`、`c/n.java:95`）。

### 控制流推断

报表按月内计数提前准备，不是先跨月再准备。金币在收入/扣款事件即时变化，报表仅汇总部分分类；
关闭报表发放村子点数，不重新入账报表净额。日历跨月另行推进居民/设施统计并清月度计数。
精确路径及带警告边界见 [周期账本报告](ACCOUNTING.md)。部分设施效果位于使用退出序列，不是月度轮询；另有到达阶段的收费和统计，
不能把所有设施资金/效果统一归到完成事件，定位见 [后续报告](CHARACTERS.md#到达收费与效果不是一个事件)。部分任务后果发生在子周期事件中，
不属于月度资金报表。

由于 `UserData.e()` 带警告，维护费扣除、事件消息和报表动画之间的完整关系还不足以写成原作通用规则。

### Ark 建议

使用三条显式且各自幂等的路径：

1. `complete_use(activity_id)` 在抵达后应用一次设施效果并释放预约。
2. `complete_task(task_id)` 记录并奖励一次任务完成；重复投递不产生效果。
3. `settle_through(month)` 从持久化结算游标之后按升序处理每个月，每月写入一条账本/报表记录。

这三条是 R1 的 Ark 夹具，不是原作入账顺序。更接近原作双资源边界的独立示例见
[周期账本报告](ACCOUNTING.md)，不将其与 R1 统一净额结算混用。

  可用状态过滤以及所有周期扣款分支仍待恢复。

- 报表动画打开期间保存/恢复的行为。

## 6. 可提取的领域规则

下列行为可以从巨型更新方法中分离，不依赖 Godot 或渲染：

| 规则 | 输入 | 耐久输出 | 仅接入层输出 |
| --- | --- | --- | --- |
| 建造报价/提交 | 目录、资金、占地 | 建筑实例、资金 | 光标、预览、消息 |
| 移动/撤除 | 建筑 ID、目标占地 | 新位置或删除、清理后的引用 | 粒子、选择状态 |
| 设施选择 | 需求、候选、可用性 | 选中的建筑 ID | 思考气泡 |
| 寻路准入 | 角色/建筑 ID、寻路结果 | 预约和活动状态 | 行走动画 |
| 使用完成 | 活动 ID、设施规则 | 居民效果、使用/进度 | 效果精灵/文字 |
| 任务转换 | 任务 ID、事件 ID | 状态、奖励/惩罚标记 | 模态框/事件动画 |
| 月度结算 | 结算游标、周期输入 | 账本/报表记录 | 报表动画 |

[C++ 示例](../example) 将这些行为实现为作用于 `GlobalState` 的小型函数。它展示目标契约，不复刻原作类布局。
