与 [共同生命周期](LIFECYCLE.md)，不声称已经实现完整人物/怪物世界。

## 原版返回语义

`m(int)` 只是追加 `[10,参数]`；无参 `m()` 是请求表情5，两者均不是完整世界更新。
`v()` 才是实例控制 FIFO 解释器，内部 `while` 每次重新读取当前队首。
`o(int)` 是即时目的地选择/建路，调用成功本身不表示到达、占用或收费。

| 本次控制结果 | 原版行为 | 后续共同人物更新 |
| --- | --- | --- |
| 队空或全部即时操作完成 | `v` 返回 false | 执行一次共同 `d` 尾部 |
| 等待仍正、运动未到、攻击未完 | 保留阻塞队首，`v` 返回 false | 仍执行一次共同尾部，不再解释 FIFO |
| 成功8 | 已移除8，直接 `A=0`，停止本次 `v`，返回 false | 仍执行尾部；新活动路径与原装备/属性尾部不立即执行 |
| 旧1024/32768导致失败8删除，或26 | `v` 返回 true | 整个 `d` 尾部跳过；调用者执行人物实例删除点 |
| 普通24、失败8的非删除 `r()` | 完成清理/重建队列后继续 `while` | 同次读新队首，没有额外“退出之后等一帧” |

局部领域消费者返回 `delegated`、`exited` 或 `cleaned_up` 只是实现的交接点。
这些标记不能自动映射成原版 false 早停，否则失败出发、旅店退出、商店退出会各多等一轮。
反过来，返回 `waiting`/`moving` 之后不能再次进入局部前缀，否则同一等待会再扣一次、同一运动会再走6.7。

## 队首消费与写入顺序

1. 0先运动，成功才移除；1先置可见位、减计数，归零才移除；14..17先提交当前攻击帧，完成才移除。
2. 2先移除再执行 `c(state)`。该 setter 清掉旧队列，可能生成新队列；不能恢复本次进入前的旧尾部。
3. 8先移除，再调用即时 `o(activity)`；成功直接写 A，失败才检查旧1024、表情18/32768、512位变更与 `r()`。
4. 10/12/13先移除，再按当前地图/引用漫游并追加到原尾部；无 db/S 只移除、零随机消费。
5. 18/19/21..30/32/33原作都是先移除，再提交副作用。维护候选在私有副本准备成功后提交整段，
   可以把内部移除置后，但不得因此改变事件顺序、读取点或让外部看到半状态。
6. 24用当前 q 身份，21直接读当前 O 格实例，两者不是同一个守卫。
   24位置/共享使用/清33/释放首引用/清队列/n0/c0之后排新活动0，商店再加属性或装备尾部。

`r()` 保留 k/l、N 与既有 G 路径：人物 `c19`，仅含1024时排等待120，然后排活动5；
怪物 `c0` 后排活动5。人物等待120刚生成仍会在本次 `v` 扣成119。
若不含1024，新8可在同次调用马上执行。新增1024之后不能回头重查32768。

## 维护组合器合同

所有者模板只要求三个适配器：读取人物唯一 `control`，写回该唯一字段，领域消费者。
领域消费者输入 `const Owner&`，只能返回私有候选；随机票号游标、显示请求和派生目录也必须留在该候选。
本函数不拥有第二份人物控制状态，不跑计数/效果/HP/成长，不安排携物表情，也不跑物理和退休收集。

领域结果必须明确选择：

- `continue_same_call`：已消费/替换当前队列，重新读当前所有者，继续解释；退出/清理一般是此结果。
- `hold_false`：真正等待、未到达、未完成攻击或成功8；保留候选给调度者跑一次尾部。
- `delete_true`：原版 true 删除请求；不给控制尾部，不在此层统一回收所有对象引用。

组合器先调用一次本地前缀；遇到未实现的领域码交接，只有明确 continue 才重新进入本地前缀。
本地正等待立即返回 held，不能拿通用“分段成功”再跑一遍。
移动0必须每个队首重新计算实际目标，不重复使用上一个0的已到达结果。
攻击使用 [prepare_world_attack_control](../../example/include/dungeon_village_reference/combat_commit.hpp)，
不要嵌套使用会自行执行本地尾部的 `prepare_world_attack_execution` 再解释一次同一等待。
同理共同前段只能在外层调度调用，不能给各领域再次调用 `prepare_world_facility_execution` 或旧旅店 `d`。

缺读取/写入适配器、人物失效、非法队列、缺领域消费者、消费者失败、continue后控制毫无变化，均返回错误且无候选。
迭代预算只防维护输入或适配器形成无限续行；耗尽拒绝整段，不能把半执行状态延后至下一帧。
预校验、进度守卫和预算是维护安全契约，不是从原作推导出的操作条数限制或损坏存档行为。
领域回调若保持队首仅改变外域后要求再执行自己，本合同拒绝；应消耗该命令、替换队列或选择真正 hold。

### 26：共享定义变化在前，调度删除在后

原命令先移除，读取人物共享定义，调用固定输入的空 `n.j()`，写定义 `m=1`，返回 true。

人物HP/control/速度仍以嵌入的共同世界为唯一所有者，不为这一命令复制整套人物定义模型。
