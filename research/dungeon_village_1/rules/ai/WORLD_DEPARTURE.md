## 唯一状态与调用合同

输入是当前 `RescueWorldState` 私有候选和 `WorldDepartureInput`。人物、HP、控制队列、
定义成长与事件只读写该世界已有唯一所有者；不创建第二份可长期变更的人物数据。
候选实例身份、状态及上次到访实例从所有者重建，不信任调用者提供的实例数组。
调用者提供当前地图定义 ID/类别/魅力、当前 `bq` 任务记录、定义详情、共享住宅 `D`、
实际 `Map.f` 出口和当前任务中心。这些是原版事实投影，不得补演示初值或从镜头猜出口。
地图定义类别与设施类别必须一致；缺目录或必要随机票号返回错误，没有半状态。

`o` 从 **旧缓存 `s`** 搜索，不以移动后的 `n` 代替；进入搜索先清 `G/H`。
无候选、无目标和合法目标无路线均返回 `candidate + succeeded=false`，保留旧 `O`，
但新候选已经清除旧路线与路径索引。无路线不是成功传送，也不自动再选其他目标。
事务不删除控制 8、不直接写 `A=0`、不运行共同计时前段、不扣款、不占用设施。
控制解释器应按自己的原执行点消费此结果和失败清理。

`destination` 对应 `O[0/1]`，与设施身份 `binding` 独立；原新对象 `O` 四项为零，
因此没有维护记录时，优先级占位扫描保留默认 `(0,0)`，不能普遍声称原 `O` 为 null。
成功到无设施格时保存真实 `unbound_route`，不伪造实例 ID0 或定义 -1 当成设施身份。
首步更新面向；空路线保留旧面向。位置、当前状态、资金与占用名单不在这里变更。

## 优先级与抽取

人物且未置 512/1024 时先处理优先级：

1. 当前任务有效、未携物、定义标志 2，且任务中心存在于当前候选：直接选中心。
2. 无定义标志 2 时，重新查询最近 `I()`；其他人物的旧 `O0/1` 已指向它则跳过救援。
3. 查询最近 `H()`，只尝试该物体缓存生成格，不扫描次近可达替代品。
4. 仅活动 6 扫当前 `bn`，按格欧氏距离取整、原反向严格小于交换平局，
   选该最近事件 3×3 内的首个成本排序候选；不因最近不可达改选次近事件。

任务中心命中后先执行 `a.e.a(0,self)`：未有 2048 则抽 100，严格小于 `u×20/100`
才置 2048，并按已有事件集合决定是否登记 116。阈值为零也消耗这次抽号。
**状态 18 的 `u×12/100` 不复用到此处。** 后续路线正常失败仍保留已完成的增强提交。
`F()` 属于人物 `c()` 的状态/抢占调用链，原 `o()` 不额外调用 `F()`。

| 活动 | 未被优先级命中时的原选择 |

| 1 | 未携物且 `I1=0` 才抽 100；未休息阈值 30/40/50，已休息阈值 60/70/80/90，按 `K` 封顶；成功实际调用 `a(4,dm5,vector)`，抽号上限类别 5、扫描类别 4 的错位保留 |

类别 3 先在住宅 `D2=1` 时抽 100；低于 90 后才检查 `R`、旧 `s` 和实例。
旧 `s.x != home.x` **且** `s.y != home.y` 两项同时成立才能采用住宅，不能改成“不同格”。
住宅实例存在且状态非零即可；住宅目标不必来自普通候选，仍须原距离场可追溯。
未用住宅时，人在前两个实际出口之一直接选另一个；否则抽整个实际出口数组。
缺出口、出口越界或缺必要住宅投影是输入错误，不制造替代出口。

## 搜索上限与后续边界

活动 6 且旧 `s` 在城外时，上限 500 仅阻止展开成本大于 500 的节点。
已经松弛的前沿格仍保持有限距离：纯横向草地中，500 格展开后 550 格可选，600 格未发现。
新的 `max_expanded_cost` 与既有 `max_cost` 不同：后者仍限制边成本并返回 `cost_limit`。
该出发入口显式启用原库存反向的同成本顺序，普通寻路默认顺序保持兼容已有调用合同。

本模块闭合 **目标选择、抽号、当前实例绑定与真实路线提交**；无设施路线保存独立真实 `G`。
后续 `P()` 已增加下述独立状态 0 消费者，仍不以 `succeeded=true` 宣称已经收费、占用或删除。
当前测试是有来源边界的共同世界夹具，不等于固定 APK 动态轨迹或真实新局完整 AI 验收。

## 控制 8 的真实 FIFO 消费

新增 `prepare_world_departure_control` 维护低层 `Character.java:10255–10307/Lc1→L11f`：
先删除实际队首 8，再以该条命令的活动参数执行上述真实 `o` 事务。
成功仅直接写 `A=0`，返回 `continue_interpreter=false`，原 v 返回 false；
不调用 `c0`，不清 B/C/D/k/l/i，剩余装备属性或其他队尾保留到后续 d。

普通失败读取 o 返回后的旧标志，依次处理：

1. 旧 1024 已置则执行真实 `c(18,0)`。概率先消费 1000，现有 cd12/24 可抑制后续变体；
   未抑制时要求平台变体数量与合法变体票号，不由截图语言推测。
2. 仅在上述旧 1024 分支中再查旧 32768；命中返回 `delete_instance=true`，
   不提前执行 r、512 改写或真实名单删除。人物 d 删除前的 q 释放由共同调度处理。
3. 未返回删除则在旧 512 存在时置 1024、清 66，再执行 r；
   **新置 1024 不倒回去重查 32768**。
4. 返回 `continue_interpreter=true`，外层在同一次 d 从 r 产生的新队首继续消费。
   不再运行共同计数/显示/HP/成长前段。

人物 r 复用现有共同救援清理；保留 k/l/N/O，清 R/db/dc/高度并设 c19，
1024 时重排等待 120，再排活动 5。原队尾被 r 替换。
本次 FIFO 续行已经以真实本地等待消费者验证 `120→119`；无等待时，测试实际再次调用
控制 8 消费者执行活动 5 并保存真实出口路线，成功才结束本次解释。
怪物 r 按同一既有清理规则提交 c0、首次 q 占用释放和活动 5，无人物等待，
没有额外调用 n0 或清 N/O。控制层只返回运动/删除请求，仍不执行 P 运动和到达。

若晚期表情票号缺失或非法，整条控制候选拒绝，输入中的队首 8、路线与效果均保持不变。
当前新增检查属于真实 o 与 FIFO 世界组合；仍不是窗口动态对照或固定 APK 跑轨验收。

## 真实 P 路线消费

`prepare_world_path_c` 对照常规 `c/b.java:528–660`，并由低层
`Character.java:2735–3075` 校正怪物类别 3 的 `true` 跳转；目标身份 `j` 对照
低层 `Character.java:9179–9230`。原状态 0 的 `c` 在 `c/b.java:4877–4879`
先执行 `L()` 再直接 `return P()`；共同 `UserData` 在 `c/n.java:3945–3946,3966–3967`
按 `c=true` 在决策遍立刻删人物/怪物名单，不能把该返回值推迟到执行遍 `d`。
怪物状态 17 的 T1/T4 也调用 `P`（`c/b.java:5359–5383`），但不传播删除：
T1 仅在 `P=false` 且城内计数 `L>=500` 执行 `r`，T4 忽略 P 返回值。
候选因此区分 `path_returned_true` 与状态 0 才置的 `delete_instance`；
调用资格和 T1 的计数清理仍由状态分支所有者负责，不能对 T0/T2/T3擅自调用 P。

调用位置必须是共同 `c` 前段、引用修复/抢占与状态 0 的真实 `L` 之后，
或已核定调用资格的怪物 17/T1/T4 分支。
本消费者不重复共同前段、`L` 抽号、计数、HP 动画、物理或投影，不在控制 `0` 偷读 `G/H`。
`WorldMapFacts` 必须与共同所有者当前地图完全一致；真实出口数组允许为空，但缺投影是错误。

### 原顺序与身份

1. 内部调用既有 `prepare_world_event_gate`，重建真实 `F()`，不接受“默认允许战斗”布尔。
   `F=true` 时保留路线，人物按原序先扫描旧格相邻、不同原 `f143e` 的人物，
   命中才消费 `c(7,0)` 概率/平台变体；表达式 7 的概率门槛为 1000，现有 `cd12/24`
   可抑制变体但不能省略前一概率票号。随后真实 `c18` 读取当前共享 `u`，
   未有 2048 时消费一次 100、阈值 `u×12/100`，并提交新事件 116。
   怪物只执行真实 `c1`，不进行人物表情/增强。
2. `F` 产生任务事件创建请求时，必须用显式纯 `task_attempt` 完成原创建尝试；
   回调返回现有 `WorldEventEntryCandidate` 完整结果，不只返回人物/事件状态：
   新 `facts.flags`、任务 `encounter`、创建 ID/拒绝原因、music2/notice24 同时交回外层所有者。
   合法尝试失败可返回未新增事件的候选，原 `F` 仍为 true，不伪造 `db` 已绑定。
   未提供消费者、抛异常、返回失败或非法改名单，都拒绝本次完整候选。
3. `F=false` 后，旧缓存 `s` 越界直接返回未移动候选。`G` 空即使 `s==O` 也不入场。
   当前 `n` 已进入目标格、但旧 `s` 尚未刷新时，仍只推进路径。
4. 仅 `G` 非空且旧 `s==O0/1` 才校验 `j`。有设施 `O2!=-1` 要求当前格实例的定义 ID、
   实例 ID 与 `O` 全相等；失配执行真实 `r`，不扣款，且保留旧路线及目标。
   无设施 `O2=-1` 仅比较坐标，**后来在目标格建起设施也仍走地面分支**。
5. 身份通过后 `O()` 同步清 `journey/unbound_route/H/path_pending`，保留目标坐标及绑定。
   地面出口安排格中心的 `z-50` 运动 `0`，再追加 `26`，位于旧队尾之后。
   此时人物/怪物都是 `P=false`，不改共享定义 `m`、不直接删名单。
   非出口地面人物真实 `c5→10,0`；怪物真实 `c17→8,7`。

### 路点与到访

未到目标时，读取当前 `G[H]`；普通格使用 100 单位格中心。状态 6/7 必须显式提供
该格当前定义的 `o.m`，按 0/1 调整 z、2/3 调整 x，偏移为 +40/-40；不能用实例 `q` 猜入口。
每次真实运动推进 6.7，按位 64 守卫，不吸附到中心，仍按原小矩形计算重叠。
仅非末点重叠才 `H++`；最后点始终保留至旧 `s` 触发入场，不能递增越界。
只更新当前 `n.x/z` 和有实际运动时的 `r.x/z`；`s/t/u` 留给原 `d` 尾部统一刷新。

普通未携物、非装备详情到访已直接组合真实 `prepare_facility_arrival`、
共享人物 `B2`、设施销售、即时现金账本与 `prepare_world_facility_use`。
到达收费使用旧 256，收费后清 256、选择人物使用模式 2，否则模式 0；
到达不会提前登记占用，`21` 才进行占用提交。
有源的特殊 `6/3` 与 `8/2` 使用需要真实 `h.e` 目标/方向票号，不补默认位置。
怪物到设施先实际到访，再 `w` 清控制队列：类别 3 返回 `delete_instance=true`，
不运行执行遍；类别 `6/3` 安排真实特殊入口/效果 20；其余 `c17→8,7`。

递归救援、装备抽选、物体交付属于显式 `facility_consumer` 合同：人物回调必须完成
真实 `a(m,o)→清256/选择use`，怪物回调只完成 `a(m,o)`，之后由本模块安排其分支。
回调接收身份通过且 `G/H` 已清的私有候选；禁止改人物名单/身份、地图、自身位置/缓存格和目标身份，
并要求实际 `J` 已记录到访实例。失败或异常整批回滚，不能以空回调当成“已到达”。
已用真实 `prepare_world_rescue_delivery` 验证递归人物旧格复制、救援收费与 helper mode2。
商店自身较宽的装备/目录所有者仍由其领域保持；这里的回调合同不宣称这些额外聚合已自动并入。
