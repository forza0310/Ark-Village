# 快照恢复、重复回放与持续存读档

2026-10-07。状态：**研究与短探针完成，以下是待确认的实施设计，尚无正式文件codec或恢复接口**。
仅维护research；固定APK仍为规则基线，Steam只作独立交叉输入。
来源事实见[存档规格](../rules/PERSISTENCE.md)，工具身份见[证据清单](../EVIDENCE.md#存取与快照交叉证据2026-10-07)，
本批实际检查见[验证记录](../VERIFICATION.md#存取交叉分析与快照短探针2026-10-07)。

## 要解决的问题与已证边界

自然扩张现有全链需7665.97秒；日常每批从新局重复该前缀成本过高。
加速应来自复用已认证前缀和缩小本批相关尾段，不能改变原日历步长、AI轮次、随机消费或删掉有效断言。
旧长测黄金轨迹、参数及注册保留，尾段通过与从新局自然可达分别报告。

本轮短探针给出了两个不同结论：

- Session与外部控制器可以在同进程值复制；真实新局433帧后，两分支各续420帧，所列逐帧字段、未来32次随机抽样和输出序列一致。
  历史检查点共享const指针，新检查点独立；合法铺路产生的待领取sound11恰好领取一次。
  这是有限场景／观测字段的验证，未覆盖完整Owner字段、文件恢复或自然扩张后缀。
- 日历检查点处于轮内，直接再执行完整框架使到访20→19、global和entry各400→401、scene_counter402→403，
  即使日期、steps、随机游标看似一致也已重复业务。不得直接将`checkpoints_`当作可续帧文件。

APK不保存随机与页栈，加载还会清理实体、丢弃设施效果队列；Steam对应队列也丢弃。
完整分析原存档有助于字段与引用覆盖，但不能单靠原存档得到精确重放。

## 推荐分工与首版范围

| 对象 | 首版建议 | 明确不作为验收结论的内容 |
| --- | --- | --- |
| 原存档研究 | 继续25分区、完整嵌套布局与真实样本交叉；保留原字段和两版差异 | 尚不宣称APK／Steam文件互通或全旧格式兼容 |
| 精确测试快照 | 独立维护格式，保存完整受支持Session动态状态、逻辑输入、测试控制器、边界与来源；跨进程恢复同一后缀 | 不把末端正确继续当作本次实现已从新局走完前缀 |
| 正常研究文件存取 | 复用同一世界字段编解码底座，首版只在稳定主场景保存；保留维护随机，恢复后重新采集OS输入 | 原APK读档语义、任意模态保存、旧demo迁移及原APK档导入均未获本方案自动承诺 |

正常存取与测试快照使用不同用途标识、载荷清单和校验，不能互相静默降级。
正常档不需要携带测试控制器或全部审计历史；省略仅测试数据须经字段分类，不得丢失玩法状态。
精确测试恢复包括仍可达的退休对象及既有审计历史；可按内容去重保存，不可清空历史后冒充原长测。
正常档的随机／页态政策与原作不同，要标为维护策略。该选择须与首版格式一起确认。

## 捕获边界与字段覆盖

首版选**完整外层测试轮结束**：保持现有控制器动作顺序，在本轮update／命令／输出领取／统计与断言全部完成后捕获。
此时Session已完成候选提交和每帧render cache，无正在执行的Owner事务；记录下一轮frame及下一命令序号。
首版不支持任意轮内或命令调用中途恢复。若以后支持命令后、输出领取前等边界，必须新增明确阶段及独立验收。
模态页存在不等于事务尚未提交：测试快照可以覆盖稳定等待页，但每一类载荷须有完整编码和校验；缺覆盖则显式拒绝。

| 状态组 | 捕获／恢复要求 |
| --- | --- |
| 固定数据 | APK与定义／地图／脚本哈希、规则语义版本；`rules`指针按身份重新绑定，不保存地址 |
| 世界与身份 | 地图／地表混合绑定、设施／人物／怪物／遭遇／投射物／任务、原序列表、稳定ID分配器、活跃及保留对象；顺序影响扫描者不得排序替代 |
| 共享进度 | 装备／库存／职业／成长／住宅、设施等级与经营值、现金／点数／人气／日期、报表／账本／任务记录 |
| 随机 | 模式、完整引擎状态或磁带及游标；只存draws或最初seed不足；捕获／校验不消费真实随机 |
| 页面与续体 | 完整栈、ID、父子关系、生命周期、初始化标记、计数／选择／名单／答案、脚本程序／pc／等待及上下文；不能仅凭raw页码重初始化 |
| 运行与表现事实 | 暂停／速度／held与下一输入、场景阶段、相机、cached_view／screen_position／render_position等影响方向或声音裁剪的值；不可按“缓存”名称盲删 |
| 一次性输出 | 队列及消费边界；首版外层轮结束应验证应领取输出已领取，异常残留拒绝捕获；扩展边界时保存待领队列并证明恰一次消费 |
| 自动玩家 | 策略版本、frame／next_attempt、任务月份／previous_task、bakery及退休ID、升级集合、经营与扩张月份、收入基线、声音累计和资源峰值等局部状态 |
| 审计历史 | 检查点内容及引用、历史检查数量／摘要与外部统计；不将进程内shared_ptr直接写入文件，也不在读取时追加重复历史 |

实施前必须由实际Owner／Session及控制器成员逐项形成覆盖清单，标明“保存／按已证纯规则重建／外部资源重新绑定／不支持并拒绝”。
新成员必须更新该清单与相应回归，不能靠当前短探针摘要推断字段已经完整覆盖。
原数值宽度、符号、浮点位模式、原序与ID语义显式编码；禁止写C++对象内存、指针或容器padding。

## 文件与事务建议

建议独立有版本的分区格式：固定头包含用途、schema、状态语义版本、来源清单摘要、边界、下一命令和负载摘要；
每个分区登记ID、版本、必需性、长度、摘要，计数与长度进入有溢出检查的总预算。具体字节宽度与预算值在字段清单后冻结。
生成提交用于追溯，不能单凭Git提交不同拒绝所有旧快照；规则／数据／策略／前缀依赖不兼容则明确失效，不自动迁移。
摘要用于完整性与对照，不代替引用和业务约束校验。

读取顺序：验证头／长度／预算→解码到私有候选→按稳定ID建立完整图→恢复原序／引用→核对页面与目录、占地和运行边界→绑定固定数据→一次提交。
不调用完整update“试着修好”状态，也不通过重新初始化页面补缺字段；已初始化但缺计数、错误父页、越界选择都明确拒绝。
失败保留当前Owner、随机、待领输出及外部控制器；文件恢复必须作为它们的联合事务。

写入使用同目录独立临时文件，完整写入和关闭校验后通过平台接入层替换目标；手动与自动目标分开。
写／替换失败保留旧有效档并返回明确错误；成功后不遗留临时文件。系统目录与数据若分文件，必须另设计代际提交，不能顺序写两份就声称原子。
文件替换原子性与掉电耐久性分别验收；C++17核心不依赖平台API，不在本次研究中承诺所有文件系统上的掉电保证。

未实现业务的原始载荷只有在边界已知、目录／引用不变且没有修改消费者时才可不透明保留。
APK的独立bytes分区有长度，未知tag却没有组长度可跳；实体关联段不能一边冻结、一边删除它引用的对象。
独立维护格式须显式区分可原样保留的可选段和未知必需段，后者拒绝；无真实原始载荷的新局不能伪造占位字节。
“持续可用”是当前声明范围内每批同步维护读写／校验／续跑，损坏档和不支持版本明确失败且旧档／当前世界不受损，不是任意版本永久兼容。

## 长测组织与中后期性能采样

| 层 | 执行时机与范围 | 保留的证据 |
| --- | --- | --- |
| 标准／短回归 | 按当前单Release批次规则执行；新增codec、恢复事务和相关功能边界 | 现有有效断言及独立oracle，不逐函数建target |
| 认证快照尾段 | 改动不影响已认证前缀时，从相关恢复点运行原控制器后缀 | 原尾段全部断言、资金／日期／完整状态差分、随机及一次性输出、引用与资源规模 |
| 完整自然链 | 生成／刷新快照，前缀规则或状态语义变化，相关集成风险或尾段差异需排查时 | 原新局可达证据、原里程碑和终点；不重复多个模式共有的同一前缀 |

快照清单记录：生成来源／规则与控制器版本、原种子、前缀命令摘要、断言结果、捕获边界／frame、完整状态摘要、资源规模、后缀命令及黄金摘要。
前缀认证与快照字节真实性分开：读档往返成功不能自己认证其前缀；新实现改变前缀消费者时，旧状态即使可解码也不能用于证明该变化正确。
资格不明时先审查依赖；影响前缀才定向重建，不机械按每次提交全重跑。夹具快照与自然生成快照分开标记。

优先捕获的自然里程碑：设施升级／晋级前后、住宅完工／年度授予与收税前后、商会交易后、扩张确认前及新区经营月。
在每个已认证点取固定逻辑调用数的中后期采样，比较相同输入后缀的CPU、墙钟、复制／分配、实例和账本／检查点规模。
采样预算与停止条件先定，允许同一内存前缀多分支比较；跨进程及下次会话复用必须等文件快照通过，内存复制不能解决跨批重跑。
每次记录审计检查点、退休可达对象、待领声音／效果、现金及任务历史；合法历史增长单列，不据有限窗口宣称永久有界。

## 下一批实施顺序与验收

1. **边界和控制器显式化**：将现有持续测试局部进度按职责整理为值，保持命令顺序与原参数；扩展现有continuous／runtime套件验证短分叉、稳定模态、暂停／双轮、输出和失败回滚。
   此阶段只解决同进程复用，为文件覆盖清单提供明确对象，不单独声称长链提速完成。
2. **共同codec与文件恢复**：按覆盖清单实现维护格式及候选校验；正常档与测试快照共用世界字段编码，分别验证策略。
   字节边界、资源预算、文件隔离故障适合集中持久化套件，既有业务规则组合留原套件；不重写战斗／建设oracle。
3. **认证中后期快照**：一次完整自然生成，比较不中断尾段与文件恢复尾段，跨进程重复读取至少两次；逐帧差分、最终摘要、原黄金里程碑均一致。
   包含到达已收费仍使用、任务成果／年度奖励、跨月、地图混合引用、待退休实体和页面拒绝风险；按对应尾段归属覆盖，避免再跑无关全链。
4. **批次选择与持续维护**：日常按风险消费认证尾段；新增持久字段同时更新读写／验证／往返／续跑。每批检查快照资格、资源规模和输出消费，阶段结束关闭进程并清理临时制品。

正式编码前需确认的是上述新增格式与政策：独立维护格式、外层轮结束恢复、测试完整状态／控制器、正常档稳定主场景且保留维护随机，暂不导入原档或迁移旧档。
这些选择不妨碍继续APK／Steam来源补证；本轮研究交付不需要先执行完整自然扩张。
