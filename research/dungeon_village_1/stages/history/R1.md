## 具体设计

拟使用 `research/dungeon_village_1/`，仅在研究实施获准后创建。维护行为规格、证据索引、候选示例与独立 CMake/CTest；生成的分析输出与工具缓存在隔离目录，不加入维护源码。

证据分为三类：

- 直接事实：来源文件/哈希、方法或字段位置、读写/调用关系、可复现输出。反编译代码也可能存在工具还原误差，保留工具版本和限制。
- 职责推断：列出支持的事实、替代解释及不确定性；不能改写成原作保证。
- Ark 候选方案：说明独立设计的接口、规则、参数和取舍，不宣称逐行还原原作。

工具候选为 APK/DEX 元数据只读盘点，以及经确认版本的 Java 反编译/调用关系分析工具（如 JADX）。具体命令、版本和必要安装在实施前确认；本设计本身不授予系统安装或生成反编译产物的许可。

先完成每个主题的行为规格和证据索引，再根据规格独立编写 C++ 示例。这里只使用“clean-room”描述独立示例与产物分离的目标，不声称已经完成团队隔离的正式 clean-room 流程。

示例仅依赖 C++17 标准库，使用独立命名空间；按真实规则创建模块，不提前建立全套空框架。定义/实例与稳定 ID 分离，只有一份权威状态；失败命令不留下部分修改，活动/任务结算要有明确完成或幂等标记。尚未核实的时间单位、奖励和容量不能以默认值掩盖。

拟按以下顺序推进：来源与工具盘点、六主题证据/规格、独立规则示例、针对证据和边界的测试、交接。某主题需要扩大资源解码或分析范围时先讨论，不边研究边扩大产品范围。
