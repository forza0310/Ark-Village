<a id="assets-目标与范围"></a>

### 目标与范围

玩家可见目标是先得到一个可运行的学习原型：使用 APK 中恢复出的原始像素美术，在 C++ 中展示地图、
建筑和角色，并支持 R1 已确认的建筑选择、放置、移动、撤除及角色访问状态。素材映射必须数据驱动，
以后替换同一逻辑键对应的自有图片时，不改领域代码。

本阶段包含：

- 只读解析 APK 内所有包含视觉内容的 `.dat` 归档，而不是预先写死归档名单。
- 恢复图片、图集/帧描述和必要调色信息，记录来源归档、内部路径、哈希、尺寸和转换。
- 保留原始提取文件，并生成原型实际使用的规范化副本和映射清单。
- 新建独立 C++17 可视原型，复用 R1 的领域示例，不直接翻译反编译 Java。
- 使用固定低分辨率画布、整数倍最近邻缩放，保留原作像素风格的观察条件。
- 形成可供后续自有素材替换的逻辑资源键和尺寸/锚点契约。

本阶段不包含：

- 将原始素材直接接入 Ark 产品或修改 Godot 工程。
- 复制反编译实现、复刻完整引擎、战斗系统或全部 UI 状态机。
- 重新绘制、AI 生成或自动修复原始美术。
- 音频提取、网络服务、APK 修改或运行时 Hook。
- 设施数值表、完整角色决策权重和存档字段恢复；它们分别留给后续 R2 阶段。

### 已定位的直接证据

- `d.a` 将资源槽映射为 `test/common/image/human/monster/weapon/effect/common2/map/event/xls/title/sound`。
- 主场景从槽 2 加载 `image.dat`；加载流程还会读取 `common.dat`、`common2.dat`、`human.dat`、
  `monster.dat`、`weapon.dat`、`effect.dat`、`event.dat` 和 `title.dat`。
- 资源读取前使用固定循环密钥 XOR；归档索引使用大端计数、名称、偏移、长度和标志位。
- 图形包通过 `img.inf` 列出图片，通过 `seb.inf` 与 `.seb` 描述精灵/帧；图片最终交给 Android
  `BitmapFactory`，且文件名兼容层将 `.gif` 映射为 `.png`。
- 原作逻辑画布和地图计算大量使用 240 像素宽度及 30 像素网格，可作为原型画布与对齐基线。
- 设计时环境未安装图形库；实施时用户已安装 raylib 6.0，并已补齐 pkgconf 3.0.7。

#### 推荐方案 A：raylib 交互原型

使用 Homebrew 安装 `raylib` 与 `pkg-config`，研究 CMake 通过 `pkg-config`/CMake 包发现 raylib。raylib 只
属于研究可视层；R1 领域库和提取工具仍只依赖 C++17 标准库。若以后不保留 raylib，领域代码和素材清单
仍可独立使用。

备选方案 B 不安装图形库，只由 C++ 生成静态 PPM/清单。它可以验证解码，但无法有效验证交互、锚点、
动画帧和运行时素材替换，因此不推荐作为本轮“原型代码”的终点。

<a id="assets-2-提取工具"></a>

#### 2. 提取工具

- `ArchiveReader` 在内存副本上执行 XOR，验证固定输入的校验值和全部大小/偏移边界。
- 工具先列出归档条目；只有检测到 `img.inf` 才按视觉归档处理。
- 提取图片、调色文件、`img.inf`、`seb.inf`、`.seb` 和与精灵显示直接相关的 `.opt`；无关表和音频不进入
  美术目录。
- 对可直接识别的 PNG 保留原始字节；需要转换的条目保留原文件，并另写规范化 PNG。
- 重名文件按来源归档分目录，不做静默覆盖。
- 解析错误、压缩标志、未知图片编码或越界一律返回明确错误，不输出部分目录冒充成功。

<a id="assets-3-素材清单与替换契约"></a>

#### 3. 素材清单与替换契约

`assets/MANIFEST.tsv` 至少记录：

```text
logical_key  source_archive  source_entry  source_sha256  normalized_path  width  height  frame  anchor  transform
```

原型只依赖 `logical_key`、规范化路径、帧矩形和锚点。用户后续替换美术时，可以修改清单或替换对应文件，
不修改建造、角色活动或结算代码。原始汉化名称只作为来源备注，不作为稳定 ID。

<a id="assets-4-c-可视原型"></a>

#### 4. C++ 可视原型

- 内部画布固定为 `240x240`，窗口默认整数倍放大并使用最近邻采样，不进行平滑缩放。
- 链接既有 `dungeon_village_reference`，以 `BuildingId`、`CharacterId` 和 `ActivityState` 作为权威状态。
- 渲染接入层维护地图格到像素坐标、逻辑资源键到纹理/帧/锚点的映射，不向领域库引入 raylib 类型。
- 首个场景显示地表、道路、至少两类建筑和一名角色；缺失映射使用明显占位框并记录错误。
- 支持建筑选择、合法/非法放置预览、放置、移动、撤除，以及角色预约、行走、抵达 `in_use`、完成后
  回到空闲的完整演示。
- 提供 `--asset-root`，允许切换到另一套具有同一逻辑键的自有素材目录。
- 原型不追求复刻完整菜单；调试信息显示在窗口标题或终端，不遮挡主画面。

<a id="assets-5-依赖与边界"></a>

#### 5. 依赖与边界

- 提取工具、格式测试、领域规则：C++17 标准库。
- 可视原型：raylib；仅研究 target 链接。
- 安装命令候选：`brew install raylib pkg-config`。确认前不执行。
- 不修改仓库根 CMake、Godot、产品素材或产品存档。

<a id="assets-预期停止条件"></a>

### 预期停止条件

- XOR 后的归档头、固定校验值或条目边界不匹配：停止，不做启发式扫描。
- 视觉条目使用当前设计未覆盖的压缩或图片格式：保留现场，提出解码候选后等待确认。
- `.seb` 语义与预期不符，无法可靠恢复帧/锚点：停止场景拼装，不用手工猜坐标冒充原作定义。
- raylib 安装、发现、编译或窗口运行失败：停止，不自动切换图形框架。
- 实现需要修改产品工程、根依赖或反编译实现：视为扩大范围，重新确认。

<a id="convergence-有限目标"></a>

### 有限目标

素材可替换；旅店、双格旅店、咖啡厅可选择、放置、两朝向移动/旋转、撤除；人物自主选择设施，
按真实多格绑定寻路、进入 in_use、完成并重新决策；普通到达收入与周期维护/报表可以观察和对账。
使用已有 C++ 规则和维护数据，不再恢复新玩法分支来扩大 R2。

采用独立原型状态聚合层，保持旧 R1 示例及旧自主模拟接口不变。相比直接改写旧 GlobalState，
此方案不让单点几何/旧结算夹具污染新接口；相比继续分解全部状态机，能优先完成可运行闭环。

<a id="convergence-集成契约"></a>

### 集成契约

1. 标准 C++17 原型模型仅依赖标准库和维护规则；raylib 仅属于窗口层。设施表严格读取，
   只消费 ID 28/29/36 已解释字段，未知列不执行。形状、定义 ID、实例 ID、图形分片互相区分。
2. 唯一状态包含地图底图、设施实例、人物、活动身份、到达统计、实例月销售、定义完成次数和账本。
   管理命令与整批时间推进在副本准备、成功后替换；错误保留包括 RNG/序号在内的全部状态。
3. 使用 R2-D 的绑定/距离场、R2-J 候选、R2-H 类别权重、R2-L 实例选择。当前只开放普通类别 1/2；
   未实现类别 3/4 等不加入此有限原型抽签，重新归一化明确为原型策略，不冒充完整原作 AI。
   多人独占使用是原型调度契约；候选实例排除已预约者，再作权重计划。
4. 使用 R2-E 邻接和 R2-C 经营推导；到达消费 R2-K，免费到达也推进统计且只执行一次。
   到达费用入账与人物/实例统计一起提交，不把人物累计消费统计当钱包。
5. 完成使用只记录观察次数，不执行未知退出效果或共享升级。访问计数在有限一轮活动后重置，
   重置时机为原型策略，未恢复原作住所/出口循环。时间速度、初始地图/资金/人物与周期长度均为夹具。
6. 月度夹具边界在该 tick 的人物更新后：到达收入计入当前周期，再扣维护、冻结报表、清零实例月销售、
   开启下周期。报表不二次发净额。它不是原作精确日历/月报动画顺序的证据；无任务奖励/存档。
7. 布局编辑取消当前路径/使用，不追发完成效果；取消前已经发生的到达收入不退款。
   原型允许建筑覆盖底图道路，邻接只统计当前未被覆盖的道路，拒绝占用人物当前格。
