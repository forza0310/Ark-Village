<a id="map-问题方案与自主决定"></a>

### 问题、方案与自主决定

既有单点模拟用外侧格作为到达点，而原作 `Tenant.z` 是有序占用格；路径类别与显示状态又是两个字段。
若只给旧网格增加“入口”，会把未知入口几何当事实，或者错误地允许人物穿过其他商店。

- A（采用）：新增独立地图绑定与全图最短路场，消费已有完整占地；原作可证实的准入单独维护。
- B：直接改旧原型所有资金、数值、几何与 AI。一次改动过大，且图形验收不可用，本批不采用。
- C：继续用外侧道路邻接作为硬门槛。与已读到的实际终点和建设后连通标记不符，不采用。

<a id="map-接口与边界"></a>

### 接口与边界

1. 标准 C++17；复用稳定 ID、占地几何。基础地图保留显示状态、五种路径类别；设施绑定含实例 ID、
   定义 ID 和分片。所有格均由唯一设施列表派生，不通过名字/图片尺寸推断。
2. 普通商店/住宅占用格为路径类别 0；入口类 4 可有出边；装饰类 3 不能普通穿行。
   无设施的类别 0/3 不加入展开集合。首个展开格可以额外进入显示状态 3/4 的邻格。
3. 单次搜索生成全图距离和前驱，用于设施可达格及路径回溯；离开格的权重仍为道路 5/7、空地 50/70。
   同成本稳定下标次序、硬成本上限/展开预算、整数/内存保护为 Ark 契约，不冒充原作平局或预算。
4. 构建地图与报告失败均无部分输出；带预算裁剪的搜索不提供可被误认为完整的可达性报告。
   带损坏结构/前驱的回溯拒绝，不越界、不无限循环。
5. 连通性检查是状态/提示，不自动变成建设拒绝。到达重新验证目标坐标、定义和实例身份；
   不新增独占容量/预约事实，不实现完整目标随机策略或原作 UI。
6. 现有 R1/R2-B 模拟继续明确保留为单点夹具；后续集成另做研究设计与真实图形验收。

### 方案与决定

A（采用）：在已有几何模块增加有序周边格，独立计算实例属性修正和来源记录；把结果交给既有经营

同类多个实例或把多格目标重复累计，都不采用。

<a id="neighbourhood-设计"></a>

### 设计

1. 从 1/2/4 格有序占地的外包矩形得到八邻域外环，按已恢复静态表次序输出 8/10/12 个周边格。
   越界周边格截去，占用格越界仍拒绝；不把周边格纳入角色路径。
2. 不可变定义保存 ID、形状、种类和属性修正项；实例只保存稳定 ID、定义和放置事实。
   定义缺失、重复 ID、实例形状与定义冲突、重叠或非法修正槽位全部拒绝，无部分输出。
3. 来源种类 2/3，目标仅种类 3；逐来源、逐外环发现相邻目标，同一来源→目标只应用一次。
   多个同类来源按实例分别生效；即使来源没有修正项，仍登记其身份，保持原作来源列表职责。
4. 商店每个外环道路格另给魅力 +2；道路唯一、地图内且不与设施重叠。
   道路对角邻接也参与属性修正，不能把它改成四邻接硬入口。
5. 先重算完整邻接属性，不累加到上次输出；输出价格/品质/魅力有符号宽整数，维护费不参与。
   溢出拒绝，属性封顶留给既有经营消费者；不复刻增减提示动画、瞬态 `H` 标记或 Java 回绕。
6. 提供检查范围的经营输入转换，重算值替换实例槽 0–2，不与旧邻接修正再次相加；保留其他输入。
   既有经营接口采用 32 位修正输入，超范围返回空输入，不隐式窄化或改变旧接口。

<a id="neighbourhood-验收"></a>

- 拒绝定义/实例/道路非法项，事务空结果；正负修正、整数上下界与经营消费者接续封顶。
- 固定种子随机布局与独立 Chebyshev 邻接集合判定差分；三套示例、两套原型回归、格式/链接和 Git。

1. 事件文本空字符串对应空矩阵；`&` 分指令，`,` 分有符号 32 位整数。按 Java trim 的 ASCII
   边界处理字段，支持前导正号，保留原文本。空指令/参数、溢出、非整数和读取预算超限均拒绝。
   结构接受未知 opcode，但不承诺能执行；预算为 Ark 保护，不是原作格式限制。
2. 工具的设施记录附加解析后的矩阵，第 33 列原文不变；固定 85 行逐项核对，26 个非空记录均为
   `6,100&40,<本定义ID>`，同时核对图标字段。不能通过矩阵结构检查宣称全部事件语义已恢复。
3. 实例保存“道具确认累计次数”和“自上次触发以来的跨月数”。月份推进只递增后者；道具确认先递增
   前者，再检查图标 2/3、次数至少 5、月份至少 36。满足后发出脚本触发意图并清零两项。
   不检查道具改良是否改变封顶后属性；道具实际扣库存和共享改良另行研究。
4. 纯函数接收值并返回候选，无调用全局解释器/渲染/库存。负计数/无效图标/溢出拒绝，无部分结果。
   使用有符号宽计数，不复刻 Java 回绕；批量月份参数由调用方提供真实跨月数，不推算日历。
5. 受限计划仅接受两条指令：opcode 6 带非负延迟、opcode 40 带当前定义 ID，图标为 2/3。
   空脚本明确 no_script，其他结构/未知 opcode 明确 unsupported，不跳过或猜测。
   计划记录定义、逻辑延迟和展示模式；不把延迟换成秒或渲染帧。
6. 不新增通用事件总线、奖励账本或存档；不声称原作具有活动 ID 幂等保障。原作实例计数可读写，
   示例只是值规则，产品持久化仍需独立设计。

### 方案与设计

A（采用）：必要原始道具表与严格读取器，独立候选事务组合已有经营/事件纯函数。
B：在 UI 内逐项改状态，失败保护弱；C：按显示名称猜适配或直接复制 Java，不采用。

1. 从已校验 `xls.dat` 读取 `item.txt`，严格 UTF-8/25 列/整数/唯一非负 ID；保留全部字段。
   原表发布到独立新目录，原件/清单按字节保存，既有目录不覆盖。只给有消费者的第 3 列类别与
   第 9–11 列三属性改良命名，其余未知不猜。
2. 原设施第 34 列作为按道具类别索引的适配值列表；固定数据核对全部长度 12、值 0/1/2，
   不把它叫按道具 ID 的效果数组。读取器仍保留原始文本。

4. 适配 0 原值、1 向零减半、2 加倍；三项写到定义累计改良槽 0–2，保留槽 3 与其他经营输入。
   用既有经营函数推导当前实例前后实际属性；显示差值为后减前，全部零时显示响应 -1，但仍消费和改良。
5. 与实例计数纯函数组合，确认一次道具消费递增一次；触发脚本意图不直接加人气。
   成功输出完整候选，共享更新只含改良数组，不含实例修正；调用方一次提交共享定义/库存/该实例。
   不在函数内寻找全局对象，不新增存档或事件队列。
6. 原作缩放经 float 转 int。固定小整数使用精确整数运算一致；巨大自有参数不重现 float 舍入/饱和
   或 Java 回绕，显式范围拒绝。整体候选原子性是 Ark 设计，不声称原作 UI 是原子事务。
