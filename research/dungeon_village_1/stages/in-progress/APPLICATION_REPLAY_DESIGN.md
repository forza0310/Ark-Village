# 完整应用研究快照与计分途中回放：待确认设计

2026-10-08，依据研究基线 `9ec4c1a5ff04beffc4da5327cc53c38117a7276b` 的只读分析。此文是新增文件范围的具体方案，**尚未确认、未编码、未注册测试**。已确认的[启动纪录方案](STARTUP_RECORDS_DESIGN.md)和[世界回放方案](../PERSISTENCE_REPLAY.md)继续沿用；原事实见[主角／纪录](../../rules/STARTUP_RECORDS.md)与[原存档](../../rules/PERSISTENCE.md)，维护状态与窗口原皮肤分别验收。

## 问题与范围

现有 `AVRSAVE1`完整保存世界Session与外部世界控制器，`AVRSYS01`独立保存应用系统纪录；`StartupTitleReplay`只接受没有world的标题。应用 `clear_rows_ / clear_ / clear_id_`不在世界Owner中，所以 `load_world_replay`明确拒绝已推进的raw17。仅保存计分页码、counter和phase不能恢复累计分、当前行及初始化捕获的最高分，也无法保证收尾事件／系统纪录只提交一次。

建议新增一个**研究专用单文件容器**，保存应用内存中的系统副本、完整WorldSession、标题随机／草稿／页面、随机交接、计分控制器与实际自然玩家Driver。完整指这些内存所有权及控制器字段，不指外部文件系统镜像，不兼容APK／Steam原档，也不扩大正常玩家存档的模态页范围。

第一版尾段仅继续已存在世界、其合法玩家命令和通关计分；允许只读返回标题／纪录观察的内存往返检查，但回放Driver不得跨捕获尾段执行新局、覆盖询问、load_world、load_world_replay或正常两栏保存等环境动作。原两栏文件不装入容器。若要复演这些动作，必须另设计两栏文件视图；只搬当前world而不搬两栏档不能称为任意跨局复演。

## 唯一所有者与完整字段

应用仍拥有至多一个可写WorldSession，WorldSession仍是世界唯一Owner。快照、准备候选和const审计可以暂时保留完整值，但UI与Driver不得取得另一份可写世界或绕过应用提交系统事务。快照不是业务领域的新Owner。

| 当前字段 | 快照处理与恢复资格 |
| --- | --- |
| `records_` | 完整保存last_slot、最高分／村名、资金峰值／村名、trophy、设施G／职业p继承字节及未知可选分区。复用系统格式校验，不能由world重新猜出跨局纪录 |
| `world_` | 可空；非空保存当前Owner、完整共同随机、原序引用及全部Session审计历史，复用已有replay格式与严格恢复校验，不清历史或按原APK加载规则清队列 |
| `draft_` | 村名、定义0name／sex／custom_name、选择栏位原样保存。草稿不覆盖已运行world的主角或村名 |
| `random_ / mode_` | 保存独立标题随机的完整引擎／磁带和游标，以及logic／title_presentation模式；模式须与调用者期望一致 |
| `page_ / record_page_ / decorations_ / requests_` | 保存应用页面、纪录页0／1、原序装饰人物名单及显式表现请求序号；恢复不重新抽名单，不将重画当请求 |
| `handoff_` | 可空的历史随机交接快照，合法引擎／磁带资格须核；不是当前世界随机的第二个权威 |
| `clear_rows_ / clear_ / clear_id_` | 三者成组保存，包含六行count／score、stage／counter／row／sum／captured_high_score／finished／new_record／trophy及实际raw17页ID |
| `paths_` | 不保存旧路径，不依快照写入玩家目录；按调用者显式传入的研究隔离目录重新绑定系统及两栏路径 |
| `error_` | 仅健康应用可捕获，要求该构造错误为空；失败返回字符串由实际Driver按其决策需求保存／消费，不据旧错误文字重做I/O |
| 外部自然Driver | 规范版本化载荷包含实际场景／seed／speed／phase、下一外层轮／命令序号、所有策略变量、有效与退休引用、输出消费状态、断言统计及来源资格。逐项审计真实变量后登记，不用几个摘要字段代替完整Driver |
| 字体、纹理、窗口句柄、OS按键／wall clock | 重新绑定外部资源，不存地址或真实时间。影响未来策略的输入脉冲／held与表现调用序号属于Driver或Owner必须保存，不能按“窗口缓存”名义删除 |

`return_to_title`当前保留 `world_`，因此“标题页面＋保留世界”是合法状态；不得要求world存在当且仅当page==world。返回标题时 `random_`取世界当前随机，随后显式标题请求可以继续推进标题流，而保留world的流不推进；两者不强制相等。`handoff_`可以来自另一新局，也可能在正常load_world后保留历史值，不能倒推为当前world起点。

当前完整原皮肤窗口若新增影响恢复的标题选择、演出计数或表单状态，须补入相应Owner／表现控制器字段清单及版本；本快照设计不会自动认证尚不存在的UI字段。

当前AST生成工具只覆盖WorldRuntimeState，**没有覆盖StartupApplication私有成员**。新批须对现有15个应用成员逐个登记“保存／由显式隔离路径重绑／健康捕获要求为空”，包括paths与error的排除理由；新增应用成员未分类必须使字段覆盖检查失败。应用字段规范清单单独形成schema身份，新增class成员不能仅靠world既有AST检查声称自动覆盖。外部Driver同样从实际变量逐项登记，不能只保存可见标题结构而漏掉clear或保留world。

## 捕获边界与输出消费

沿用**完整外层研究轮结束**：本轮应用update、玩家命令、实际候选提交、表现请求、声音领取、Driver统计与断言全部完成后，记录下一轮和下一命令。不得从world的轮内日历checkpoint开始完整框架，不支持文件替换或计分收尾函数调用中途捕获。

raw17等待阶段可以捕获；暂停、模态页或已返回标题不等于交易进行中。捕获必须拒绝 `scripts.executing_page`、未消费 `sound_requests`、未消费的Driver一次性计划／返回结果以及任何正在等待异步操作完成的边界。不能为了保存临时调用 `take_sound_requests`丢弃输出。

恢复不调用 `open_records`、update、页面初始化、收尾脚本或引用收集来修补字段，也不重新抽取随机。既有world中持续显示效果、通知与退休引用按已有字段保存；一次性计划／声音在首版边界必须已消费。计分完成的声音及事件4／5／6按真实应用提交结果继续，不能因恢复重复播放／领奖。

一次系统写失败若已返回，旧应用／world／clear和随机仍未提交，Driver已记录该失败及下一动作时可作为完整轮末候选；文件锁、权限等故障注入属于测试环境，不装入玩法状态。恢复只能继续已保存的旧控制器，不伪装成已完成stage7。

首阶段为当前raw17条件验收登记实际Driver身份 `application-clear-conditions-v1`：保存fixture资格、场景／seed／speed、阶段、next_frame／next_command、下一confirm脉冲、稳定clear页ID、入口系统最高分／村名、事件4／5／6基线、声音累计／输出已消费标记、检查数和停止条件。其驱动规则只有已批准raw17输入与有界续行，所有实际循环／策略变量加入载荷，未知phase或未消费结果拒绝；没有空占位Driver。自然通关Driver登记独立身份及实际经营变量，条件档不能借用natural身份或证书。两种资格均可使用同一完整应用容器，但不混用同一个策略版本。

## 必须通过的关系校验

字段合法、摘要相符和关系可达是不同检查。先复用完整world／系统／随机／文字校验，再检查下表；不通过有效断言修改原表或重置累计分。

| 关系 | 首版强校验 |
| --- | --- |
| 页面与世界 | page==world要求world存在；标题／配置／纪录可保留world。草稿slot与系统last_slot各自0／1，不无条件相等；配置尚未开始时二者本来可能不同 |
| 标题名单 | 未在records页应为空；logic模式为空；records要求requests>0。使用保留world的human_presence构造当前资格池，没有world才用冻结初始status；非空池允许原序交换后的至多5人子集，空池后备名单按原flags1定义序。不得重新随机验证 |
| 请求与随机 | 校验完整流及请求序号；不得以“累计requests×当前候选池大小”强推最低抽数，因为历史池可能不同，也可能经历world→title交接。自然资格另由Driver／认证链证明 |
| 计分三元组 | rows/state/id同时存在或同时缺失；存在时page==world、栈顶为相同ID的存活raw17，world未暂停；world页计数／phase与clear.counter／stage一致 |
| raw17入口 | 三元组缺失而栈顶raw17，只接受当前应用可接的未推进入口：counter／phase缺失或0；已推进但没应用控制器明确拒绝 |
| 六行来源 | 已初始化rows须与当前冻结计分world的纯只读六行投影一致，binary32舍入保持原算法；不是用保存的sum猜六行 |
| 计分阶段 | 复用现行计分严格资格：stage0–6、各阶段counter范围、row与阶段对应、sum与已累加行一致；特别区分stage3 counter44与45，45恰已累加一次。存在的控制器不得finished／new_record／trophy提前置位 |
| 最高分捕获 | 当前计分期间system.high_score尚未提交，clear.captured_high_score须等于保存的应用记录。stage7不是可保留控制器；系统提交失败保留此前stage6候选，成功后原三元组退休 |
| 系统与world | 从正常load_world的“用外部系统覆盖world现金镜像”行为分开。完整应用恢复保留两者捕获值，不再执行install_loaded。健康应用提交边界中现金镜像应与记录一致；系统继承字节与world.system_unlock_data并非总相等，新世界／载入旧栏位须按实际入口验收，不能补全局相等守卫 |
| Driver与Owner | 外层next_frame／命令序号、应用模式、world存在、实际任务／页／退休引用、策略阶段及输出消费须匹配；外层frame不等于world.simulation_steps，倍速也不能以二者相等校验 |

现有 `prepare_startup_clear_score_page`把纯校验与一次推进写在同一函数。建议抽出其已有资格为只读验证帮助器，并由推进函数和恢复复用；不在读档时“推进一次看能否成功”，也不另写第二套累计／舍入规则。

## 单容器格式与复用

建议新magic `AVRAPP01`，格式／应用语义均从1开始，用途固定为研究应用回放；与 `AVRSAVE1 / AVRSYS01`不能混读。固定头保存来源dataset、world codec schema、应用字段清单摘要、外部Driver身份、捕获边界版本、下一外层轮／命令序号及追溯版本；Git提交仅作追溯，不据提交不同机械失效。

| 分区 | 内容与实现取舍 |
| --- | --- |
| 1 必需 | 外层metadata及边界、Driver身份；精确版本和规范整数宽度 |
| 2 必需 | 现有AVRSYS01系统副本的完整字节，保留未知可选分区 |
| 3 必需 | 新应用控制字段，含world存在标志及标题／计分全部状态；不含路径、指针、纹理或可写world副本 |
| 4 条件必需 | world存在时嵌入现有AVRSAVE1 replay Session完整字节，当前Owner与原序审计保持原格式；不存在时明确拒多余分区 |
| 5 必需 | 外部实际自然Driver规范载荷；空载荷及不支持语义版本拒绝 |
| >=1024 可选 | 与引用无关的附属研究资料，原样往返；未知必需段拒绝 |

每段都有ID／版本／必需标志／长度／摘要，整体有摘要；重复ID、越界长度、保留ID、尾字节及版本不匹配拒绝。嵌套world使用固定桥接controller身份 `application-world-session-v1`及非空版本标记；其controller_state仅标识所属容器，不重复外部自然Driver。嵌套next_frame与外层同值、purpose必须replay；不能利用正常格式清除held／审计。

目前world `encode_file/decode_file`及system `encode/decode`都在各自匿名命名空间。实现只需增加**内部纯字节桥接**，供容器复用相同写前自检与候选恢复：不通过临时写world/system文件再读取来序列化，也不复制字段编码算法。`startup_world_file_io`继续负责容器单文件独占临时写入、刷新和平台原子替换。world字段未变不改原schema，应用字段清单独立版本化；不改旧证书或改世界黄金oracle适配新容器。

建议暂保留现有128MiB整体文件上限、world64MiB单Owner编码、完整world及审计共享的16Mi节点／128Mi分配预算。系统仍4MiB，应用字段与Driver各1MiB，可选段单项1MiB、最多60段；所有段及开销受容器整体128MiB约束，嵌套world可用空间会小于原单世界档。嵌套world／history只允许一份，不能为每段重置Owner预算。解码时存在容器字节、嵌套暂存和C++对象的并存，实际RSS须另采样，不能把wire预算叫总内存上限。

**自然通关180月量级的审计历史存在明确超预算风险。** 当前排程估算至少288000合格轮／720份历史；已有61月样本为244份历史，旧38000档83份历史约34.5MB，平均约416KB，按旧平均估720份已约300MB，尚未计未来状态增长。以上是规模估算，不是已走完通关或已生成300MB档；4096份数量上限不是首个障碍，节点／分配预算另行约束。

第一阶段具体完成**现行预算内的完整应用raw17条件快照**及短跨进程恢复，不要求先重写通用历史架构才能补齐当前计分控制器。自然路线本身继续独立推进，其合法预算内前缀可保存为候选；不能预先承诺完整自然通关历史已可归档。后续先采样真实段的历史数量、序列化增量和尺寸，不删历史或临时增预算凑通过。确实超限时保留最近合法候选及现场，无损分区／内容共享／流式校验等历史方案另设计、确认和验收；本方案不自动授权这些决定。

## 加载与隔离文件事务

API只提供研究容器保存、私有候选读取和最终联合安装，不增加玩家正常档入口。候选包含应用全部状态及Driver字节；外部自然Driver需用自身严格解码器完成结构、引用及策略关系校验后才能提交。新捕获默认独占发布新容器，目标已存在即拒绝，不覆盖旧证书／候选；输出路径同样在本研究隔离工作范围内，不能与当前应用系统／两栏、只读源快照、trace或证书重叠。

恢复调用者显式指定本研究包内的隔离目录。目录本身可存在且为空；系统路径、两栏路径必须尚不存在，三者不同且位于该目录内。路径由调用者重新绑定，快照旧路径不参与写入。源快照与隔离目标／trace／证书不得重叠；核weakly_canonical、symlink、hardlink及Windows大小写别名，不靠字符串前缀判定包含关系。环境检查失败只返回错误，不删除、备份或覆盖任何已有目标。

准备顺序：读容器并验头／摘要／预算→系统与完整Session纯字节解码→应用控制字段→所有关系→外部Driver解码／检查→准备全部可noexcept移动／swap的最终候选。**不能调用当前StartupApplication普通构造后先读隔离系统默认值，也不能走install_loaded重写镜像。** 用封闭的持久化访问桥接构造健康私有应用；它不向UI提供任意纪录setter。

最终提交只把保存的系统副本原子发布到**一份新隔离系统文件**，成功后noexcept联合安装应用和外部Driver。现有 `replace_save_file`在Windows使用带REPLACE_EXISTING的MoveFileExW，不能直接用于这次“只创建新目标”的发布：须新增内部无覆盖单文件出口，同目录临时文件保持独占，Windows最终移动不带REPLACE_EXISTING；如果其它进程在预检后创建同名目标，最终发布必须失败、保留该文件。新研究容器捕获复用此无覆盖出口；以后隔离系统业务更新仍使用既有替换职责，两个出口明确区分。其它平台须有真实无覆盖发布支持，未接平台不能宣称已验。

恢复不写两栏world文件，world仍来自容器内存；未来研究保存仍是独立具名操作。若系统新目标发布失败，调用者当前应用／Driver不变、源容器不变、两栏不存在，临时文件按既有RAII退休。解码失败尚未到文件写入，不产生系统文件。成功点在新目标已发布后，不允许因后续可避免的分配失败产生“文件成功、内存失败”，全部分配及可能抛错的校验在发布前完成。

这不是两个rename的跨文件原子事务，也不改玩家系统／世界。恢复成功后各次现金／计分提交只更新隔离系统；原输入文件hash与旧应用字段在回归中独立检查。文件原子替换与掉电耐久性继续按现有平台证据分开。
