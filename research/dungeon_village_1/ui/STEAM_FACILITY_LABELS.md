# Steam设施详情74的左右软标签

2026-10-10。补齐[设施详情合同](STEAM_FACILITY_DETAIL.md)保留的softLabels74表值。固定Steam具名cctor／Init／Update2独立证据见[工作包](../work/steam-facility-labels/README.md)，无原窗口输入实验。

SubForm.cctor创建101项int[][]：raw74在0x1032A27C新建长度2的int[]，只将元素1写2，元素0保留数组初始0；在0x1032A2C7取得外数组偏移0x138=0x10+74×4并写入。最后0x1032AAE6发布到SubForm静态区偏移0。因此**softLabels[74]=[0,2]**，不随“定义预览／实例／第一页／第二页”换成另一个表项。

AppData.cctor的15项字符串表中，0是空字符串，2是原日文`戻る`，在0x102689D0发布到静态区偏移0x4C。74的Init共同入口读取该pair，转成AppData的两字符串，SetSoftLabel(left,right,null,null)：左空，右返回，第三／第四标签null。原文本翻译链与屏幕最终语言另验，不能把日文原literal说成当前中文屏幕已观察。

| 输入角色 | Steam实际消费 |
| --- | --- |
| 确认 | Update2直接检查逻辑pulse0x100000；不通过空的左标签0，也没有查询IsPushSoftLabel(0) |
| 左软键 | 74没有用其空标签实现“确认”。不能因为左标签槽存在就创建一个可点确定按钮 |
| 右返回 | 无确认时调用IsPushSoftLabel(2)，匹配当前右标签原字符串后检查并消费pulse0x400000；成功Pop |
| 可重定位的返回标签 | 通用IsPushSoftLabel不是固定只看右边：若当前左字符串恰匹配2，也会查pulse0x200000。当前74初始左为空，不满足此分支 |

单参IsPushSoftLabel(2)委托双参并传额外key=0；这不是数字键0，也不会赋予左空标签任何确认含义。通用helper按当前显示标签字符串作相等比较，和纯粹按屏幕左右点击位置不等价。底层Keypad查询会消费脉冲，既有顺序仍保留。

raw74先查确认，再查返回。预览确认Pop；实例第2页确认返回false，不执行取消；实例第1页确认交接到道具／商品／入住等消费者。这解释了“右侧返回”“底部可操作提示”“页面确认”是三条不同路径，不能统一成两个默认确认／取消按钮。配置门控的keyState0x40替代确认仍沿上批限制，未根据位号推物理键名。
