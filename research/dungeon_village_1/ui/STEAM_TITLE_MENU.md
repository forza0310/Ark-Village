# Steam标题菜单与选档合同

2026-10-09。本批只核固定 Steam DLL 的具名方法、metadata 和既有资源索引，不含新窗口观察，不替代 APK 规则来源。不要求产品照搬反编译实现。

## 来源与适用范围

DLL SHA-256 为 `9cf4bb10d55afe6898bf9b82d9016d328cce623a7e4743623eb3df720b55ab1a`，metadata 为 `80e17b3c1f7b7a844d64be27918e16cacfab05d70d7f33c0a61e45d830d7a369`。EVIDENCE.json（本地核对材料，不随仓库交付）记录 18 个唯一方法的最大读取范围，共 25,168 字节；多个 `_draw`／`Update` 前缀不重复计数。另复用此前完整 `_addTouch` 的 6,752 字节证据，不重新宣称本批发现了旧范围全部行为。

VA 均基于静态 ImageBase `0x10000000`，不是运行地址。下文 W/H 是 GameView 的游戏逻辑宽高，不是 OS 窗口外框、客户区或截图像素。手动／中断的原保存顺序沿用[正常保存合同](../rules/PERSISTENCE.md)，本批不执行原档加载或写入。

## 标题状态与初始化

`TitleForm.state_` 为 0 时是标题两项菜单，为 1 时是选档。字段 `selectSave_` 是横向两栏槽号 0/1；`selectSaveType_` 是纵向两行，**0 中断，1 手动**。初始化读取 `system.int[8]` 作为槽号，默认选中手动行，菜单选择为 0，随后应用音量／静音并 `PlayBgm(0)`。

`ChangeState` 只改 state 与软标签，不清菜单／槽号／行号选择。cctor 中软标签索引为：正式版标题 `[5,0]`、试玩标题 `[0,0]`、选档 `[0,2]`。索引对应的最终可见文本本批未解，不能单凭数值命名左右软按钮。`Init` 还重建标题20个装饰槽、重置标题计数；调度与随机仍按[标题人物合同](STEAM_TITLE_ACTORS.md)处理。

## 标题菜单绘制

草边之后设绘制原点 `((W-240)/2,0)`。`titleFrame < 75` 时在 `0x1020E930` 提前返回，普通菜单与选档窗尚不绘制；语言按钮位于此门槛前，不能把整个标题视作不可输入。

state0 的逻辑布局如下；行号 r 为 0、1，`Y=H-60+22*r`。

| 元素 | 原逻辑参数 | 消费锚点 |
|---|---|---|
| title图片1底图 | `(137,H-72)` | `0x1020F369` |
| 选中背景 | `(152,Y,73,16)`，RGB `(255,150,107)` | `0x1020F401` |
| 行文字 | `TextLayout.Draw(157,Y,63,16,lineSpace=0,anchor=0x22)`，RGB `(96,87,0)` | `0x1020F49D` |
| title图片3选择指示 | `(127,Y-13)` | `0x1020F4F0` |
| 标题行触摸基矩形 | `AddTouch(id=0,x=138,y=Y-3,w=100,h=22,value=r)` | `0x1020F522` |

原字符串正式版为 `スタート`／`ハイスコア`，试玩第二项为 `正式版へ`；实际语言经过翻译调用，本批不把日文 literal 写成 Steam 中文显示事实。Steam 使用矩形文字布局，不能套 APK 的文字中心点调用。

在 Steam 平台类型4、标题位于栈顶且 state0 时，尾部依次请求 `SteamInputManager.DrawButton(g,20,20,2,callback)` 与 `DrawKeyboardButton(g,21,51,2,callback)`。这里仅认证 helper 实参，不认证最终 OS 坐标／弹出平台界面。

普通 `_draw` 路径末尾没有恢复入参原点。debug 信息分支先保存当前原点、设零、再恢复它；末尾共用地址 `0x101C9750` 的真实字节是 `C2 00 00`（`ret 0`），不改变原点。自动符号输出的 Steamworks 名字属于 IL2CPP 共用地址别名，不能当作实际平台业务调用。本批普通菜单分支未发现新增直接随机请求，不能据此宣称整个深层绘制调用树没有随机。

## 选档小窗

state1 且标题栈顶时绘制；栈顶是 id4、且 `SubForm.IsMenu()` 时保留后方选档窗。令 `V=trunc((H-240)/2)`。窗口调用为 `DrawWindow(g,198,146,V,LT("セーブスロット <0>/2",slot+1),-12)`，不能把两个尺寸参数替换成测得的截图宽高。

两侧 common SEB3 箭头分别用 frame3／frame0，位置 `34-(frame%20)/5` 与 `203+(frame%20)/5`，y 均为 `V+54`；标题栈顶且应用 focus 时才注册 id1、value16/18。类型说明位于 `(120,V+69)`，中断行为 `中断データから再開`，手动行为 `セーブデータを読込`。

两行基线 `R=V+84+47*r`，r0 中断、r1 手动。外框调用为 `DrawBox(29,R-12,210,R+29)`，后两项是该 API 的边界坐标，不写成宽高。

| 项目 | 中断行 r0 | 手动行 r1 |
|---|---|---|
| 日期存在哨兵 | `system.int[11+slot]` | `system.int[6+slot]` |
| 名称 | `system.string[6+slot]` | `system.string[2+slot]` |
| 资金文本来源 | `system.string[8+slot]` | `system.string[4+slot]` |
| 图标裁片 | `IMG_SL[1]` | `IMG_SL[0]` |
| 空行 | `中断データなし`，无行触摸注册 | `空きスロット`，允许触摸 |

非空行选择背景 RGB `(200,200,255)`：非日文 x75、宽102；日文 x79、宽94；y 为 `R+6`、高14。名称用矩形 `(75,R+6,102,14)` 与 anchor `0x22`。触摸基矩形为 `(0,R-5,240,51)`，id3、value `0x20000|r`，无显式 TouchOption。日期整数按年 `D/10000`、月 `(D%10000)/100`、周 `D%100` 拆解，显示各加1，文字格式 literal 为 `10,,+2`，位置 `(34,R+24)`；资金经 ParseLong 与 `YEN("Ｇ",value)`，右对齐到 `(201,R+24)`。选中且栈顶时，common SEB22 指示位于 `(181,R+12)`。

空手动行继续注册相同行触摸矩形，文字中心 `(126,R+15)`，选择指示 `(177,R+21)`。空中断行不注册行触摸，最后以黑色、srcRatio128 盖 `(29,R,181,41)` 后恢复默认渲染模式。页底提示 `データを選択してください` 在 `(120,V+176)`，RGB `(125,158,116)`。

图标来源 common图片177。Steam自己的 `img.inf` 将177映射到逻辑名 `saveload.gif`，真实归档成员是 `saveload.png`。不能因通用图与 APK 完全相同，就用它代表所有 Steam 语言版；既有清单中该图为 APK1项与 Steam10项（含 zh-CN），中文图字节不同。

| 数组 | dx/dy | sx/sy | w/h | 非空／空行目标锚 |
|---|---|---|---|---|
| `IMG_SL[0]` | 0 / 0 | 6 / 3 | 16 / 16 | `(39,R+6)`／`(39,R+15)` |
| `IMG_SL[1]` | -4 / -2 | 2 / 23 | 25 / 20 | 同上 |

先加目标偏移，再以源裁片绘制。两个6元素初始化块均从 Steam cctor 的 RuntimeFieldHandle 独立解析，记录在ICONS.json（本地核对材料，不随仓库交付），未借 APK 填值。选中指示的common SEB22为`finger_l.seb`，其图片引用仍为70号`finger_r.png`，不能按SEB文件名虚构不存在的`finger_l.png`；[Steam启动正式素材](../assets/steam-startup/README.md)已包含此依赖及十种saveload原路径，产品可按清单复制，毋须读取work或原容器。

## 输入与后续分流

标题 state0 的 Up／Down repeat 分别检查 `0x20000`／`0x80000`，两项取模2均切换选择；确认 `0x100000` 在菜单0时 `ChangeState(1)`，不会直接开始新局或读档。菜单1在正式版推入 id3 的 RecordForm，试玩版跳正式版入口。

选档 state1：Left／Right 的 `0x10000`／`0x40000` 切槽；Up／Down切中断／手动行。若选中中断且对应日期为 -1，立即强制选择手动行；不能保留不可用中断行作为有效确认目标。无现有 dialog 时：

| 选择及日期状态 | 确认动作 |
|---|---|
| 手动空行 | `NewGame()` 推 raw91 配置子页，尚未创建正式世界 |
| 中断非空行 | `ContinueGame()` |
| 手动非空行 | 推 raw20 菜单，x136、y=`97+47*type`，载荷槽号写入子页 `+0xB8` |

软标签2返回标题 state0，保留选择值。已有 dialog 的结果0→ContinueGame、1→NewGame、2→把对应日期置 -1 再 SaveSystem，最后清 dialog 引用。这只是静态结果分支，未认证 raw20 的完整可见选项顺序或真实删除授权。

ContinueGame 二次检查日期存在，清软标签，然后 `LoadGame(slot,auto=(type==0))` 并切 GameForm；异常分支清世界数据指针并提示。**原加载非事务，不能把原函数的失败行为当作维护 Owner 的安装契约。** `ProcessBackKey` 属于应用退出资格／系统标志路径，与软标签2的选档返回不同。

触摸分发25项跳表已独立读为数据：id0→`0x1023C940`，id3→`0x1023CA42`。其后100字节跳表不再线性伪装成指令。

- 标题 id0 的 ENTER2：向栈顶表单写 `type=0x30000,value=row`，选中菜单；UP1：发送逻辑确认，缺自定义键时为 `0x100000`。其它事件不走这两个动作。
- 选档 id3 复用 OnTouchDlgSel：ENTER2 与 UP1 都先写 `type=0x20000,value=row`，仅 UP继续确认判定。这里 AddTouch 没有 option，既有 `_addTouch` 的 id0/id3 路径不生成 marker，SurfaceBase 保留空 option；`TouchComponent.Check(0x10)` 对空 option 返回 false。因此本页正常注册行的 UP直接发确认，**不是设施75带 `FLAG_MARKER=16` 时的首次 UP仅标记规则**。
- GameView.Set 将值分成高16位类型与低16位有符号选择值，写入栈顶 TouchValueAccessor；TitleForm.SetTouchValue 消费0x20000/0x30000。原 setter 未见越界保护，维护实现仍须拒绝非法行号与父页，不能仿照越界写。
- 此处描述组件 ENTER／UP语义。窗口单击是否产生哪个事件、焦点、裁剪及平台事件转发继续遵守[Steam输入合同](STEAM_INTERACTIONS.md)，不能将任意鼠标 MOVE直接写成 ENTER。原 `_addTouch` 还叠加绘制原点、margin、比例与裁剪；本表矩形是调用者基矩形。

## 维护建议与未闭合项

建议正式标题表现层按两个状态、两个槽、两个行定义只读输出；把菜单选择、选档行选择与确认分别映射为 Owner 请求。标题／选档无需复用普通列表两次UP规则。世界恢复仍经过已批准的完整应用快照／Owner事务路径，原存档目录不得被表现示例修改。

本批未实现原型皮肤，未新增窗口观察；后继[raw20菜单与确认合同](STEAM_SAVE_MENU.md)已补原序、默认“否”的两类询问、原result返回与取消、组件9输入、菜单SEB帧及raw1布局。实际显示译文、平台设置与键盘helper、真实窗口缩放最终坐标、语言资源运行选择、通关计分自然路线仍分开待验。上述静态菜单完整度不等于完整原版皮肤已验收。标题人物调度、随机交接、字体窗口框沿用各自合同，不能把本批静态方法覆盖数当全游戏分析完成率。
