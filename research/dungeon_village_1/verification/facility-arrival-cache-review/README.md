# 建设与邻接变化后的到达价格：来源核对和修复边界

2026-10-09。回应[产品请求](../../../../docs/reference/RESEARCH_REQUESTS.md#facility-arrival-price-cache)。本批只读固定APK与当前维护实现，不读取产品原始测试数据、不运行原游戏、不改C++／格式、不构建。产品420／440、300／320差异是请求方提供的观察，本研究独立确认其代码成因；不将该观察写成Steam原窗口数值事实。

## 结论

这是维护缓存失配，原规则不需要重新决定：APK `a/o.a(int,c.m)` 每次使用定义属性I加当前实例邻接s，再作上限裁剪；普通到达调用槽0即时取值。维护却将到达价格另存 `RescueFacility.price`，建设后 `refresh_map` 更新邻接及提示而没有同步该字段，造成只读报价已变化、实际收入仍用旧值。

品质没有同样的长期实例缓存：当前完整世界退出路径在command24通过最新邻接、共享等级／提升和职业人数派生槽1，再传入ShopExitInput。魅力与维护费也不应因本次修复新增另一份缓存。现存的price必须在地图邻接更新成功时同步，装饰增加与移除、移动两端都要覆盖。

事务上，建造、编辑、住宅替换已有外层私有State候选；新辅助仍应先完成本地价格投影再落回传入候选。任一缺源、溢出或后续扣款失败不能泄漏资金、随机、notice、实体退休、price或surface。地图刷新自身不应抽新随机或发额外音频。无需改原表或用现在的报价重算过去销售。

## 初始世界与快照资格

真实初始投影 `startup_world_projection.cpp:140–171` **已经**按完整邻接和初始非零人物的职业人数派生价格，不是简单写定义基础价。运行时随后再次`initialize_startup_world_neighbours`；修复需逐实例比较前后价格/邻接是否一致，不能先假定新局黄金必变，也不能仅因初始检查相同就认证所有晚期前缀兼容。

`startup_world_codec_fields.inc:907`明确持久化price。旧快照可能已经因建设或退休收取错误金额，修后读入只重算价格不能修复此前现金、目标选择、随机和历史；**禁止加载后暗补或换头重签旧快照当当前自然路径**。

最小必须提升世界状态语义3→4，容器格式1及Owner字段结构可保持；正常世界文件与世界回放均拒旧语义。应用包含活动/保留Session及四目录不可变blob，必须对所有世界引用执行新语义校验，隐藏目录也不能漏掉。为清楚退休当前应用自然前缀，建议应用语义6→7并更新应用清单；系统目录格式2和无行为变更的Driver结构不必机械升版。若选择只升世界语义，必须证明无世界标题应用可兼容且所有世界blob必被核验，不能仅检查活动Session。

当前12月运行可保留为修前语义6／世界3历史证据，不再追加24月前缀；修复后先重建最短420轮／首月和相关操作尾段。无需立即再从头跑12／24月。原文件、证书保留原字节并登记退休原因；输入完全等价的小片段若未来单独认证复用，必须有明确资格，不能沿用当前应用证书。

## 本批后集中验收建议

扩展现有 `startup_world_building_test.cpp` 的建造／移动／撤除与共享升级组合，现有fixture能表达Owner路径，不新建一次性target：

1. 真实规则、真实建造入口，普通营业设施与装饰邻接：只读报价、price一致，然后驱动合法到达，核现金/该店销售/人物统计同增；断言独立取自原表端点与已核加成，不能只以同一getter相等作为oracle。
2. 装饰移走或撤除后再合法到达，收入回落；另一方向新邻店上升。包含`notices=false`过渡与多实例同定义，不误改其他位置的邻接。
3. 等级／共享道具后仍按各实例邻接封顶；满上限、负修正、装备价替代及免收费不重复收入。现有底层用例保留，只补跨域接线风险。
4. 缺源／超界及后续扣款拒绝，完整Owner、随机、资金、页面、notice与实体不变；初始化对齐检查，品质退出读取最新槽1。
5. 存读档与应用尾段往返验证新价格持续，旧语义明确拒绝；按改动范围集中跑现有套件，然后交付冻结checkpoint，由产品复验受影响布局收益。
