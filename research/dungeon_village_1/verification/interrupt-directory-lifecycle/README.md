# 中断／手动目录生命周期：具名写者复核

2026-10-09。接续[自动中断预研](../interrupt-save-continuation/README.md)，定向复核系统日期 `6/7/11/12`；不重解25分区、不读取账号／玩家档、不启动原程序、不修改维护格式。本专题是静态来源增量，不是新的动态实验。

## 可采用的结论

固定APK与当前Steam样本的正常保存均按 `auto` 与当前槽选中**一条**日期目录，保存该游戏记录后更新对应日期／资金／村名，再保存系统。所核普通继续、加载入口和场景激活直接路径没有“读取中断后清中断日期”的写点；也没有在已核保存目录尾部清另一条中断日期。不能据此新增“手动保存清自动”或“读后自动删除”的维护规则。

Steam场景初始化的确有系统整数清零，但清的是 `int[16] = SYSSAVEI_REVIEW`，不是自动日期11／12。标题普通删除将所选目录日期置-1而保留载荷；普通玩家UI只从手动行打开继续／重开／删除菜单，不能因为底层索引表达式可算自动行，就声称正常自动行也开放删除。

以上负面结论只覆盖列出的具名入口和直接已追踪写者，**不是全程序所有别名、间接调用、异常、迁移或平台变体均无清除的证明**。没有单槽平台证据，不能由当前两槽推演单槽／多槽清除差异。

特别防止两种偏移误读：`sysSave+0x10` 是整数数组字段，数组对象自身的元素起点也为0x10；`int[8]` 的元素位移是0x30、`int[16]`是0x50。必须先追到AppData的真实sysSave字段，再识别数组，不能把任意 `[寄存器+0x40]` 都当成系统对象。

### 另有诊断下载写者，不属于普通保存

同一 `TitleForm.Update` 在配置与输入条件下另有下载分支：`0x1020CC52` 调Http连接，`0x1020CC9D`写当前手动记录，`0x1020CCE0`将 **`sys.int[6+slot]=300`**（机器码立即数 `0x12C`），随后写相应目录字符串并在`0x1020CDB8`保存系统。

因此“TitleForm.Update只有删除一个日期写者”不成立。本批只登记该分支的存在；没有发起网络请求，没有认证其当前玩家可达性、配置名称、下载内容或字符串含义，不把它接入维护普通菜单。它也不是读档／保存后清自动目录的证据。

## 维护影响与后续

目前系统2／应用6已确认的“保存与隐藏分别只改所选目录”合同保持不变。原版先写游戏再写系统、加载先改全局，失败安全弱于维护唯一Owner与单系统提交点；不能为模仿原样撤销维护事务保障。

下一步自然中断候选应继续按[中断预研](../interrupt-save-continuation/README.md)讨论原日历位置的捕获、外层轮提交与主场景重新激活。精确回放仍在完整外层轮末；本次没有授权／设计新的轮内恢复格式，也没有实现自然自动档产生者。

如果以后取得冻结的同槽手动／中断前后实档，可对四日期和四载荷分别做动态验证；缺动态结果不阻止复用本次已证写者。不要求用户为当前目录合同另跑窗口，也不从旧真实档统计推断所有版本政策。
