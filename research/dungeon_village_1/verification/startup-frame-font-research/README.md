## 交付范围与使用顺序

扩展既有 `startup_skin.hpp/.cpp`，不新建Owner、随机、文件字段或CMake target：

- `startup_window_skin` 返回两个边线图元、非空木纹块、标题带和可选标题文字锚点。绘制顺序固定为边线→木纹→标题带→标题阴影→正文。
- `startup_content_skin` 返回标准白色内容框的填充、外线、内线和四个原SEB角。它覆盖原style0，不把蓝线框或common图片121替换分支当成相同绘制。
- `StartupSkinRect.rect` 一律使用半开像素大小。`outline=true` 时画内部1像素线，不能再次增加宽高。图片计划仍沿原图块桥：SEB内部偏移只能加一次。
- 标题文字仅接收调用方实际测得的整数宽度。这里不提供替代字体、字形、测宽实现或演示文本。

查询输出由既有 `startup_world_visuals` 套件直接消费；实际产品迁入仍需冻结维护提交与原资源来源。标准测试不产生文件，可选CPU拼图扩大为760×930，下方依次展示200×170纪录框、220×186新局框与222×155计分框，均无假造字体和业务值。拼图只展示窗框图元，不能宣称完整页面：计分背景、嵌套内框、人物和文字尚需按各页原顺序组合。上批600×660冻结图不覆盖，本批根验收写入新的 `work/startup-frame-font-delivery/`。

## 几何交叉：差1像素的来源

原 `d/a.java:2774` 给标题窗的宽W、高H、垂直附加offset和style；sceneTop为 `b.c.n`。原逻辑画布为240，页面外层平移由调用者另外处理，不能把DPI物理坐标传入：

1. `left=120−W/2`。H>216时inset=0，否则inset=sceneTop+2×style。
2. `top=(inset+240)/2−H/2+offset`，每个整数除法单独向零截断。
3. 源 `o.d(x,y,w,h)` **覆盖w+1、h+1像素**，不是Android Paint的stroke，也不是填满矩形。`o.java:1013` 实际画四个1像素宽的填充长条。
4. 转换后外边线为 `(left−1,top−2,W+2,H+3)`，RGB(89,103,91)；内边线为 `(left,top−1,W,H+1)`，RGB(239,239,221)。两者都是描边，内色不能误称整个窗的底色。
5. 木纹common28从源(0,0)按40宽重复，目标从(left,top)开始，高H；尾块取剩余宽。W恰为40倍数时原Java循环还发出一个零宽请求。维护计划省略此无像素请求，不将其计入有效图片数，不伪造一条裁40的尾块。
6. 标题带common29目标(left+1,top)，源(left+1,0,W−2,17)；它沿原横坐标裁取，不能缩放整张240宽标题带。
7. 测得整数文字宽T后，x=120−T/2。阴影N=(44,54,105)在top+3，正文M=(247,253,247)在top+2。这些是原文字入口锚点，尚非Canvas文字基线。

标准内容框来自 `d/a.java:474`。传入left/top/right/bottom后，两个y分别加 `sceneTop/2`，w=right−left、h=bottom−top。源 `o.f` 填充是通常的半开大小；源两个 `o.d` 转换后分别为(left,y,w,h)和(left+1,y+1,w−2,h−2)。颜色依次(247,253,247)、(172,202,179)、(222,234,225)。

四角common SEB6 / image30，以左上、右上、右下、左下为顺序：

| frame | 源裁片 | SEB偏移 | 外锚 |
| --- | --- | --- | --- |
| 0 | 0,0,4,4 | 0,0 | left,y |
| 1 | 4,0,4,4 | −4,0 | right,y |
| 2 | 4,4,4,4 | −4,−4 | right,bottom+sceneTop/2 |

四帧都无翻转。原图8×8，不能拿整张当一个角，也不能自己镜像后再消费SEB翻转。填充／线后才覆盖角图。

## 字体：目前已证到哪一层

原 `kairo/android/ui/n.java` 持有Android Paint；`i/h.java` 负责语言资格和字符串转换。以下是固定APK的局部实现事实，不代表Steam字体：

| 项目 | 已核事实 | 仍不能推定 |
| --- | --- | --- |
| 字号 | 参数0/1/2对应12/24/30；其它非负字号参数可直接成为大小。缩放函数再按比例量化实际Paint字号 | 原12像素字形等于任意系统字体12px |
| 字体族 | slot0/1为MONOSPACE、slot2为SANS_SERIF；样式映射normal/bold/italic | Steam使用同族、同字库或同字重 |
| 选择资格 | 日语资格路径优先normal，检查“ぃ”“ト”宽12、“.”和“ｲ”宽6决定是否保留monospace；非日语走sans bold；Typeface有静态缓存 | 汉化APK显示中文就必走某分支；设备fallback字库恒定 |
| 文字转换 | 测量和绘制均经过 `h.b`：反斜线→¥、控制退格符路径、翻译查表和换行/制表处理 | 对原始UTF-8字节计宽即可，或者仅字符数×固定宽 |
| 测宽 | slot2或Android SDK12分支调用Paint.measureText；其它分支调用getTextWidths并按半字号单位量化，累加后向整像素收口 | measureText与getTextWidths分支永远相等 |
| 整数/浮点 | `n.a(str)` 在浮点宽+0.01后转int；`n.b(str)`保留浮点。窗口标题用前者，而部分居中/右对齐正文用后者 | 全部文本都可共用整数居中 |
| 基线 | `o.java:167` 中对齐后 `baseline=top−Paint.ascent−0.9`；绘制时开抗锯齿 | 入口y就是baseline，或者raylib ascent天然相同 |
| monospace绘制 | 半宽字符逐个0.9横缩，0.1描边；连续全宽片段0.2描边；绘制分类门槛与测宽量化的常数不同 | 单次DrawText与该路径等价；把字体名字改相同就可像素一致 |

原测宽类保留1024个float的临时数组；本批未新增长字符串能力，也未认证此长度之外的原行为。9/10/11号临时字号和 `h.b()` 页面资格必须与调用者交叉，不能仅由截图反推当前Typeface与基线。

字体的下一最小证据是Steam实际字体资产/动态fallback与绘制方法的对应、同一文本同一逻辑字号的实际advance/ascent；完整窗口截图只能支撑视觉比对，不能独自证明字体源或内部测宽。

## 维护保护、验收与边界

窗框查询只接受W=3…240、H=17…240，确保木纹和标题带可从原PNG裁取；内容框宽高至少4。原Java没有这些维护保护，不能记为原版限制。所有坐标运算先提升为64位并检查最终范围和相关原整数中间量，拒绝坏尺寸、负测宽、反向端点或溢出，不复制原Java溢出的结果。H>216时不求值未使用的sceneTop/style，保留原资格分支。

既有套件新增：原资源哈希/尺寸/索引、原角SEB记录、整数奇数与负sceneTop、216/217分支、40倍数空尾块、反向/溢出拒绝、CPU描边末像素/木纹与标题带裁片、实际内容框双线颜色。不会加Owner重复测试、无关长测或独立target。根负责集中构建和最终通过记录；此说明本身不宣称新回归已跑。

资源规模：新增图元每次标题窗最多7个有效图片请求（6木块+1标题带），标准内容框固定3矩形+4角，不保留跨查询缓存。CPU图像用既有RAII持有者释放，输出由拼图与审核消费；这不代表原世界账本/历史永久有界。源PNG/SEB没有复制修改；统计和哈希见 [EVIDENCE.json](EVIDENCE.json)，生成方式见 [audit.cjs](../../tools/startup-frame-font-research/audit.cjs)。
