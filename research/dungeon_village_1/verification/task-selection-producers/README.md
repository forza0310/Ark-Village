## 结论及证据范围

`a/m.x`是标题初始化时按原序加入的30个flags4任务定义，**不是完成过的任务历史**；`a/m.u`同时加入6个flags2特殊任务。原世界重置不清空这两个目录。复发选择还要经过事件60、40票号、当前探索阶段及对应怪物`a/k.y`条件，因此“目录存在”与“已生成／已完成30个复发任务”不同。

原`a/k.y`由初始flags1、普通怪物介绍以及读档恢复产生；开放态`p`不是它的别名。普通介绍在发出介绍脚本／raw89页面后就将`y`置真，不等待玩家确认89，也不是第一次击杀才置真。

`a/m.v/w`在本固定DEX全部具名直接写引用中只有静态初始化的0。消费端保留`v==1 && kind==1`时取`u[w]`的分支，但本次没有找到启用1或改变索引的直接写入者。不能把这一结果扩大成已排除反射、JNI、外部修改或其他版本的全程序不可达证明。

`Lc/b::k()I`完整195 code unit已保存，可逐寄存器重核：

1. 按原顺序考虑下一个非flags4怪物：要求后者阶段≤当前探索阶段、前者p1、后者p0；前者成长`v>=8`才开放后者，遇到这一对后结束首轮扫描。
2. 逆序收集最多5个已开放、非flags4怪物，并调用一次按候选数抽签。
3. 所选怪物`!y && !flags1 && !c/n.h()`时进入介绍。`h()`是活动任务判断，不能把“没有任务定义”当条件。
4. `t`非空才执行定义介绍脚本；然后构造raw89、绑定所选怪物、交页面框架；最后pc190置y=true并返回定义ID。

`Lc/n.f`复发窗口pc335–447已核：先抽100，与40比较；要求事件60已见；再逆序遍历静态x，以任务阶段≤当前探索阶段且怪物y筛选，最多6项；非空才按名单size抽签并跳到真正任务创建。无资格或空池回普通阶段目录。这里的任务flags4与怪物flags4属于不同定义命名空间。

## 发现的维护缺口及本批修正

发现时基线`2ea65e21685dd963ff47cb9757c9505883920eee`：`StartupWorldRuntimeState.task_replay_order/task_special_selection_list`注释写“新局空”，新局构造只填81项任务进度；工厂虽已转出／写回两个向量，却没有正向填入6/30目录。因而已介绍怪物和event60存在也可能错误落回普通池。**已有任务选择消费者不等于其首次初始化接线完整。**

父会话核实并授权按实现缺口修复后，本分支仅在原新局Owner的同一tasks遍历内按flags2/4及原定义序填入目录，修改两个注释；v/w原0及怪物y初值／投影不改。独立世界入口也取得目录，不依赖是否经过研究标题窗口。

扩现有`startup_world_runtime_tasks_test.cpp`，不新建target：独立字面6/30目录oracle、event60资格下seed3实际复发工厂与writeback、同seed无事件的普通选择、y与p不同的边界，以及显式mode1/index5目录接线。事件与y／模式输入明确是条件夹具，不冒充自然原游戏路线。没有删改旧断言。

本子分支未构建／运行CTest；父会话集中验收，并负责快照语义退休、旧回放证书失效范围和正式交付。修前24月／在途更长采样不能因“暂时没看到复发”自动保留当前语义认证；本页不为其背书。

## 检查与剩余边界

本次DEX脚本语法检查与实际扫描通过；APK/DEX绑定、定义数量、窗口预算均已检查。JSON中的C++源hash采于修正前，用于保存发现现场；重跑脚本会重新记录运行时的当前文件，不能误称保持修前字节不变。旧源可按上面的基线提交复核。

本批只新增小型脚本、一个有界派生JSON和本说明，不新增原游戏副本或构建树；无后台任务、游戏或编译进程。原引用资料继续保留；维护任务历史、现金记录等仍不宣称永久有界。
