# Steam标题菜单、四条存档目录与应用事务：已确认设计

2026-10-09。用户已明确采用本文方案并授权连续实现、验收；本文件是维护设计，不是原版格式。最初设计批只写本文，没有读取原档或运行窗口；后续系统版本2与目录事务开始实现，验收结果另行登记。下列具体方案整批沿用，不为每个方法再次确认。

## 问题与依据

当前[应用](../../prototype/STARTUP_APPLICATION.md)只有标题／覆盖询问／配置／纪录／世界页面及两个`worlds`路径；系统`AVRSYS01`版本1没有手动／中断的目录记录。[应用回放](../../prototype/APPLICATION_REPLAY.md)语义5明确不包含外部两栏文件，恢复只发布系统文件。不能把`worlds[2]`机械改成四个可覆盖文件，就宣称标题原输入、四条目录、文件失败回滚和跨局回放都已经解决。

已确认[应用回放方案](../../stages/in-progress/APPLICATION_REPLAY_DESIGN.md)明确：跨捕获尾段执行新局／覆盖／正常保存／加载，需要另设计槽位文件视图。本文正是该后续设计。当前世界语义3和世界字段schema保持基线；现有128MiB上限、完整历史、单Release动态构建及唯一Owner约定不变。

来源分别为[Steam标题与选档](../../ui/STEAM_TITLE_MENU.md)、[Steam raw20／raw1](../../ui/STEAM_SAVE_MENU.md)、[APK标题调度](../title-owner-contract/README.md)、[原存档](../../rules/PERSISTENCE.md)、[声音来源](../../ui/AUDIO_REQUESTS.md)。Steam作为UI目标，APK仍为世界／旧逻辑轨迹基线。Steam的75绘制门槛不能覆盖APK100更新准入，尚未闭合的Steam更新计数和平台事件顺序继续标待证，不猜成相同常量。

已核原版事实：

- 两槽各含中断行0、手动行1；目录日期为-1才代表隐藏／空，不是扫描世界文件是否存在。
- 中断非空直接读取；手动非空进入raw20；手动空进入raw91草稿。空中断不能确认，选择后强制回手动。
- raw20原序为继续／重新开始／删除。后两项推默认选“否”的raw1；“是”才允许返回父页消费预设结果；“否”或取消留原菜单。raw20取消必须覆盖旧待返回结果为-1。
- 重新开始的“是”只进入配置，实际开始才建立新世界并更新最后槽号，不提前覆盖旧游戏文件。
- 删除只把所选目录日期设-1并保存系统，旧世界字节及其他三条记录仍在；不能实现成删除文件。
- 原保存先游戏记录、后系统目录，两者没有共同事务。维护须采用明确更强的安全策略，不能照抄这一失败行为。

## 目标与分批边界

一次确认覆盖：标题／选档／raw20／raw1的应用状态；四条目录和路径；新局／加载／隐藏／具名正常保存的事务；标题B0和真实世界激活G；完整文件视图的应用回放。批准后可以按纯控制器、存取接线、皮肤三批验收提交，不为每个方法再次询问。

这不批准原档导入、迁移、擦除、Steam云、联网、平台退出／失焦保存或任意轮内快照。真实自动中断的产生者与raw14仍要沿原时点接线：原自动档位于世界已更新、日历未消费的轮内边界，现`normal`轮末档不能假称它。第一批四目录的中断读取用明确标记的合法条件文件认证；自然产生中断档未完成就必须如实标注。新增目录存储应预留“已登记载荷用途”字段，不能用未知用途占位冒充可加载档案。

## 应用状态与输入接口

建议保持`StartupApplication`协调应用事务、Session拥有唯一可写世界。应用对外仍只返回const视图；独立纯控制器返回意图，不直接读写磁盘、初始化世界或领取声音。

| 状态 | 最小内容与约束 |
| --- | --- |
| 标题根控制器 | 根模式菜单／选档、菜单行0/1、存档行中断／手动；槽号继续唯一使用`draft.slot`，不另存可分歧的selectedSlot |
| 当前子页 | 明确kind、稳定递增页ID、父ID、初始化／活动／关闭标记；受支持路径至多标题→raw20→raw1，不引入任意深度通用UI栈 |
| raw20载荷 | 打开时槽号、固定手动kind、菜单行0…2、结果-1…2、可选确认子页ID；所选存档目录身份／修订摘要必须与父载荷匹配 |
| raw1载荷 | 覆盖或隐藏两种具名原因、父raw20的ID、按钮0/1默认1、结果-1…1；答案只能消费一次，越界／错父／过期ID拒绝 |
| raw91返回 | 配置父页身份及取消／实际开始结果；保留已获批的自定义姓名后切性别保名、取消保留草稿策略，不据此补写Steam动态事实 |
| 动画与纪录 | 保存真实需要推进的菜单frame、纪录动画计数及具名框架相位；复用已有标题20槽和随机，不以绘制次数重建；纯派生几何不存档 |
| 文件目录 | 系统记录持有固定2×2条目录，见下一节；应用保存已读取系统的修订／摘要用于写前冲突检测 |
| 一次性声音 | 新增应用级有序typed输出队列；应用拥有的世界在公开命令边界将当次输出移动到此队列，独立Session仍保留现有接口，不能同时向两份队列复制同一请求 |

输入接具名的重复方向、确认脉冲、软返回和组件ENTER／UP；按具体页合同执行，raw20不能套设施75的首次UP仅标记。标题上下、选档四方向的独立判断和子页返回优先级必须来源化；纪录的left／else-if right／else-if back与普通菜单不同。过期选择、非法slot、非栈顶输入、已初始化却缺载荷均返回显式错误，不靠容器异常。

建议新接口以`apply_title_request(expected_page_id, request)`准备**整个一次请求**的候选：背景更新／随机→导航→实际子页结果→必要文件事务→联合安装。既有`advance_title_background`与`open_records`分别成功后再调用的组合，不能冒称本接口单次失败会回滚前一个独立请求。logic／title_presentation继续分开；未取得Steam完整调度前，Steam皮肤可先消费已证的静态视图，不能替换APK随机轨迹。

## 四条目录与最小磁盘协议

建议应用从“系统＋两条任意世界路径”改为显式的**应用存储根目录**。四条是逻辑记录，不要求四个可覆盖的固定文件名：

```text
<application-root>/system.avr
<application-root>/worlds/world-<SHA256>.avrs
<application-root>/write.lock
```

`system.avr`仍是独立系统文件，建议`AVRSYS01`升版本2：保留原纪录／继承和未知可选段；新增必需分区3，含系统修订号和固定四条目录。每条含`packed_date`（-1或原零基日期值）、村名、保存现金、可选世界引用（文件SHA-256、字节数、已登记用途）。slot/kind由固定数组位置决定，不重复保存。现金用受校验int64，显示再格式化，不把原资金字符串当作维护数值格式。

空记录初值日期-1且无引用；隐藏已有记录只改日期-1，保留名称／金额／引用和旧世界字节。可见记录必须有完整引用，实际载荷不在绘制时读取。目录元数据与世界内容可以独立；维护新保存产生时要求对应，打开标题时不擅自用世界日期“修好”系统目录。确认加载时才按引用读取、核字节／身份／用途、完整语义验证。

世界仍复用已有正常`AVRSAVE1`，其字节不可变，以内容摘要命名；相同内容可复用同一文件，多个目录可指向它。文件名由已校验摘要构造，不接受容器里的任意路径。此设计不修改世界codec、不把菜单和系统目录塞进业务Owner。

根、系统、worlds及所有发布路径须沿现有大小写／硬链接／符号与重解析点／Windows特殊名拒绝。应用只操作显式研究根，不发现或猜测真实Steam保存位置。CLI的旧`--slot0/--slot1`组合应显式报接口已变，不把缺中断参数静默补成旧格式；低层独立世界保存接口仍可用于原有研究场景。

没有选择固定四个覆盖文件的原因：先替换某world再写系统，系统写失败已经破坏旧世界；反过来则目录指向尚未写好的内容。临时备份后两个rename也不等于原子提交，增加journal会扩大恢复状态。不可变世界字节＋一个系统引用提交点是本草稿的最小推荐方案，但它是**新维护决策，须确认**。

## 单一提交点及失败行为

存储根采用短时写租约：本批只实现并验证Windows独占文件句柄，释放随RAII，不靠持久PID猜是否仍在写。`write.lock`为零字节普通文件，存在本身不等于持锁；其他平台明确拒绝，后续有实际需要再实现，不预建锁框架。

保存／更新系统的顺序：

1. 取得写租约，重读系统修订和摘要；与应用当前观察值不符则显式拒绝，保留旧应用并等待具名重新读取，不合并另一写者的新世界或目录。
2. 在内存完成世界、目录、系统、页面、随机和输出候选；准备所有可能分配／失败的对象，递增修订不得回绕。世界需落盘时先编码、用当前读器完整自检。
3. 将新world字节无覆盖发布到摘要路径；若同名已存在，必须验证字节一致才复用。旧world绝不替换。
4. 用现有同目录临时写闭／刷新／回读／原子替换提交**一份**新system。它是可达目录的唯一提交点。
5. 仅在系统提交成功后noexcept安装准备好的应用／Session／页栈／随机／输出。失败不离开询问页、不消费结果、不装载半个世界、不发激活声音；重试由仍存在的原状态重新准备。

系统发布前失败：旧system和其引用文件不变；本次新建、尚未引用的world由本次所有权凭据回收，不删除预存的同hash文件。清理遇权限错误须报告未引用文件残留，不能假称没有磁盘副作用。崩溃留下未被system引用的内容不是一份半成功存档；冷启动以系统引用为权威。掉电耐久性与事务可见性分开，未获证据不承诺所有文件系统掉电零损失。

系统成功后旧world清理是独立维护：只考虑本次替换前确实由应用持有且四条目录（包括隐藏项）均不再引用的文件；不得扫描删除用户任意文件／历史实验。清理失败返回“已提交、待清理”，不能对用户报保存失败后又重做业务。活动世界历史无磁盘引用，外部应用快照含自身字节，均不能因清理被破坏。删除菜单只隐藏记录，因此其引用文件绝不因“不可见”进入回收。

新局开始、正常读档只需提交last_slot／系统镜像，再安装准备好的世界，不保存新world。覆盖同意仍只进入raw91。隐藏操作只提交system中的一个日期；两次回答或过期页请求拒绝。目录可见但world损坏时，保留旧应用、world、目录和选择，返回维护加载错误；不仿原加载失败清掉世界。

## 标题B0、激活G与一次性输出

真正初始化标题成功时入队`replace_bgm(0)`；冷构造健康应用和世界→标题的实际重入分别有一次初始化。纪录／选档／raw20／raw1／配置的返回不是重新初始化，不能每次重画或子页返回再发B0。

真实新局或加载激活成功时，按已核G的当前任务／遭遇状态选择B1/B2，追加在该事务实际产生的较早输出之后；失败不发，不按ID去重。首次健康构造后直接开始若调用者尚未领取，B0和B1顺序都保留，不能用后者替换队列中的前者；真正播放时B操作的幂等由播放器负责。

应用`take_audio_requests`和旧ID投影接口仅消费同一应用队列；世界当次输出在应用提交候选时转入，绝不同时保留两份可再次领取副本。公开命令成功边界要求应用所持world当前待发队列为空；历史checkpoint里的声音仍按已批准完整codec保存，不清历史。独立Session行为不变。录制／捕获需两个边界都已消费；精确恢复不执行初始化、G或额外B0，先恢复控制器，下一次具名请求才推进。

本批不把失焦、语言窗口、平台键盘、正常暂停推定成播放／停止操作；通关初始化StopBgm等其他来源仍有独立缺口。输出接口完整只指本次已列来源，不宣称原全部音频已闭合。

## 应用快照、恢复和预算

建议在同一次应用版本升级中保存上述控制器／应用声音字段及**完整四条目录的文件视图**，包括隐藏但仍被引用的world字节。去重只可按完全相同字节共享一个blob，不删除有效历史、隐藏记录或未知可选段。原始绝对路径、锁句柄、平台输入和播放器不入档。

`AVRAPP01`可维持格式1但升下一应用语义（当前5，预计6），增加一个必需槽位视图分区；应用schema登记所有新增与嵌套字段。内嵌系统升版本2；独立标题控制器和有关Driver也升级，明确普通世界动作／菜单文件动作各自的资格。旧应用1–5、旧系统1／旧标题控制器明确拒绝，不扫描旧world自动生成目录，不修改历史证书。若实现开始前版本已推进，使用新的实际版本号，不机械抢占6。

现有正常世界语义3／schema本身不需因标题字段而改变；旧独立世界短轨迹能否继续使用按其依赖复核。应用旧前缀必须保持旧资格，不改头迁移。初期先一套当前短前缀及raw20／raw1中途文件尾段认证，不再反复从头跑自然十六年；本次尚未批准的格式不得先用新号产长前缀。

现有回放总文件128MiB、控制与Driver各1MiB、系统4MiB、Owner64MiB、16Mi节点及128MiB估计分配预算保持；内嵌最多四份正常文件与活动Session／全部历史共同计数，不为每份重置节点预算。槽位字节先按长度／总量检查，再解码；四条引用可逐份验证，只有活动Session安装成可写世界。超限明确拒绝并保留源，不能丢弃隐藏档／长历史来凑通过。正常磁盘每个world仍沿已有单文件预算；实际最多四条可达引用及本次待提交文件的空间另报告，不把单文件上限当总目录空间上限。

恢复固定到调用方显式研究parent下**尚不存在的新应用根**，例如`<parent>/restored-application/`。不能继续声称只发布system而实际需要再写四条world：先在同文件系统的独占临时子目录准备system＋全部引用blob、逐一核验，在安装前再次核根／protected_paths／源文件别名；最终使用真实无覆盖目录发布，把完整文件视图一次变为可见，再noexcept安装应用与Driver。Windows平台原子无覆盖目录发布需独立测试；其它平台没实现同等语义则该恢复模式拒绝，不用exists后rename或逐个复制假装同等保证。

任何发布前错误保留旧应用、Driver、源容器和既有目标，回收本次独占临时目录；目标竞争创建时发布失败，不覆盖对方。恢复成功后各次菜单保存沿上节单系统提交点；回放比较完整应用／目录字节／引用blob集合、实际操作＋ID序列及Driver，不能只比较当前world摘要。

## 集中验收与可先推进的工作

扩既有应用、系统文件、持久化、codec及进程隔离套件，不按菜单项新建target。验收分工如下：

| 主责层 | 必须证明的行为 |
| --- | --- |
| 纯标题／菜单控制器 | 原行序、空中断归手动、原方向优先级、ENTER／UP映射；raw20继续、覆盖、隐藏、否、取消和再次进入；默认否、父选择保留、错页／越界／过期答案拒绝 |
| 应用事务 | 覆盖是仅进配置；实际start不覆盖旧world；四条目录互不误改；隐藏留原字节；源损坏、写冲突与失败保留原world／随机／页栈／输出 |
| 文件协议 | 系统2与四目录关系、不可变字节复用、别名／硬链接／重解析点拒绝、系统发布前失败、发布竞态及重试、成功后的清理不回滚已提交结果 |
| 输出与引用 | B0只在真初始化、成功激活G只一次、已有声音保序、双接口互消费；菜单退休后无悬挂结果，隐藏仍引用world，音频不长期重复积累 |
| 快照与恢复 | raw20选中／raw1否决前后／已隐藏目录及新局草稿的规范往返；错误子页关系、坏blob与旧版本重签拒绝；新根发布失败无旧目标改变 |
| 短跨进程 | 一次真实支持范围前缀→两次新进程，相同命令加载／隐藏／重新开始并保存，比较完整应用、四目录文件视图、Driver、声音、随机和源hash；条件中断档不得升级成自然自动保存证据 |
