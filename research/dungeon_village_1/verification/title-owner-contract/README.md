# 标题 Owner 接线的 APK 输入与生命周期合同

2026-10-09。本批仅只读分析固定 APK 1.0.8 的反编译源码，为[标题表现研究](../../ui/TITLE_PRESENTATION.md)的显式 Owner 请求补齐接线依据。未操作原窗口、原档或产品；下列内部字段、原方法顺序不升级为 Steam 已证行为。来源窗口和文件哈希见 EVIDENCE.json（本地核对材料，不随仓库交付）。

## 两种标题页面与输入顺序

`b/h.h=0` 是标题菜单，`h=1` 是存档选择；两者在同一个原标题对象中。应用枚举 `title` 不能单独表达这两个状态。`j` 是开始／纪录两项选择，`f130b` 是两档选择，`o=0/1` 分别为中断／手动记录。现有 `draft.slot` 可以作为唯一档位，但须明确绑定 `f130b`，不能再落第二份可分歧的 slot。

原 `h.b()` 的受支持主干严格为：

1. `super.b()` 推进父 `aA`；`l` 饱和递增，`f132f` 回卷递增。
2. 新 `l<100` 时先消费确认并拉至 100；仍不足 100 则返回。因而旧 `l=98` 的确认只跳动画，旧 `l=99` 的确认仍可进入菜单动作。
3. 全部人物移动／退休，之后生成门槛和随机抽取。新生不在本轮移动；这一部分早于菜单导航及开纪录的名单抽取。
4. 原调试长按更新、共享指示图元 22 更新；本批可明确排除调试，但指示图元不能伪称由 `f132f` 驱动。
5. 根据 `h` 处理输入和子页返回；再处理调试末尾。

| 模式 | 源输入顺序与作用 | 重要边界 |
| --- | --- | --- |
| `h=0` | `up=131072` 改 `j`，再 `down=524288` 改 `j`；二者是独立 `if` | 同轮上下均真会翻两次，不能用 `else if` |
| `h=0` | 消费可能存在的 `k` 返回，再退出／外链，再确认 | 本批排除退出／外链时须写明未实现分支 |
| `h=0,j=0` 确认 | 只执行 `a(1)`，切到同对象的存档选择 | 不等于立即新局、加载或配置页 |
| `h=0,j=1` 确认 | `a(new e())` 压入新纪录对象 | 纪录初始化名单抽取在随后子页初始化，不是标题出生前 |
| `h=1` | left 65536，再 right 262144 改 slot；up，再 down 改 `o` | 四个方向各自独立，之后才判断中断可用性 |
| `h=1` | `o=0` 且系统索引 `slot+11` 为 -1 时强制 `o=1` | 不可停留在无中断的选中状态 |
| `h=1` | 若 `k` 非空先处理返回、清 `k` 并 `return false` | 本轮不继续消费确认或取消；人物已提前推进 |
| `h=1` 确认 | 有中断则直接读；有手动档则打开 raw20；空栏则打开 raw91 | 从手动已有档直接进入配置会漏掉菜单／覆盖确认 |
| `h=1` 无确认 | 返回操作 `d.a.a(2)` 执行 `a(0)` | 确认优先于取消；回标题菜单仍保留原 `j` |

`ui/a.b(mask)` 消费脉冲；`ui/a.c(mask)` 读取方向重复准入而不消费确认。Owner 输入宜接已归一化的具名重复方向布尔值和确认脉冲，不以 OS 当前按住或绘制次数猜原准入。

`h.b(int,int)` 是 UI 回调：高 16 位为 131072 时直接写 `o`；196608 时直接写 `j`；其它交父类。该回调自身无界检查，维护入口必须显式拒绝越界，不能复刻越界写后数组异常。这里仅证明回调落点，不能由此宣称 Steam 点击／双击过程已证。

## 子页返回与重新进入标题

| 场景 | 原对象／调度事实 | 维护建议 |
| --- | --- | --- |
| 冷启动新建 | `d/a:276` 建 `new b.h()`；构造分配 q/u，`f132f=0`；Java 默认父 `aA=0` | 初始化完整控制器 |
| 第一次标题初始化 | `h.a()` 设 `h=0,j=0,slot=J[8],o=1,l=s=t=0` 并新分配全零 q；重置默认草稿 | 显式初始化请求；它本身不是合格更新 |
| 纪录／配置压栈 | 标题保留在栈下，框架只更新栈顶 | 父标题 q/l/f132f 均冻结；重画不补更新 |
| 子页退休返回 | `framework.c` 标子页 4，父若为 3 改为 1；退休处理轮先返回；后续 1→2 后正常更新 | 返回不重新执行 `h.a()`；首个实际标题更新才推进计数／随机 |
| 世界转标题 | `g:11306` 替换为既有 `av.k`；已不在栈的标题重新以生命周期 0 入栈 | 对同对象调用原标题初始化，重置 q/l/h/j/slot/o；`f132f`、父 `aA` 未在 `h.a()` 重置，不可一并清零 |

框架 `a(aVar)` 将其余页面标为退休，但若目标本已在栈会走另一分支；本次“世界转标题重新初始化”依赖原标题已从世界替换路径退休，不能概括所有 `a(existing)` 都重置。`h.a()` 未显式清 `k`，不要凭全量对象重建声称逐字段原样；当前支持的新局成功路径会替换整个页面栈，待返回的 raw91 指针不应原样序列化。

raw20 返回给标题的 `K=0/1/2` 分别为读取／覆盖后新局配置／删除；取消保持 -1。raw91 取消明确 `K=-1` 后退休。原标题在处理 raw20 的 `K=1` 时调用 `f()` 创建新 `k`，然后又无条件置 `k=null`；这是源中的指针时序，维护实现应以显式子页种类／返回载荷表达有效生命周期，不能用一个可空地址复制此行为，也不能据源指针为零认定新配置页不存在。用户已允许取消配置保留草稿的维护策略，Steam 短名实验无需补测。

## 纪录计数与父计数

纪录 `e.b()` **没有**调用 `super.b()`，只令 `f110a=(f110a+1)%INT_MAX`，再按 `left else-if right else-if back` 处理。因此同轮左右都真仅左生效；任一方向生效都阻止同轮返回。翻页不重置 `f110a`，不重抽名单。

每次原标题菜单新建 `e()`，其 `f110a/f111b` 由 Java 对象默认值从零开始；`e.a()` 并没有显式重置这两个字段，不能把“重用同一 e 再初始化”也当归零。`e.a()` 清并重建名单，重置 `f113d=0`。只读投影的箭头相位为 `(f110a%20)/5`，人物步为 `(f110a%16)/4`；它不等于标题 `f132f`、`l` 或人物 `age`。

父 `d.b()` 只递增 `aA`。标题调用它，纪录不调用；标题绘制和纪录绘制都不调用父 `d.a(o)`，所以也不能附带推进父绘制计数 `aB`。本次核查 `h/e` 全文件无读取 `aA`，因此在**只覆盖上述标题／纪录受支持行为**的最小控制器中不保存 `aA` 可明确作为维护字段覆盖选择；这不表示原APK父字段不存在或可对所有其它表单删除。若目标改为原对象全字段复盘，再加入独立父计数。

## 最小持久载荷与拒绝契约

在已批准的应用快照内新增标题控制器时，须新语义版本，不能在旧 v1 名下暗增：

- `l,f132f,s,t`，20 槽的全部 `[active,definition,x,y,direction,age]`，含 inactive 槽的旧 age/y。
- 标题子模式 `h`、菜单选择 `j`、行选择 `o`；slot 绑定现有 `draft.slot`，不重复权威字段。
- 纪录动画计数 `f110a`；纪录页号及原序名单已有字段则只复用。需要支持从世界纪录返回时另有明确父页，不可固定回标题。
- 如本批实现 raw20/raw91 的异步返回，保存子页种类、有效答案／已消费状态；不保存 `k` 指针，不用应用枚举猜答案。若暂不支持中断读取／删除，给出具名未实现拒绝，不能返回成功。
- 随机流与请求计数保存现有权威值；同轮标题出生与随后纪录名单抽数须联合候选提交，任何一步磁带耗尽保留所有旧计数、人物、页面和随机游标。

本报告不另加广告／调试／共享指示图元内部状态；三者仍是完整原皮肤缺口。新增字段至少校验阶段、行／菜单、计数范围、20 槽长度、活动位／方向、引用定义、坐标和活动关系，不用 `map.at` 抛异常代替拒绝。回复应用恢复时不重新初始化 q、不重抽名单、不补一次更新“修复相位”。

## 本批交付与规模

只新增本目录的报告与证据 JSON，无 C++、原表、图片副本、后台任务或缓存。来源以相对路径与窗口哈希引用，不复制反编译实现。原有标题调度文档负责随机／排序算法，本报告只补 Owner 接线和语义边界；不重复游戏长测。阶段主会话须集中完成实际代码、回归与输出消费验收。
