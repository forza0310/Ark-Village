历史限制：旧34400→34419证书只核累计收入上涨后跨月；34419当月实际收入为0。该旧证书保持原样，不补签新结论。修正后的`step`及validator额外检查权威`monthly_cash[current_raw_month][facilities][income] > 0`，34429才首次满足。现金流水`period`是模拟步域，不能当月份号。本设计中的当前起点及全部边界以34401→34429证书为准。

## 交接次序：先完整恢复，再只构造策略

1. 显式传入上述快照和证书，沿其明确来源链检查controller、schema、文件与分区摘要、认证范围和历史限制。复用[首星审计](../active-first-star-route/audit.py)的边界，不扫描目录挑“最新”文件，不接受同名未认证候选替换。
2. 新CLI在私有局部作用域创建应用，使用`restore_startup_application_replay`、v1 controller和当前`validate`，完整恢复应用、Session、系统与四类目录引用以及规范v1 Driver。目标为项目work内本轮独占的新隔离根，遵守既有无覆盖发布和失败回滚；不接受调用者传入正在经营的可写应用。
3. 使用v1 `step`执行34402–34429的28轮，不为交接改变其输入、更新次序、输出消费或terminal判定。核完整摘要及证书终点；末轮两层音频请求为空，无正在执行的页面脚本。此处是正常旧路线运行，不能称为“交接本身不更新”。多轮推进若任一轮失败，CLI整体弃用私有应用，停止并保留诊断；不得返回半推进应用或发布v2快照／成功证书。已成功恢复产生的私有隔离文件可以作为失败证据保留，不能冒称整项失败从未创建文件，也不能把它安装回调用者会话。
4. 保存完整旧metadata为`origin_metadata`，以旧validator计算`before = startup_application_replay_digest(app, origin_metadata, old_validator)`。再次确认v1真实terminal，且`pending=wait`、场景恢复、活动页载荷退休。不能仅以rank1作为交接门槛。
5. 新Driver构造函数只接受`const StartupApplication&`、旧metadata和已核来源身份。在内存中构造v2策略；不调用`update`、输入、`take_*`、文件保存、随机抽取或Session安装，不改Owner、历史、页面、系统引用及环境目录。
6. 用**相同旧metadata和旧validator**再次算`after`并要求`before == after`，同时比对已恢复系统及目录文件清单字节身份、旧来源文件hash。新metadata故意包含新controller和Driver，所以新旧metadata下的完整digest不同是正常现象，不能拿这种比较证明世界变化或不变。
7. 完成v2严格校验，才发布首份v2快照；捕获边界仍是34429轮末，尚未发送任何v2命令。随后从新快照做独立双恢复短回放。候选构造或校验失败时私有v1应用和metadata不变；失败不把活动策略句柄切为v2。只有独立回放通过才能发布成功证书；已落盘但尾段失败的快照只记候选，不撤回或改签为成功。

公共底层restore允许恢复合法terminal。旧CLI另有“terminal或超过stop不再运行”的守卫，该运行限制不等于底层无法恢复终点；不删除旧守卫来偷渡新策略。当前已认证文件捕获在34401，故先完整恢复再原样短跑28轮是最小实现路径。禁止用`load_world_replay`重新激活世界代替完整应用恢复，禁止导出世界后重装、可写world、`const_cast`或第二业务Owner。

## 测试层最小接口

下列是拟定职责／签名方向，不是新增产品或prototype公共业务API。只把真实跨翻译单元所需的纯检查或CLI入口放现有测试支持头；创建应用及多轮推进均保持CLI私有，旧实现仍在原主动Driver翻译单元内持有私有`Driver`。

| 接口 | 输入与输出 | 约束 |
| --- | --- | --- |
| `validate_active_v1_replay(app, metadata)` | const应用、旧metadata→具名错误 | 窄门面转发原`validate`；不改旧策略及编码 |
| CLI私有`prepare_active_v1_terminal(source, isolated_root, origin)` | 明确来源及新隔离根→CLI自持候选／具名失败 | 内部创建应用、完整恢复、原v1短跑28轮及终点核验；不接受外部可写应用，不对外公开多步`advance(app, …)` |
| `make_active_second_star_driver(app, origin_metadata, origin)` | 全部const→私有候选v2 Driver | 内部先核旧terminal及origin；只读派生下一策略，不安装、不消费输出 |
| `validate_active_v2_replay(app, metadata)` | const应用、新metadata→具名错误 | v2 magic／规范字节、当前业务绑定、历史来源和预算严格校验 |

来源快照／证书hash校验和进程编排仍放脚本层；C++门面不自行遍历证书链，也不把脚本宣称的terminal当实际terminal。门面不返回v1可写Driver，不开放旧`plan`／字段setter。仅提取确有两个调用者的纯只读观测或trace编码；不复制整套v1源码，也不为此次交接重构全部旧策略。

新策略使用独立`application-active-progression-v2`及`AVACTDR2`；仍复用现有应用回放容器。v1输入ID、magic、规范Driver、CLI参数和证书含义保持。v2命令枚举独立登记，不能把旧ID重新解释为住宅或赠礼；明确wait不增加命令序号。构建仍归现有应用持久化测试可执行，CMake显式登记必要源，不逐函数新建target。

## v2保存哪些状态

| 类别 | 必存字段及含义 |
| --- | --- |
| 不变来源 | 来源快照和证书hash、旧controller和producer、捕获34401／交接34429、完整规范旧metadata、旧终点摘要、来源链身份及`uncertified_history`身份；完整证书作为外部审计证据保留 |
| 轮与命令 | 绝对`next_frame`从34430继续；独立v2 `next_command`从1开始、v2 checks从0开始；`handoff_next_frame=34430`和旧`next_command=881`只作为origin，不合并旧计数 |
| 策略阶段 | 设施补缺、住宅／赠礼、任务、村办、晋级、等待活动30领取及terminal；待执行意图和阻塞原因须规范编码 |
| 住宅事务 | 当前实际人物稳定ID、募集／住宅实例ID、所绑定父子页ID、选中礼物身份、等待父64消费或施工的阶段；无事务时字段全部清空 |
| 冷却与观测 | 任务原绝对月冷却、活动下一可尝试轮、当前实际任务ID；日期、随机游标、模拟步、历史数量、栈顶身份和资源峰值均从Owner核对 |
| 输出 | 原334条音频计数／hash留在origin；v2音频计数从0、hash从其独立规范起点开始，逐轮记录实际输出；两层队列为空才允许保存 |

v2阶段与意图的所有持久枚举有边界检查、长度预算和规范回编码；缺字段、重复ID、溢出、未知阶段及跨页父引用错误显式拒绝。只保存跨轮策略必需信息，不另存可写金币、满足度、库存、HP、实体或第二份业务进度。报价可用于日志及决策，真正扣款仍由Owner根据真实状态完成，不能把旧报价当付款授权。

交接时旧validator与当前应用必须匹配；v2运行后世界已经前进，origin仅按旧Driver规范与不可变来源身份校验，**不能再要求旧terminal观测等于当前应用**。当前世界由v2 validator约束；origin保持完整旧字节以供独立重建审计。来源链和限制不能仅以可随意改写的显示文字存在，编码内固定摘要，外部证书保留原全文。

## 分批验收与资源收口

先在现有应用持久化／主动Driver套件加入交接边界：旧validator失败、非terminal、旧摘要不符、pending输出、错误父页／初始化、错误controller／producer、未知或截断Driver、来源限制丢失均拒绝。测试应利用现有已核夹具并保留完整事务前后断言，不为测试制造原版自然到访证据。restore自身失败仍须不发布目标根、不改目标应用和metadata；restore成功后的多轮推进失败则弃用CLI私有应用及本次策略，不发布v2成果。额外覆盖第1轮成功后续轮故障／终点摘要不符的失败路径，断言源文件和外部会话未变、没有成功证书；不要求每个已发生的私有轮都倒放回滚。策略构造失败在恢复已成功的隔离应用上仍须不改Owner。

正向沿34401→34429已认证短尾段完成零v2输入交接；明确检查相同旧metadata的digest相等、源文件字节不变、交接构造前后隔离目录引用未变化。然后以首份v2快照执行reference和两个新恢复进程20轮，逐轮核命令、规范Driver、完整应用／系统／目录摘要和typed音频。不能只比最终资金。新origin相同与当前v2摘要一致分别报告。

最小实施分三批，每批都必须有可运行行为、对应验证和checkpoint，不预建空的住宅／壶模块：

1. **有限交接＋真实短策略**：完成上述私有恢复、28轮核验、零输入构造证明、规范v2存取、三进程20轮。v2首批沿已有任务消费者，在真实冷却与资格满足后主动接受下一任务，保留后续自动出发／真实确认并取得至少一次实际管理命令的回执；必要等待如实推进和记录。仅20轮被动wait证明存取，不能单独称这一批主动策略完成。策略阶段和编码只实现本批实际需要的字段，不先造住宅空状态。若任务资格尚不具备，记录合法阻塞并继续有界营业至首个真实任务操作，不注入任务或挪用住宅当已完成。
2. **住宅＋建设补缺**：接入真实人物赠礼及募集入住，先认证第一住宅完整生命周期，再推进四住宅及kind3/9设施10。沿每次真正变化补短尾段，独立记录任务继续和经营预算。新增策略不能静默改变首批已冻结v2的下一意图含义；需要不同策略时明确登记策略修订身份、由前一严格validator完成同样的零业务变化交接，不覆盖原快照或宽容解码。没有策略改变的编译／实现错误按已确认契约修复。
3. **二星自然收口**：取得成功12及人气800，实际晋级、活动30真正领取及相关页退休。只捕获最后有价值的业务边界，不重跑共同前缀；达到预算边界保留现场另行分析，不硬凑二星。

各后继边界采用20轮或覆盖完整实际动作的必要短尾段。赠礼65→父64、住宅替换等跨域风险需覆盖实际跨轮组合；可先在条件夹具验拒绝／回滚，不能据此声称自然路线已完成。不要每次从新局重跑34429轮。

每批记录快照字节、联合解码节点、当前／峰值活跃与保留实体、页面／载荷、任务／现金／审计历史、输出消费和引用退休。31.7MB只是当前容器字节，不等于联合内存预算余量。历史继续合法增长；达到128MiB或既定节点预算即保留现场并报告，不删除有效历史或提预算凑通关。成功尾段临时进程根在证据消费后清理，冻结来源保留；不触碰别的智能体缓存和进程。

本设计更新只做静态核对、链接及差异检查，无C++变更、无后台任务、无构建缓存。收入gate已在`6267808`收口；上述有限交接、v2真实策略及二星认证仍待后续批次完成。
