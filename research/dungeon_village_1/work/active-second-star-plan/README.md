## 赠礼不可沿用旧150G预算常量

旧`natural_housing`的守卫使用`residence_fee+150`。它是旧测试策略中的预留值，**不是当前原版短剑报价**：固定`weapon.txt`短剑0的列11为400，维护`compile_startup_world.mjs`原样映射到shop.price；`human_equipment_gift_cost`在共享库存0时按武器×3/2得**600G**，库存>0返回-1并消费一件库存。初次开放可能有一件免费库存，但这是全村共享，一次使用后不能按四个人各有一件来估算。

礼物满足度增量按新旧等级差和当前职业亲和矩阵算评价，再映射2–9。重复同装备也可奖励，但不同人物、当前职业、已经换过的装备会改变评价，不能把历史“人物1短剑10次”机械复制到0/2/3。新策略先从实际64目录取可选装备和现有库存、当前装备／职业，调用只读已核报价/评价helper核计划，逐次65确认后等待父64真实消费结果，再读取满足度决定是否继续。禁止用预测次数直接写满足度，禁止在65确认即记已经付款。

同一次赠礼的真正扣款在父64恢复，报价会重新读取；原父消费者没有第二次资金不足保护。策略必须在打开65时预留**真实当前现金报价＋该候选入住费＋已承诺其他必要费用**，并禁止夹入第二笔自主支出。若看到父`human_page_answers`未消费，等待真实更新，不重开65。用金币送装备与用已持有普通道具是不同成本；普通道具消耗现存库存，不应把药品卖价或零库存商品当免费礼物。

## 金币、点数及建设排序：规则与策略分开

原规则没有本节的统一“储备账户”；下面是避免Driver自己把经营逼入无资金死路的测试策略，数额每次从Owner/原表推导，不写回世界。

- 金币保留优先级：已进行赠礼的父返回付款→已选住民入住费→活动任务的实际续期报价→下一自然月当前设施维护费→下一项建设/赠礼。读取原字段和既有报价，不补固定2000G缓冲。
- 对新任务：征集费可付之外再核当前参与候选能力、期内营业/治疗空间和可能续期成本。旧策略“任务结束后两个绝对月号再开下一任务”可保留为恢复间隔，不能把它解读为任务必定两个月内完成。续期先显示报价，父确认按当前实际参与者重算，Driver不可冻结旧价当最终费用。
- 村子点数独立于金币。首星所需活动和16按原费用20/40及季度次数安排；二星准备到接近完成时为活动30保留100点，不能把100G当100点。若人气未达800，选择真实已开放且可支付的人气活动，比较原效果/费用；不先声称某个最优配比已自然成立。
- 设施10项按当前3/9计数补缺，优先真实目录已开放、原价可支付、能接现道路且可营业的类别3；同定义多实例仍逐实例计数，但不以重复便宜店当经验证最优收益。额外维护费与既有邻接价格/品质都要计入观察。住宅4项独立推进，装饰只作为已核收益/品质选择，不拿它补设施数。
- 每次付费动作失败保留完整应用/世界/随机/页面/音频；业务denial可能已提交提示，不能自动无限重试付款。按真实提示返回并等待资金/资格变化。

## 任务与第一BOSS前置

现主动v1在`rank==0 && popularity<300`才新开普通任务，首星后会停止主动征集。因此二星必须明确扩大任务策略，直到真实成功数12；不能只延长v1的stop-at。

BOSS阶段`task_progress.exploration_stage=x`与星级不同。普通成功在没有仍存在特殊任务阻挡时，探索给G+50、战斗给G+100；G≥500强制战斗选择，当前x0对应任务39／怪物30“相扑一郎”。外层第一年显示≤8月探索限制仍可能覆盖候选种类；目录出现、接受、参战、击杀最后怪物、任务成功及延迟152奖励分别验收。**12次成功可能在二星前已经遇到BOSS，不能把BOSS安排为二星之后的必然步骤。**

Driver需要实际候选队伍／现HP／装备／职业和已开放设施信息来决定是否接特殊任务；没有来源定义“保胜战力阈值”，本批不发明数值。先复用真实征集/出发消费者，观察第一次特殊任务资格，失败按原救援、续期或中止处理。凡会改变角色的装备／转职均走公开人物页，不直接改攻击、HP或技能。怪物普通地图遭遇战与任务成功计数分开。
