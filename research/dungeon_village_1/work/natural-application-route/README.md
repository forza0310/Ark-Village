# 自然通关应用Driver接线与分段认证

2026-10-09。接续[完整应用快照交付](../application-replay-delivery/README.md)与[自然路线成本审计](../natural-clear-route/README.md)。本文区分已存在的原版规则消费者、本批应用命令桥和下一批测试策略；没有执行自然180月，也没有把条件快照改标签当自然前缀。构建和正式验收由主研究批次统一记录。

## 本批最小落地

应用只暴露`const StartupWorldRuntimeSession*`，原`update/acknowledge_page`不足以承载被动路线：87不是普通确认，48普通确认可能晋级，83普通确认可能进入买卖。因此在[应用具名动作](../../prototype/src/startup_application_actions.cpp)补三桥：

| 应用入口 | 现有Session消费者 | 资格与结果 |
| --- | --- | --- |
| `act_award_page(id, action, selection)` | `act_award_page` | 只接栈顶raw87。终止请求与终止确认分别提交；不自动授勋。 |
| `return_rank_page(id)` | `act_rank_page(id, 0, true)` | 只接raw48返回；不复用raw49的置u8确认。 |
| `leave_commerce_page(id)` | `cancel_page(id)` | 只接raw83取消；不进入84/85、不确认购买。 |

桥先检查应用错误、活动世界、无计分控制器以及当前未退休栈顶的ID／种类／原页号，再复制Session、执行现有Owner命令、通过`commit_world`联合提交系统纪录与世界。命令失败保留旧应用；桥不直接读写文件，不增加Owner字段、应用schema、随机或测试专用setter。

原83在尚未初始化且没有残缺载荷时允许取消，已经初始化仍须完整载荷验证，见[商会消费者](../../prototype/src/startup_world_commerce.cpp)。87原`termination_prompt`由独立是非命令消费，不推一个可generic确认的子页；请求与确认之间必须重读当前状态。87首次初始化先增加一枚勋章；已初始化页勋章耗尽为0时原消费者可直接关闭，Driver不能无条件发第二次确认。年度页面有共同更新前缀和event23，不能按自己预期直接抹掉pending或退休页面。

应用仍可通过`world()->state()`只读观察`award_termination_pending`、`page_counters`、`scripts.pages`及月历，不需要新增为Driver服务的Owner字段。运行时已有初始化及文件加载校验的责任继续保留；新桥不把不完整map当有效输入。

### 验收归属

新增[应用动作检查](../../prototype/tests/startup_application_actions_checks.cpp)，归入既有持久化可执行／CTest，未新增target。复用[persistence测试](../../prototype/tests/startup_world_persistence_test.cpp)严格条件文件工厂：一次真实早期世界准备，插入原页面工厂产生的48、83、未初始化87勋1、已初始化87勋0条件，经权威loader检查后载入应用。未初始化87首请求严格检查勋1→勋2；零勋条件先沿真实初始化消费者增加一枚，再明确设置已耗尽夹具，不声称自然授出过勋章。这四个条件只证明接线，不证明自然年度／晋级／商会触发。

主责核错ID／错页、未请求先确认的拒绝不变；真实Session消费者与应用接线的完整状态／历史／随机、原序声音一致；返回不晋级、离开不买卖、终止不授勋、零勋关闭；退休后拒绝再次消费；无纪录改变不写系统／两栏文件。年度计算、商会条件、晋级条件留在既有领域套件，不复制完整排列。

## 下一批自然Driver的规范状态

建议独立身份`application-natural-clear-v1`，仅逻辑模式、固定Java seed1、原speed0；不是`application-clear-conditions-v1`或旧晋级／扩张Controller。Driver使用已交付`AVRAPP01`封装，不新增文件格式。完成当前标题字段/schema收口后再生成首份自然前缀，避免刚生成就被字段清单变更退休。

下列影响下一步、诊断、断言或消费的值必须进入`controller_state`，不能只留C++循环局部变量；路径、文件流、墙钟与OS句柄属于外部环境：

| 字段组 | 必须记录／验证的关系 |
| --- | --- |
| 身份 | Driver语义版本、自然策略ID、seed、speed、logic模式；与应用／世界速度一致。 |
| 次序 | `next_frame`为下一外层轮，`next_command`为下一实际玩家命令；二者独立递增，不能沿条件Driver假设相等。每轮一次`update`，至多一次具名玩家命令。 |
| 控制 | phase（经营／计分／ED后经营／已完成）、下一命令枚举与目标稳定页ID；由当前未退休栈顶和pending重新计算并交叉验证。无悬空页、无原执行栈。 |
| 日历 | 原开局年0月3、上次原年／月／单位、累计实际月变化、最后有月进展的帧及同月外层轮数；拒绝倒退、漏跳或不相容阶段。 |
| 状态绑定 | 最近随机游标、simulation_steps、历史数量、当前栈顶kind/raw/id；与完整应用精确相等，不用局部字段替代Owner快照。 |
| 检查累计 | 成功／失败请求、各具名命令数、已观察页的具名统计、实际事件4/5/6基线／已见、检查数、失败原因；page去重若只用于输出，也必须明示是否计入规范状态。 |
| 输出 | 当前轮声音已经全部领取、序列累计数量和规范摘要（不无限保存全部声音列表）、表现请求固定为0；实际逐轮尾段trace保留有序声音。 |
| 资源 | 已见人物／设施／页／审计历史／账本／任务历史峰值；峰值只能增、不能小于当前只读计数。已退休引用按现有Owner契约检查。 |
| 计分 | 自然触发raw17的稳定ID、入页年月与实际月数、捕获纪录、计分phase绑定；六行等内容已在应用内，不另造一份可漂移的业务状态。 |
| 目标 | 本次阶段目标（月数／帧数／尾段长度）、是否终止与精确理由、累计资源与输出核验资格；候选／认证来源登记在外部证书，不能恢复后偷偷更改Driver终止标志。 |

暂不启用任何建设／住宅／任务接受／活动／授勋策略，也不沿用旧扩张Driver的`terminal`。被动通关只认证自然日期进入计分、实际结算和ED后继续经营；五星、BOSS和全部内容另设自然分支。原speed0至少288000合格世界轮；总外层保护须大于它，且每月须有无进展诊断，不能单纯把continuous的36月参数改成180。

### 每轮页面策略

1. 在旧轮末验证Driver与应用关系；执行一次应用`update()`。`raw17`由应用Owner拦截，不落入世界generic确认。
2. 重读栈顶。场景以及16／24／56／57／97／98由既有自动消费者推进，不补“自动完成”。87按真实pending分别请求或确认终止；48调用返回；83调用离开。
3. 已证普通对话／简讯／报纸及明确登记raw确认白名单才调用`acknowledge_page`。原11、49、59、67、81、88、89、94、95、96及任务结果各有不同消费者，不能把“非场景全部确认”写成原交互规则。被动策略遇任务或主动管理未知页时，保留当前可诊断现场并停止，不删除页。
4. 计分页按照实际stage/counter等待与确认，复用现有应用Owner；不把`application-clear-conditions-v1`的row2 fixture策略当作自然来源。确认可能即为一次页面Update脉冲，必须与世界更新轮的序号分别登记。
5. 收尽本轮声音，核一次性输出为空，更新完整Driver字节，然后捕获／写trace。不得在命令中间、声音未消费或`scripts.executing_page`尚在时保存。

每轮至多一个主动命令是**维护测试策略**，不主张原版“一帧最多一输入”。它避免年度两请求中间的隐含状态，并与此前自然黄金轨迹隔离；不修改旧黄金。

## 分段成本采样与复用

| 阶段 | 前缀及必要实际产物 | 尾段与停止条件 |
| --- | --- | --- |
| 首份 | 真实标题配置→`start_game`→420完整外层轮，留当前schema的完整应用候选 | 对同一文件两个新进程各续20轮，与不中断reference逐轮比较应用、Session／全历史、Driver、声音、系统文件摘要。420不是原月历门槛。 |
| 首月 | 沿同一真实reference继续到累计第一月且稳定轮末；保留一份候选 | 保存／恢复成功及相同20轮；记录总字节、当前Owner／历史段字节、历史数、保存／恢复墙钟、进程峰值与有效预算错误。不能拿文件字节推算解码内存。 |
| 第12月 | 从首月合法前缀继续，跨年度实际87终止与48/83策略 | 不重跑新局；记录真实触发页面、月份／轮数、规模和20轮证书。若未知页／预算拒绝，保留最新合法前缀、错误及成本，停止该长分支。 |
| 后续 | 成本允许才分12→60→120→179→180月 | 每阶段仅认证目标附近短尾段／具体跨域边界；不每次重复完整前缀，也不把未认证周期候选宣传成自然终点认证。 |

128MiB文件、16Mi节点／128MiB全历史联合解码分配预算不变。可将编码段统计放在只读容器报告器，实际通过仍以C++恢复为准。现没有可依赖的公开“精确解码预算已消费”计数接口，报告不能伪造该指标；若需显式计数应单独给codec只读诊断出口，不将采样统计注入Owner。超预算不得删历史、放宽断言或提高阈值；应另设计无损共享／分块历史存储并确认。

完整应用当前语义为2；旧四个`application-clear-v1`快照只保留为历史证据，现加载器拒绝，不迁移。本批已重新认证`application-clear-v2`计分条件档，可复验其计分尾段，仍不能用作自然前缀；旧五份world晋级／扩张快照schema不匹配当前Owner。将来的自然前缀必须同时匹配world schema、application schema、dataset、Driver身份与完整验证器；仅标题接口兼容不能代替该检查。

本目录只增加文本，不生成快照／构建树、不启动长测或原游戏。本批动作桥不增加字段；标题并行工作已使完整应用字段清单增至16项，并要求语义2。自然Driver尚未实现，本文分段认证仍是下一批策略，以主批次最终schema和证书为准。
