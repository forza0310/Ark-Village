# 自然通关应用Driver接线与分段认证

2026-10-09。接续[完整应用快照交付](../application-replay-delivery/README.md)与[自然路线成本审计](../natural-clear-route/README.md)。应用命令桥及实际自然Driver已经实现。修前420轮、首月、第12月曾各完成20轮三路一致，随后确认应用更新遗漏Session轮末人物缓存收尾，三份档案现仅作修前诊断。当前应用语义升至3，修后420／首月自然前缀已重新认证；自然180月、计分和ED后经营尚未自然认证。构建和最终阶段验收由主研究批次统一记录。

## 本批最小落地

应用只暴露`const StartupWorldRuntimeSession*`，原`update/acknowledge_page`不足以承载被动路线：87不是普通确认，48普通确认可能晋级，83普通确认可能进入买卖。因此在[应用具名动作](../../prototype/src/startup_application_actions.cpp)补三桥：

| 应用入口 | 现有Session消费者 | 资格与结果 |
| --- | --- | --- |
| `act_award_page(id, action, selection)` | `act_award_page` | 只接栈顶raw87。终止请求与终止确认分别提交；不自动授勋。 |
| `return_rank_page(id)` | `act_rank_page(id, 0, true)` | 只接raw48返回；不复用raw49的置u8确认。 |
| `leave_commerce_page(id)` | `cancel_page(id)` | 只接raw83取消；不进入84/85、不确认购买。 |

桥先检查应用错误、活动世界、无计分控制器以及当前未退休栈顶的ID／种类／原页号，再复制Session、执行现有Owner命令、通过`commit_world`联合提交系统纪录与世界。命令失败保留旧应用；桥不直接读写文件，不增加Owner字段、应用schema、随机或测试专用setter。

原83在尚未初始化且没有残缺载荷时允许取消，已经初始化仍须完整载荷验证，见[商会消费者](../../prototype/src/startup_world_commerce.cpp)。87原`termination_prompt`由独立是非命令消费，不推一个可generic确认的子页；请求与确认之间必须重读当前状态。87首次初始化先增加一枚勋章；已初始化页勋章耗尽为0时原消费者可直接关闭，Driver不能无条件发第二次确认。年度页面有共同更新前缀和event23，不能按自己预期直接抹掉pending或退休页面。

应用仍可通过`world()->state()`只读观察`award_termination_pending`、`page_counters`、`scripts.pages`及月历，不需要新增为Driver服务的Owner字段。运行时已有初始化及文件加载校验的责任继续保留；新桥不把不完整map当有效输入。

## 已实现的自然Driver与规范状态

实际实现为[startup_application_natural_replay.cpp](../../prototype/tests/startup_application_natural_replay.cpp)，独立身份`application-natural-clear-v1`，仅逻辑模式、固定Java seed1、原speed0；不是`application-clear-conditions-v1`或旧晋级／扩张Controller。Driver现使用`AVRAPP01`语义3封装，不新增文件格式，不改原表或既有晋级／扩张黄金。元数据producer固定为`natural-passive-v1`，运行二进制的Git身份由外部证书另记；Driver身份不变不代表旧应用语义仍兼容。

以下实际规范字段进入固定1480字节`controller_state`。路径、文件流、墙钟与OS句柄属于外部环境；存档含完整应用与Session，Driver只保存策略和交叉检查所需数据，不另外复制世界业务状态。

| 字段组 | 必须记录／验证的关系 |
| --- | --- |
| 身份 | Driver语义版本、自然策略ID、seed、speed、logic模式；与应用／世界速度一致。 |
| 次序 | 两字段都从1起。完成420轮后`next_frame=421`；`next_command`仅在实际世界玩家命令成功后增加，不计新局配置和普通Update。每轮一次`update`，至多一次具名玩家命令。 |
| 控制 | phase（经营／计分／ED后经营／已完成）、当前页若立即输入应执行的命令、当前栈顶稳定ID。下一轮必须先Update再重读页，不能照抄上一轮pending操作旧ID。 |
| 日历 | 原开局年0月3、上次原年／月／单位、累计实际月变化、最后有月进展的帧及同月外层轮数；拒绝倒退、漏跳或不相容阶段。 |
| 状态绑定 | 最近随机游标、simulation_steps、历史数量、当前栈顶kind/raw/id；与完整应用精确相等，不用局部字段替代Owner快照。 |
| 检查累计 | 六种成功具名命令数量、128槽页面观察计数、事件4/5/6基线／已见、完成轮检查数。页面观察在栈顶ID变化时累计，父页恢复可再次计数，不冒称全局唯一页数。失败立即退出并写诊断，不伪造成功轮或将失败Driver保存成可续的自然前缀。 |
| 输出 | 当前轮声音已经全部领取、序列累计数量和规范摘要（不无限保存全部声音列表）、表现请求固定为0；实际逐轮尾段trace保留有序声音。 |
| 资源 | `humans/facilities/pages/audit_history/cash_entries/retained_tasks`当前计数及峰值。最后一项为`s.tasks.size()`，包含保留任务对象，不能误写成活动`task_order`或完整事件历史。页载荷、商店实例／顺序等检查无悬空引用；这不是完整内存审计。 |
| 计分 | 自然触发raw17的稳定ID、入页年月与实际月数、捕获纪录、计分phase绑定；六行等内容已在应用内，不另造一份可漂移的业务状态。 |
| 固定目标 | 原raw15/3自然触发计分，实际结束后继续经营到累计月份大于180且回到主场景才标完成；2000000外层轮上限、100000轮无月进展保护均为维护策略。完成phase不允许偷偷改成未完成后续跑。 |

CLI的`save-at/save-month/stop-at/stop-month/tail-after-save/trace-from`是**观察与截取边界**，不改变任何玩家命令选择，所以不进入Driver。不同观察窗口在相同轮末仍应得到相同完整摘要；这正是reference继续20轮与新进程恢复20轮可比较的条件。它们不允许改变seed、速度、白名单、声音消费或目标phase。新进程的开始时间／捕获耗时／来源路径也不参与业务摘要。

验证器检查版本、范围、相互关系和实际应用绑定；SHA-256检验完整性，外部证书绑定来源与尾段结果。二者都不是密码签名，不能承诺识别人为重写所有相容字段并重新计算摘要的伪造档。来源资格以实际新局reference和被冻结证书链为依据，不能把合法形状等同自然来源。

暂不启用任何建设／住宅／任务接受／活动／授勋策略，也不沿用旧扩张Driver的`terminal`。被动通关只认证自然日期进入计分、实际结算和ED后继续经营；五星、BOSS和全部内容另设自然分支。原speed0至少288000合格世界轮；总外层保护须大于它，且每月须有无进展诊断，不能单纯把continuous的36月参数改成180。

### 每轮页面策略

1. 在旧轮末验证Driver与应用关系；执行一次应用`update()`。`raw17`由应用Owner拦截，不落入世界generic确认。
2. 重读栈顶。场景以及16／24／56／57／97／98由既有自动消费者推进，不补“自动完成”。87按真实pending分别请求或确认终止；48调用返回；83调用离开。
3. 只确认显式枚举的对话／简讯／报纸；未知kind拒绝。raw普通确认白名单恰为11、49、50、59、67、81、88、89、94、95、96。任务接受、延期、购买和未知页不在白名单，具名错误包含当前轮／月／raw／id／来源；停止时保留已有候选和进程日志，不承诺额外保存一个验证器尚不认识的未知页快照。
4. 计分页按照实际stage/counter等待与确认，复用现有应用Owner；不把`application-clear-conditions-v1`的row2 fixture策略当作自然来源。确认可能即为一次页面Update脉冲，必须与世界更新轮的序号分别登记。
5. 收尽本轮声音，核一次性输出为空，更新完整Driver字节，然后捕获／写trace。不得在命令中间、声音未消费或`scripts.executing_page`尚在时保存。

每轮至多一个主动命令是**维护测试策略**，不主张原版“一帧最多一输入”。它避免年度两请求中间的隐含状态，并与此前自然黄金轨迹隔离；不修改旧黄金。

### 白名单来源与早确认

白名单复用[世界页面消费者](../../prototype/src/startup_world_runtime_pages.cpp)，不在Driver内复写计算、快进或退休。11／89早确认只快进至40，之后由原消费者关页；59早确认不快进，满70才设置缺席月并关闭；49是初始化后的u8置位／关闭，不走48晋级。50、67／88、81分别走原晋级庆典、授勋显示、设施升级消费者，阈值由这些消费者主责，合法早输入可能无变化，不能被测试策略当成必须立刻关页。96沿原40／77双阶段。94／95沿[奖励页](../../example/src/world_gift_page.cpp)早确认设40，之后才提交真实奖励。以上没有按秒换算逻辑计数。

17由应用Owner拦截，stage0满75、stage3满45时才发送确认；stage1/2/4/5及stage6结算由原更新推进。每次确认本身也是一次页面更新脉冲，Driver命令序号独立计数。自动等待页16／24／56／57／97／98从现有连续路线消费者沿用，未默认逐帧确认；遇运行时缺来源错误仍直接失败。

输出门禁的实际声音检查复用[应用动作检查](../../prototype/tests/startup_application_actions_checks.cpp)中87真实请求／终止产生的未领取声音，在现有领取前调用自然验证器的专属拒绝检查；随后原Session声音序列对照和一次消费仍执行。这只认证输出保护，不将87条件夹具提升为被动自然来源。新局停在对白时80次空Update不保证声音，该错误期待已移除；Driver未消费标记拒绝、实际pending声音拒绝分别保留主责。

## 实际CLI及进程协议

CLI仍归入既有持久化测试程序，不新增target／CTest。[三进程runner](../../prototype/tests/application_natural_process.mjs)登记在既有进程隔离用例的可选自然分支。

```text
application-natural-clear-v1 --work-dir <现有独占目录> --trace-file <新JSONL>
  --stop-at <硬外层轮上限>
  [--load-file <既有源>]
  [--save-file <新快照> (--save-at <完成轮> | --save-month <累计月>)
   --tail-after-save 20]
```

保存模式默认20轮尾段，只输出捕获后trace；不能与`trace-from/stop-month`混用。非保存模式可指定这两个纯观察边界；恢复默认从源`next_frame`输出，若潜在观察范围超过10000轮则必须显式给`trace-from`。这是防止无意序列化整条长前缀的观察保护，不改Driver策略。月捕获在首次达到指定月的完整轮末发生；源已经达到该月、源下一帧越过捕获轮或停止轮时，在恢复候选验证器中拒绝，系统文件尚未发布。

JSONL每行含`frame`（已完成轮）、`next_frame=frame+1`、完整应用／Session历史／Driver摘要、本轮原序`sounds`和实际系统文件`system_digest`。三路逐字节比较尾段，另比终点年月／完整摘要／资源／声音累计及源文件不变。`application-natural-summary`给出实际捕获轮／月、完成轮、资源计数／峰值、声音摘要、随机、phase与存取墙钟。完整状态摘要仅在trace尾段、实际存取和终点计算；正常长前缀只作轻量状态／引用／输出检查。JSONL缓冲独立限制8MiB，每次追加前检查，最终以既有create-only出口发布；该预算只约束测试输出，不提高或替代Owner、应用文件和解码预算。
