# 世界所有者与调度

`startup_world_runtime` 持有唯一聚合 Owner，准备完整下一状态并在成功后发布；arrival/pages/scene/nonactors 接线跨模块消费者。`startup` 安装固定初值，`rules/` 提供共享领域类型、随机、场景和调度基础。

这里允许依赖各领域模块，领域规则不反向依赖运行时所有者。失败保留原世界及随机游标；正常窗口的线程/FIFO/47ms 调度由 `src/app/session` 与 timing 负责。

场景、人物和非人物的私有入口只借用本轮独立 Owner，减少子阶段整世界复制；跨域请求继续使用原消费者。路线读写的随机流由聚合层同步，最终发布与完整审计相互独立，失败不发布草稿或部分审计。

`startup_world_menu`消费真实3/4/7/10页栈、冻结目录、选择与父位置；信息9由village模块处理，菜单NEW只在源刷新/出口时更新。`startup_world_save`负责raw14阶段、严格稳定导出和成功/失败结果候选，不访问文件；app/session桥选择玩家两栏codec，维护application桥选择完整Owner格式，两者共享源页面资格但不混用文件政策。

`startup_world_manual`负责说明13的正文缓存、翻页、Init冻结人物与Finish清理；正文属于固定rules，绘制交给presentation纯计划。维护格式保留模态载荷，玩家两栏只分类为discard并冷清，不借页面功能改变玩家随机政策。

路线投影保留完整历史人物键；有序写回只复用既有 map 节点，不改变实时业务名单顺序。完整世界的八个成员按声明顺序复制，并用结构化绑定使新增字段在编译时要求更新；返回投影不借用源容器。
